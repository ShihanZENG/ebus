# 织间商城 · 首单联调

本地中文演示，面向英国女装场景，GBP 计价。公司资料、商品和收件资料均为模拟；不收款、不连接承运商、不计算真实税费。不可直接对外营业。

## 启动

在项目根目录运行 `./tools/start-storefront-demo.ps1`。若本机数据库端口未就绪，脚本只尝试启动项目的 `crossborder-erp-db-1` 容器并等待健康；已有服务端口被占用时只提示，不杀进程。日志保存在 `.superpowers/sdd/2026-10-19-storefront-first-order/logs/`。

- 顾客商城：<http://127.0.0.1:15174/>
- 演示 ERP：<http://127.0.0.1:15175/storefront>
- 演示 API 就绪检查：<http://127.0.0.1:18081/ready>

启动依赖现有本机 PostgreSQL 和 `backend/.env` 配置。脚本从配置派生名为 `erp_storefront_demo` 的独立数据库，拒绝远程数据库。ERP 使用现有本地演示管理员配置；凭据不写入商城代码或本说明。原 ERP 的 15173/18080 服务、数据库保持不变。

首次准备需已有 `backend/.venv` 的后端依赖，并分别在 `frontend`、`storefront` 安装 npm 依赖。初始化可重复运行：不会重置管理员密码、已改售价、发布状态或已有库存。默认 1 款商品、6 个颜色尺码规格，每规格初始 3 件。

商城支持首页 `/`、商品详情 `/products/{slug}`、分类 `/collections/{category}`、搜索 `/search`、购物袋 `/cart`、结账 `/checkout`、结果 `/checkout/result`、安全查单 `/orders/lookup`、帮助 `/help`、演示政策 `/policies/*` 和服务状态 `/status`。分类、搜索与筛选条件保存在 URL，目录 API 支持服务端分页、类别/尺码/颜色/价格筛选及价格/上新排序。已购顾客可凭订单访问令牌提交演示客服请求，ERP“独立站运营”页可以查看并处理状态。正式部署时，Web 服务器需将这些前端路径回退到 `index.html`。

## 演示一次完整链路

1. 在商城顶部「登录 / 注册」创建独立顾客账号（用户名 3–40 位字母、数字或下划线，不区分大小写；密码 10–128 位）。登录后选颜色尺码，加入购物袋，填写演示资料。可点“填入虚构测试资料”，不要填真实个人信息。也可保留游客下单方式。
2. 提交演示订单，记下 `ZJ-` 开头的订单号。此时订单进入 ERP 草稿，**尚未预留库存**。
3. 在演示 ERP → 销售订单中按来源单号查找。详情展示收件快照；订单商品、价格和地址不允许直接改单。
4. 审核订单（沿用织间演示仓）→ 申请发货。只有申请成功才预留库存；缺货会失败，不产生部分预留。
5. ERP → 出库单 → 确认出库，填写 `DEMO-001` 一类演示单号。此时扣减在库与预留库存；不会创建真实快递单。
6. 回到商城点“刷新订单状态”，应显示“已出库”。出库不代表已揽收或签收。

### 顾客登录与我的订单

- 登录/注册页：<http://127.0.0.1:15174/account/login>；订单中心：<http://127.0.0.1:15174/account/orders>。
- 顾客身份独立于 ERP 员工账号。账号下单的归属在后端与订单一起写入事务；再次登录同一账号即可查询，不依赖原标签页。
- 登录会话采用 HttpOnly、SameSite=Strict 的 Cookie（7 天到期），数据库仅保存会话令牌摘要，密码使用既有 PBKDF2 算法。退出会使当前会话失效。
- 历史游客订单不按邮箱自动认领；仍通过原订单访问凭据查看。当前版本不提供游客订单认领、邮箱验证或密码找回，请保管好顾客账号密码。
- 登录后「我的订单」支持分页、刷新、订单详情、履约状态和售后入口。购物车仍保存在当前标签页；本次没有实现跨设备购物车同步。
- 账号表由 `0039` 迁移建立，它与 `0038` LIM 网关迁移分别从 `0037` 分支，`0040` 合并。已有本地演示库可单独升级到 `0039`；新环境的 `upgrade head` 包含两分支。

可以在“独立站运营”上传 PNG/JPG 商品图片（单张最多 8 MiB）、维护图片集/材质/护理/尺码说明、改价和上下架；顾客刷新商品后可见。图片默认保存在 `backend/data/storefront-media`，可用 `STOREFRONT_MEDIA_DIR` 指定本机目录；图片使用随机文件名，通过商城公开图片端点读取。已经提交的订单保留原价格。已申请发货订单取消后释放预留，重复取消不会二次释放。

## 边界与安全

- 默认后端 `app.main:create_app` 不开放商城接口。只在命名数据库验证通过的演示工厂中启用。
- 公开接口仅返回商城所需字段；查单需该订单的随机访问凭据，放在请求头，不放在链接。
- 待确认提交及恢复凭据保存在当前浏览器标签页 sessionStorage。网络失败使用“重试原提交”，服务端防重；重试会轮换查单凭据。关闭标签页可能失去查单入口，本期没有邮件找回。
- “本会话游客订单”汇总当前标签页保存的最多 20 个游客订单访问凭据；关闭标签页/会话后可能无法找回。登录下单的订单另由顾客账号归属表持久保存。
- 商城根据当前商品、分类与路径更新 title、description、Open Graph 与 canonical；搜索/筛选参数不进入 canonical，订单、结账、账户及演示内容均标记 `noindex,nofollow`。这是客户端 SPA 元数据，爬虫可见性仍需上线前做预渲染/SSR 验证。
- 演示客服请求可附 PNG/JPEG/PDF（最多 5 MiB）。附件保存在 `backend/data/storefront-support`，可用 `STOREFRONT_SUPPORT_DIR` 指定本机私有目录；顾客须持对应订单凭据，运营人员须有商城读取权限才能下载。附件到期 30 天后首次读取时拒绝访问并删除文件。
- 商城 API 对浏览器写请求校验 `Origin`/`Referer`，默认允许本地运营台 `15173` 与商城 `15174`；其他前端源通过 `STOREFRONT_ALLOWED_ORIGINS` 配置逗号分隔的完整 origin。订单/客服访问、结账提交分别按每 IP 每分钟 30 次限流，媒体上传每分钟 10 次；这是单进程内存计数，不是生产级 WAF 或多实例限流。
- API 统一加 `nosniff`、禁止嵌框、无来源泄漏、无缓存、最小权限策略和 API 响应 CSP。它不替代网页托管层的 CSP/HSTS/TLS 配置。
- 可用 `python scripts/cleanup_storefront_support.py` 预览 30 天以上的附件清理量，审核后加 `--apply` 同步删除文件与元数据。脚本不会自动调度。
- 可用 `python scripts/storefront_file_backup.py backup|verify|restore` 制作/校验商城图片与附件 ZIP，并预演恢复；恢复必须显式加 `--apply` 且会拒绝覆盖已存在文件。ZIP 有 SHA-256 清单但不加密，也不含数据库。
- 草稿不占库存，因此多个草稿可能竞争最后一件；以 ERP 申请发货成功为准。缺货提示随当前可用库存变化。
- 只接受 GB 中英格兰、苏格兰和威尔士邮编；商品图为示意，S/M/L 尚未对齐实物英国尺码。
- 所有服务仅绑定 loopback。公共接口限流为本机单进程版本，不是生产级防滥用设施。
- 商品图片与客服附件保存在本地单机目录，没有对象存储或跨实例共享；客服附件过期后会在首次读取时惰性删除，也可用手动清理工具扫描，但没有自动调度，长期无人访问的过期文件仍占磁盘。
- `backup_db.py` 只备份数据库；文件工具另存图片和客服附件，但两者不构成原子/加密联合快照。备份窗口内需暂停相关写入，恢复时先用隔离数据库和空文件目录演练。ZIP 含敏感客服附件且不加密；生产环境需受控加密存储、保留/访问审计和恢复演练。演示工具不等同生产安全验收。

## 验证

后端目录：`.venv/Scripts/python.exe -m pytest -q`。

PostgreSQL 并发验证：`.venv/Scripts/python.exe -m app.storefront.demo test-postgres`，在演示库内创建随机测试 schema，结束后只删除该 schema，不清空演示表。

前端：`node --test tests/*.test.mjs` 和 `npm run build`。商城：`npm test` 和 `npm run build`。
