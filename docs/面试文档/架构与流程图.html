跨境电商 ERP 系统 — 架构与流程图

面试配套图集 · 可截图放入 PPT / 简历 · 配套文字见《01-项目背景与业务流程.md》

1. 系统架构图（分层 + 业务域）

纵向是「接入 → 鉴权 → 业务 → 数据」四层；横向是 ERP / OMS / WMS / SCM 四个业务域，每个域只维护自己的数据，跨域通过服务方法调用，而不是各自独立部署的微服务 —— 这就是「模块化单体」的含义。

2. 销售发货主链路 · 订单状态机

订单生命周期是清晰的有限状态机：出生即 draft（含平台拉单），审核后才能推进；shipping_requested 阶段取消会自动释放预留，避免库存被「幽灵占用」。状态变化都依据实际履约结果，不靠前端按钮伪造。

3. 采购补货主链路 · 流程图

补货建议由「销量窗口 + 交期 + 安全库存 + 有效库存 + 有效在途」算出，且可售已扣预留的不重复扣减；建议可追溯公式与输入。整条链路的关键动作（转单、收货、关闭）都有幂等和审批护栏。

4. 库存并发控制 · 时序图（防超卖）

这是整个项目最值得讲的技术点：库存「可售 = 在库 − 预留」不是算出来的展示值，而是靠 数据库事务 + SELECT FOR UPDATE 行锁 在并发下强制串行化，再配合出库单状态校验防止重复累计。它直接对应业务痛点「多平台多店超卖」。
