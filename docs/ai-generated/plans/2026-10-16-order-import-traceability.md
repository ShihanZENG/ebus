# 订单导入追溯 Implementation Plan

**Goal:** 每次有效导入请求产生可回看的批次，保存来源标记、操作者、店铺、规范化内容摘要及分组结果。

**Architecture:** 新增 order_import_batches 表，与订单导入同事务提交。复用 orders:read 及店铺范围鉴权，保留旧导入返回字段。前端提供批次历史与结果回看。

**Tech Stack:** FastAPI / SQLAlchemy / Alembic / React / Ant Design。

**Spec:** 用户已批准的五批路线中的第二批：导入来源、批次、成功/跳过/失败结果。

## 约束与边界

- source_name 是用户声明的文件名或来源说明，不是经认证的官方来源。
- data_origin 为 unspecified / sample / user_import，默认 unspecified；用户声明并不证明数据授权。
- content_hash 为服务端计算的规范化提交内容 SHA-256，不是原始文件校验值，也不作为强制禁止重试的依据。
- 不保存原始文件和客户联系方式副本；批次保存结果行号、单号、创建订单ID和错误。格式或鉴权失败的请求不创建批次。
- 重复提交保留新批次，既有订单仍按店铺/渠道/单号跳过。
- 历史批次分页，越权详情返回404。修改文本后必须重新预览，防止导入旧内容。
- 当前目录无Git仓库，保留文件和执行结果，不创建worktree或提交。
