# OMS 门户单点登录设计

## 意图

让已有 ERP 工作区用户能够从企业门户安全进入独立 OMS，免去再次输入 OMS 密码，同时保留 OMS 自己的身份绑定、账号状态和权限模型。

## 目标

- 只允许已登录的 ERP 用户从门户发起 OMS 登录。
- 使用短时、一次性、限定 OMS 接收方的登录凭证；不把 ERP Bearer Token 传给 OMS。
- OMS 只接受管理员预先绑定到 ERP 用户 ID 的 OMS 账号；不自动创建账号或授权。
- 建立正常 OMS 会话后，后续业务 API 继续执行 OMS 自身角色、权限和数据范围检查。
- OMS 未绑定、被停用或凭证无效时，显示明确错误并提供独立登录页入口。

## 非目标

- 不合并 ERP 与 OMS 的用户表、角色、数据库或业务数据。
- 不将 ERP 角色或权限映射为 OMS 权限。
- 不实现通用 OIDC 身份提供方、跨系统登出或外网部署架构。
- 不改变 OMS 独立用户名密码登录流程。

## 设计

ERP 后端新增受认证保护的 OMS 启动凭证签发端点。它只签发包含不可变 ERP 用户 ID、签发时间、短有效期、OMS 固定受众及唯一随机 ID 的凭证，并用独立的跨系统密钥签名。密钥通过本地环境配置，不复用数据库密码或 ERP 会话签名材料。门户在用户点击 OMS 时调用该端点，再把凭证放入配置好的 OMS 登录页 URL fragment；目标地址由服务端配置，不接受调用者传入的跳转 URL。浏览器不会把 fragment 发送给 Web 服务器。OMS 登录页在渲染和发起其他请求前立即读取并清除 fragment，通过 POST 将凭证交给 OMS 后端；非本机部署必须经 HTTPS 传输。

OMS 后端验证签名、受众、有效期和 ERP 用户 ID，并以唯一随机 ID 防止重放。它在同一数据库事务内写入随机 ID 的摘要、标记该凭证已消费并创建 OMS 会话，数据库唯一约束保证并发重放也只能成功一次；过期的消费记录定期清理。OMS 仅查找 `erp_subject` 精确匹配且启用的 OMS 用户；未匹配时拒绝登录。成功后通过现有 `issue_session` 创建标准 OMS 会话，并写 OMS 登录审计记录。新增的 ERP 用户绑定字段只能由 OMS 管理员在用户管理中设置，数据库唯一约束保证一个 ERP 用户最多绑定一个 OMS 账号。现有用户管理 API 和界面提供该字段，绑定变更和撤销写入审计日志。OMS 的普通 `current_user` 与资源权限检查不变。

跨系统密钥缺失、ERP 用户未绑定、OMS 用户停用、凭证过期或重放都必须失败关闭。日志不得记录凭证原文。前端消费凭证后立即移除地址栏中的 fragment；错误页不回显凭证。

## 约束与后续

- 实现范围为本地 ERP 与 OMS 两个 FastAPI 服务及其 React 前端；沿用各自现有认证和会话实现。
- ERP 与 OMS 必须配置相同且足够随机的专用 `PORTAL_OMS_SSO_SECRET`；两边未配置时门户 OMS 入口保持禁用。
- OMS 用户绑定由 OMS 管理员显式配置；首版提供现有用户管理 API 和界面字段，不做按用户名自动匹配。
- 一次性凭证重放记录需有持久化存储和到期清理策略，不能只用单进程内存缓存。
- 本地开发可用 HTTP 回环地址；任何非本机部署必须使用 HTTPS 并单独审查密钥轮换、CSRF/来源校验和跨域配置。

## 验收

- 未配置跨系统密钥时，门户不提供可用 OMS 启动链接。
- 已绑定且启用的用户点击 OMS 后，无需再次输入密码即可进入 OMS。
- 未绑定、停用、过期、受众不符、签名错误及重放凭证均不能建立 OMS 会话。
- 修改 ERP 角色不改变 OMS 权限；修改 OMS 角色会立即影响其 OMS API 权限。
- ERP Token 不出现在 OMS URL、请求头或 OMS 日志中；启动凭证不写入服务日志。
- OMS 原有密码登录和退出流程继续可用。
