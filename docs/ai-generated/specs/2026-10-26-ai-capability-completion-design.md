# 智能 ERP 能力补齐路线与第一阶段设计

日期：2026-10-26。状态：设计草案，待用户确认第一阶段范围；不是功能完成报告。

## 目标与依据

用户要求逐步补齐简历中描述的能力，使每项能力都有代码、可运行场景和验收证据。沿用 FastAPI、React、PostgreSQL、Redis 与现有 LIM 模型网关；不重写 ERP 业务底座。以下实施顺序和首个场景由助手提出，尚未代表用户选择。

代码核查基线：`lim_runtime.py` 有单 Agent 模型工具循环；`lim_workflow.py` 有确定性 DAG 编排与证据汇总；`business_evidence_tools.py` 有业务证据封装；`lim_knowledge.py` 有权限及版本管理的词法检索；`lim_skills.py` 管理不可执行的 Skill 元数据。没有在当前应用代码和依赖中发现 LangGraph、Neo4j、OpenTelemetry、Langfuse 接入。网关 V1.1 已有 Redis 治理与模型调用观测，旧能力清单中的相关缺口不能直接当作最新结论。

## 分阶段交付

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| 1A | LangGraph 驱动的受限多 Agent 经营诊断 | 真实图执行；模型选择分析域；至少两个专业 Agent 在跨域用例中贡献可追溯证据；越权、无数据、冲突、预算耗尽都有明确结果 |
| 1B | PostgreSQL 检查点与可恢复任务 | 进程重启后恢复；累计预算不重置；恢复时重新鉴权；并发恢复只有一个执行者；已完成节点不被无条件重复执行 |
| 2 | OpenTelemetry 与 Langfuse 可观测接入 | 同一 run 关联模型、Agent、工具与检索记录；通过本地接收端验收；导出故障不破坏业务；不默认向外部服务发送业务正文 |
| 3 | Agentic RAG 与混合检索 | 查询规划、关键词/向量召回、过滤、证据引用；固定数据集对照现有词法检索，报告 Recall@k、误引率和耗时 |
| 4 | Neo4j 时序 GraphRAG | 从 PostgreSQL 增量构建可重建投影；实体键、有效期和来源版本明确；至少一个两跳问题和历史时点查询通过验收；图故障不影响 ERP 写入 |
| 5 | 分层记忆与可复用 Skills | 工作/情景/语义/程序记忆有真实读写与召回；来源、适用范围、冲突、衰减及遗忘可验证；审核后的 Skill 被运行时实际使用，效果有对照 |
| 6 | 执行控制与评测闭环 | 审批绑定不可变提案及证据版本；写操作幂等、失败核对；评测任务结果、证据忠实度、工具选择及违规率；具备版本回退 |

每阶段保留现有回归、附运行说明与演示步骤，分别标注“实现”“本地验收”“生产验收”。模型费用只有在配置可追溯价目版本后才可计算；缺失用量不能算成零。不得预先填写性能提升数字。第 2 阶段前使用现有 LIM Trace 记录基础事件。

## 第一阶段场景与边界

场景：用户选择一个已授权店铺、一个日期区间，询问“销量下滑且库存积压，应检查哪些原因、先做什么？”用户可选 SKU；缺少 SKU 时只输出店铺维度结论，不把全店数据伪装成单品数据。

事实边界：用户问题中的“下滑”和“积压”属于待验证假设。销量对照采用紧邻的上一等长区间，展示两期绝对值；基期为零时不生成百分比。当前库存工具提供现时可用量，不能证明历史库存或库龄，因此缺少周转/库龄证据时只报告库存现状及待补数据，不判定积压成因。当前订单摘要的维度以工具实际输出为准，不能从全店金额推导单个 SKU 的利润。

未提供 SKU 时，首版库存分支明确返回 `SKU_CODES_REQUIRED` 数据缺口，不新增全店库存汇总，也不将广告映射或订单涉及的 SKU 子集冒充全店库存。用户提供 SKU 后才能输出对应库存证据。

范围分为 1A 与 1B 两个独立验收点。1A 先完成真实协作与证据输出；1B 再引入可恢复任务和 PostgreSQL 检查点。1A 不声称服务重启后可续跑。第一阶段只生成诊断和建议，不执行采购、库存调整或广告预算修改；后续执行闭环单独验收。

专业角色先选商品/销售、库存、广告三个域。各角色必须有不同的职责提示、允许工具集合与结构化产物。不能通过把固定函数改名为 Agent 来宣称多智能体协作。采购及财务角色在对应业务工具和证据契约验证后扩展。

## 1A 行为与接口

新增独立诊断入口，保留原有单 Agent 和固定工作流行为：

- `POST /api/v1/lim/diagnostics`：接收 goal、shop_id、date_from、date_to、可选 sku_codes。首版同步返回结构化结果与 run_id，任务规模受预算限制。
- `GET /api/v1/lim/diagnostics/{run_id}`：查询已保存诊断，沿用调用者与授权管理角色的访问规则。
- UI 在现有 LIM 控制台增加诊断入口，展示分析角色、证据引用、数据缺口、冲突和建议。失败或无数据不得显示成功诊断。

内部图：输入校验 → 有界计划 → 按计划逐个运行专业 Agent → 确定性证据合并与冲突标记 → 有依据的综合建议 → 输出校验。首版串行调度，避免跨线程共享 SQLAlchemy Session；不承诺并行加速。

Planner 返回结构化 Plan，最多选择三个白名单域，每域最多一个任务，任务包括 task_id、domain、question、dependencies。Pydantic 校验引用、循环依赖和白名单；非法计划最多纠正一次，仍不合法则失败，不偷偷回退到固定流程冒充模型规划。支持单域问题选择单域；跨域验收问题必须真正调度至少两个域。

专业 Agent 通过现有网关进行模型推理；经现有运行时的权限、工具 schema 和 Scope 校验入口调用只读工具。禁止直接访问任意 Python callable、任意 SQL 或用户提供的 URL。Agent/Tool 版本在任务启动时固定。

统一产物：findings、evidence_refs、gaps、proposals。每条 finding 附 claim、证据 ID、店铺/SKU、统计区间、单位与可用的数据版本。证据引用必须来自本次已授权工具产物；不存在的引用被拒绝。引用校验仅证明引用存在，语义支持程度仍需后续评测，不能宣称自动保证结论真实。

冲突检查按“同一对象、指标、区间、单位”比较；不同窗口和单位标记不可比。相同口径值不一致时保留两方来源并标记待核实。不得让模型自行选择一个数字当作事实。缺数据输出 gaps，不以 0 替代未知。

预算采用父任务共享计数：最多 10 次模型请求（网关内部尝试另记）、12 次工具调用、120 秒活动执行期限，递归上限为有限值。上述为助手建议的初始配置，实测后调整。每次模型请求仍走现有 Redis 配额；超限或取消后不得启动新节点。现有同步工具不保证强制中断，界面和文档必须明确这一限制。

协调器拥有父 run_id，每个专业 Agent 创建独立子 LimRun，各自绑定固定 Agent 版本和工具白名单，并关联父 run；工具调用必须使用专业 Agent 的子 run，不能借父 run 的更宽权限。事件以 parent_run_id 关联，各子 run/span 可追溯。预算由父任务统一记账，不能为每个子 run 重置额度；工具执行入口必须复核当前专业 Agent 的固定版本与允许工具。共享上下文仅包含已授权的结构化证据。

读历史结果时，在身份和 Scope 校验之外，复核该任务实际使用证据所需的所有业务域读权限。首版采取整份拒绝策略：任一必要权限或 Scope 已撤销，返回 403，不返回正文、证据或派生结论。管理员按现有角色规则处理。普通用户不能通过猜测 run_id 查看他人任务，不能仅复用现有 `_run_visible` 就视为满足新的权限要求。

## 1B 持久化与恢复

使用 LangGraph 持久化检查点与独立 PostgreSQL schema；内存 checkpointer 仅用于测试。run_id 与内部 thread_id 由服务器关联，客户端不可传任意 thread_id。状态包含 actor、固定的 Agent/Tool/graph 版本、Scope 引用、已完成节点、证据引用与累计预算；不持久化密钥或任意原始业务正文。

恢复入口重新校验身份、当前权限、Scope、工具版本可用性和运行状态。使用数据库租约/执行所有权防止并发恢复。只续跑未完成节点；模型请求与检查点提交之间仍可能存在重放窗口，应明确记录而不声称“恰好一次”。模型及工具执行结果落库顺序、租约失效与检查点事务边界在 1B 单独详细设计。

1B 启用前提供重启、重复恢复、过期租约、权限撤销、预算不重置的真实 PostgreSQL 集成测试。LangGraph 的检查点和跨线程长期记忆不是同一能力，不以检查点宣称四层记忆已完成。

## 代码落点与验收

建议新建 `backend/app/lim_diagnostics.py`（图、计划和证据契约）、`backend/app/lim_diagnostic_routes.py`（鉴权和 API）；复用 `lim_runtime.py`、`lim_model_gateway.py`、`business_evidence_tools.py`，必要时抽取可复用的只读执行函数。模型扩展与迁移编号由实施时的实际 Alembic head 决定，不预占编号。

UI 使用独立组件接入 `frontend/src/pages/LimConsolePage.tsx`，API 类型集中在 `frontend/src/api/lim.ts`。新增诊断测试文件，与现有 runtime、workflow、scope、gateway 回归一起运行。

1A 必须覆盖：正常跨域任务、单域路由、非法域/循环计划、未授权店铺和工具、无数据、虚构引用、冲突证据、模型故障、共享预算耗尽，以及历史诊断越权访问。使用确定性的模型响应桩覆盖异常，再用已配置模型进行单独标记的演示验收；模拟通过不等于真实模型效果通过。

实施时验证 LangGraph 与当前 Pydantic、Python、psycopg 的兼容版本并锁定依赖。新增迁移在临时库升级/回退验证。配置开关可关闭新入口，既有业务路径保持可用。
