# 织间｜英国女装独立站可行性分析

> 目标已更新（2026-10-19）：用户以 AI 应用开发求职为主，不再以女装真实经营为当前目标。本文保留作旧方案参考；最新方向见 `docs/superpowers/specs/2026-10-19-ai-commerce-portfolio-design.md`。

日期：2026-10-19。用途：决定先做什么、哪些条件未满足；不是收益承诺或法律税务意见。

## 结论先说

**值得先做“小规模、可验证”的商城与 ERP 演示闭环；现在不宜直接按真实跨境零售上线。**

技术基础已经具备一部分：项目有商品、SKU、店铺、订单审核、库存归属、库存预留、出库、售后及收款凭据模块。但品牌展示页不等于商城，收款凭据不等于在线支付接口，仓库出库不等于承运商已经揽收。

商业能否成立目前未知。我们还没有真实供应商报价、样衣质量、跨境物流报价、英国退货方案、获客成本或顾客购买证据。网站可以验证交易流程，不能替代这些验证。

## 1. 我建议做的生意模型

- 面向英国市场的自有女装品牌，暂用“织间”，主张“把喜欢，穿进今天”。品牌名称未做商标或域名可用性核验。
- 以日常通勤、周末出门、轻聚会为选款场景，不一开始覆盖所有性别、年龄和品类。
- 首期 10 个演示款，每款 2 个颜色、3 个尺码，共 60 个 SKU；这是系统测试规模，不是采购建议。真实尺码覆盖由样衣试穿和目标顾客反馈决定。
- 演示价格区间 £19–£49，只用于界面和算账验证，不代表市场调研结论或最终定价。
- 当前全部界面与文案使用中文，按用户要求制作；GBP 是结算币种，两者不是一回事。面对主流英国消费者真实投放前，需验证语言适配，建议另做英语版；本次不擅自翻译。
- 首轮配送设计先限定英格兰、苏格兰、威尔士，北爱尔兰及其他地区暂不开放。这是为控制税务与配送复杂度作出的设计建议，不是用户已确认的经营范围。

## 2. 参考 SHEIN，但不复制其规模和身份

[SHEIN 集团站](https://www.sheingroup.com/)以集团、品牌、治理、新闻等信息为主，并提供零售站入口；[英国零售站](https://www.shein.co.uk/)则突出分类、商品、英镑价格和促销。两个站的职责不同。

织间初期采用一个顾客网站：商城为主，品牌故事、公司与联系信息作为独立页面。ERP 是独立的员工后台。暂不做单独集团门户、投资者关系、招聘平台、多品牌矩阵。

值得借鉴的是清晰的商品分类、搭配内容、低摩擦购买流程，以及销售反馈指导补货；不能据此推断我们具备 SHEIN 的采购价、流量或供应链效率。保留原创品牌、文案和素材，不复用对方商标、商品图或虚构销量。

## 3. 现有系统能复用什么

以下为本次代码静态检查，不代表本次已运行或验证全部功能。

| 能力 | 代码证据 | 判断 |
|---|---|---|
| 商品、颜色尺码 | `backend/app/models.py` 的 Product、SKU.attributes | 能关联商城商品；缺零售发布、图片、尺码表、定价 |
| 英国店铺与 GBP | Shop.market、timezone、currency_id | 可建独立站店铺，币种关联 GBP 字典 |
| 订单与来源去重 | SalesOrder、SalesOrderItem；店铺+来源+来源单号唯一约束 | 可以接入商城订单；还需要提交幂等与顾客订单访问控制 |
| 员工审核与履约 | `backend/app/orders.py` 的 approve、shipment-request | 可复用，审核本身不占库存 |
| 库存归属与预留 | `inventory_allocation.py` 的 available、reserve、finish | 应复用本店专属+公共可用量，不能把其他店的专属库存当作商城可售库存 |
| 发货状态 | `wms.py` 的 reserve_order_stock、ship_order | 可以回显出库与单号；没有据此证明真实运输、签收 |
| 收款与售后 | PaymentRecord、recognized_payment_condition、AfterSale | 有登记/核对基础；不是支付机构自动扣款与原路退款 |
| 顾客商城 | 当前 `frontend/src/App.tsx` 为 ERP 路由 | 需要新增独立商城前端和受限公共接口 |

特别风险：`frontend/vite.config.ts` 的本地开发配置会向 ERP 开发页面注入演示登录凭据，生产构建配置为 null。**不能把 ERP 开发服务器暴露到互联网，也不能照搬该配置给顾客商城。**本次未读取或输出凭据。

## 4. 技术上怎样走通

第一阶段是无真实付款的演示：

```text
ERP 发布商品 → 顾客选颜色尺码 → 提交演示订单
  → ERP 待审核 → 员工审核 → 申请发货并预留库存
  → 仓库确认出库 → 顾客页面显示已出库及演示物流单号
```

顾客提交成功仅表示收到订单，不等于库存已锁定。初期使用现有流程，缺货时必须明确提示待处理/取消，不能显示“已付款、保证发货”。

真实支付上线是第二个门槛：需要设计结算时的库存占用、占用超时释放、支付回调验签、金额核对、幂等、支付成功但库存过期的补偿，以及取消/退款处理。未完成前，不能把演示按钮换成真实支付按钮就营业。

架构选择：保留现有 React + FastAPI + PostgreSQL，新增独立 `storefront/` 前端，后端增加 `/api/storefront/v1`。不再另写一套库存账本。试验使用独立演示数据库与专用演示仓库，避免测试订单污染现有经营报表。

## 5. 商业账：每单真正剩多少

先算单位经济性，再考虑投广告。下表全是假设数字，不是英国女装市场均值、供应商报价或预测。

| 单笔模型（GBP） | 假设值 |
|---|---:|
| 折扣后、不含代收税费的销售收入 | 30 |
| 货品与包装成本 | -12 |
| 去程物流与履约分摊 | -5 |
| 支付等变动手续费 | -1 |
| 预计退货退款、逆向物流及折损的净影响 | -3 |
| 广告获客前贡献 | **9** |

因此在这个例子中，获客成本 £6 时每单贡献 £3；获客成本 £12 时每单亏 £3。这还没扣网站、人员、仓租等固定费用。退货损失应按统一口径计入一次，不要既从收入全扣又重复计入费用。

决策线：实际到手收入减全部变动成本和获客成本，应稳定为正，并能覆盖固定费用；同时准备采购、在途、退货和支付结算期间的现金。没有这些实测数据，不建议大批压货或大额投放。

## 6. 真实营业前的必备条件

| 条件 | 当前状态 | 最小证据 |
|---|---|---|
| 需求 | 未验证 | 目标顾客试穿/访谈、小规模真实购买测试；记录渠道和样本量 |
| 供应链 | 未提供 | 样衣、成分、实测尺码、质量标准、可补货量、采购报价 |
| 物流 | 未提供 | 发货地、承运方案、含税/清关责任、偏远地区费用、英国退货去向 |
| 收款 | 未接入 | 可用商户账户、沙箱闭环、回调安全、对账与退款测试 |
| 经营主体 | 目前虚构展示 | 实际主体名称、可联系地址与邮箱、必要注册信息 |
| 财税与消费者保护 | 待按实际经营确认 | 专业核对后的价格、税务、配送、取消、退换和隐私规则 |
| 生产技术 | 未完成专项核验 | HTTPS、权限隔离、备份恢复、监控、限流、PII 保护、并发库存测试 |

公司名称、地址、联系信息可以模拟用于本地设计，但不能用虚构主体接收真实订单。AI 概念穿搭图不是商品实拍，也不能作为成分、版型或质量的证据。

英国在线销售需在交易前清楚展示支付方式、配送选项及费用、总价等，并提供确认和可保存的条款。[GOV.UK 在线销售要求](https://www.gov.uk/online-and-distance-selling-for-businesses/online-selling)

一般网购取消与退货权有法定要求；官方指南列明收到货后 14 天内通知取消、再有 14 天退回，以及标准配送费用退款等规则，并有特定商品例外。政策不能写成“打折商品概不退”。具体适用及文本上线前需专业核对。[GOV.UK 退货退款](https://www.gov.uk/accepting-returns-and-giving-refunds)

跨境直销税务取决于卖家、销售时库存所在地、收货地区及货件价值；£135 涉及整票货件，并非单件商品。不要直接假定“小额免税”，也不要把一套规则无差别套用北爱尔兰。[HMRC 跨境直接销售 VAT 指南](https://www.gov.uk/guidance/vat-and-overseas-goods-sold-directly-to-customers-in-the-uk)

服装标签以及 Cookie/类似技术的使用还需分别核对适用要求。第一版不放广告追踪代码，不声称已完成合规认证。[纺织品标签](https://www.gov.uk/guidance/textile-labelling)、[ICO Cookie 指南](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guide-to-pecr/cookies-and-similar-technologies/)

## 7. 推进顺序与验收门槛

1. **现在：完成设计与成本清单。** 固定页面职责、商品字段、订单状态、ERP 对应关系；当前无真实收款。
2. **下一开发里程碑：一笔演示订单闭环。** 建隔离测试环境，先让一个商品下单进入 ERP，完成库存预留、出库和前台回显，再扩展 10 款。
3. **业务验证：用样衣和真实报价替换假设。** 先小规模验证顾客愿意买什么、收到后是否满意、每单是否有贡献，再决定采购和获客预算。
4. **上线评审：支付、物流、合规、安全全部有证据。** 任何关键条件缺失，保持演示，不接真实交易。
5. **小规模真实试销：按风险逐步放量。** 看退款后的每单贡献、尺码退货原因、发货准时率、复购与库存周转，不以网页访问量代替盈利。

本轮交付为分析与设计稿，不是商城已接入 ERP 的完成声明。具体工期、预算在实施任务拆解和真实供应链信息到位后估算，不用虚假的精确数字制造确定感。
