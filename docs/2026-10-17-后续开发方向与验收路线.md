# 后续开发方向与验收路线

日期：2026-10-17

## 项目定位

面向小型跨境卖家的 AI 运营工作台。当前优先交付一套能演示完整业务过程的技术 MVP；目标用户和付费需求仍需通过实际使用验证。

近期交付重点：用一笔订单串联现有业务模块，以采购补货作为首个重点展示的 AI 场景。该选择基于当前已有开发基础，不代表采购补货的市场需求已经验证。此前的 Listing 优化保留为候选场景，待用户反馈决定投入顺序。

## 当前依据与约束

- 项目记录已有本地商品、订单、库存、采购、客服、售后、分币种本地收付款与费用核验等能力，以及权限和审计基础。
- 最近已接入轻量客户档案和客服内部记录草稿；完整浏览器操作验收仍有未完成项。
- 暂无 Amazon 账号/API 授权，近期以本地合成样本和经授权的 CSV/报表为数据入口。
- 本文是后续计划，不是重新验证过的全系统完成报告；每批开发前先核对已有实现，复用已有接口和页面。

## 第一批：走通一笔生意，建立验收基线

目标：能从起点到终点讲清每一步由哪个模块处理、生成什么记录、下一步在哪里操作。

- [ ] 准备独立、明确标识的合成验收数据，避免改动已有日常记录。
- [ ] 跑通本地自发货路径：商品/SKU与库存准备 → 订单导入或录入 → 审核及库存预留 → 出库和物流记录 → 本地收款登记及分币种核对。
- [ ] 同一订单补一条客服/售后分支，检查客户档案、订单与工单能相互定位；按已支持的动作验收退款或退货，不假设所有异常均已实现。
- [ ] 检查客服 AI 草稿的生成、编辑、人工保存和工单记录回查；记录保存前后数据变化。
- [ ] 验证库存不足、重复导入、权限不足和已关闭工单等实际支持的异常路径。
- [ ] 形成一份逐步操作记录和缺陷清单，先修阻断流程的问题。

完成条件：正常路径和选定异常路径都有可重复的操作记录；订单状态、库存数量、币种金额、关联单据和审计结果相互一致。这里只验收本地业务，不代表平台已同步或银行已到账。

## 第二批：让真实资料进入同一条流程

目标：已有导入能力可以处理一份来源明确、经授权的脱敏订单样本。

- [ ] 核对现有订单导入追溯、去重及错误处理能力，列出差距后再补开发。
- [ ] 明确一种文件格式，提供可下载的空模板、合成示例与字段说明。
- [ ] 让导入预览明确显示店铺、订单号、SKU映射、数量、金额、币种及错误行。
- [ ] 映射不确定和字段缺失的记录有人工处理入口，导入失败能定位和重试。
- [ ] 有授权样本时逐条与原文件核对；没有样本时先完成合成数据技术验收，并把真实数据验收保留为待办。

完成条件：同一文件重复导入不会重复建单；每条导入订单能追溯到批次与来源；错误记录可见、可处理。

## 第三批：把采购补货助手做成可核对的 AI 场景

目标：用户能回答“为什么建议补这些货”，并能从建议进入已有采购流程。

- [ ] 核对现有采购 Agent 和补货工作台，明确已接入工具、计算口径、草稿生成和审批边界。
- [ ] 固定一个演示问题，例如“这个 SKU 是否需要补货，建议补多少，依据是什么”。
- [ ] 展示建议使用的销量期间、库存、在途、交期及缺失资料；没有可靠销量时明确资料不足。
- [ ] 打通建议 → 人工确认采购草稿 → 现有审批 → 收货 → 库存回查，复用现有能力。
- [ ] 补齐需要的运行轨迹：查询/工具调用、计算依据、耗时、成功或失败、关联草稿；不把模型私有思考过程作为展示内容。
- [ ] 检查无权限、资料缺失、模型失败、重复操作和过期建议等边界。

完成条件：固定样本的建议数量可复算，来源可查看；人工确认的采购草稿可追溯到建议；失败有明确结果；收货后的库存变化可核对。

## 第四批：整理成别人能试用的版本

- [ ] 首页提供明确的待处理事项和下一步入口，优先修复“看见数据但不知道做什么”的页面。
- [ ] 整理一份十分钟左右的演示脚本，覆盖完整订单流程和采购补货亮点。
- [ ] 补齐新环境启动、演示账号、模型配置、数据标识与常见失败说明。
- [ ] 请一名有相关业务经验的人试操作，记录卡住的位置、需要纠正的结果及实际完成时间。
- [ ] 根据反馈决定下一批投入：导入维护、补货、Listing或客服，不按 Agent 数量决定。

完成条件：试用者能按说明完成指定任务，形成实际问题记录。没有业务人员试用时，交付称为技术 MVP。

## 近期暂缓

新增独立 SAP/CRM 系统、多平台同时接入、继续堆 Agent 数量、通用长期记忆/向量平台、无人审批采购、自动广告投放。当前轻量客户档案继续服务已有订单与工单流程。

## 下一次开发的明确起点

执行第一批的业务验收：先列出测试数据与状态变化，再在隔离环境跑通并修复阻断问题。最终交付一份可复现的端到端验收记录，作为后续开发的基线。
