# Storefront 4.6.4–4.6.8 验收与剩余依赖

## 本轮补齐

- 商品详情支持选择购买数量；同规格合并后检查可售库存与单规格 20 件限制。
- 新增 `POST /api/storefront/v1/checkout/quote`：与实际下单复用发布状态、商品版本、SKU 可用性、库存与价格校验。服务端返回小计、优惠、演示运费、演示税费、最终总额及费用规则。
- 结账先核算、再确认创建订单。修改商品、数量、地址、优惠码或消费者身份后，旧报价不能直接用于确认。报价不锁库存、不占用优惠名额。
- 创建订单再次核算金额；`expected_total` 不一致返回 409，事务回滚。原有幂等键和恢复凭据保持有效，旧版本待恢复请求兼容未提供 `expected_total` 的情况。
- 测试支付失败后保留重试入口；已成功的支付不可被后续失败情景覆盖。历史订单也优先展示成功支付记录。
- 零金额订单不显示测试扣款按钮。测试支付使用明确的情景选择，不写真实 ERP 收款记录，不宣称验证了真实支付网关。

## 验收步骤

1. 按 `storefront/README.md` 启动演示 API 与商城。浏览器进入商品详情，选规格和数量，加入购物袋。
2. 填写虚构地址，点击“核算最终金额”。核对服务端返回的小计、优惠、费用和最终总额。
3. 改数量或优惠码，旧报价应失效；重新核算，再点击“确认总额并创建订单”。
4. 在订单页选择“模拟支付被拒”，确认能再次点击“模拟支付成功”。刷新订单，成功状态应保留。
5. 登录另一个消费者账号，不应读取前一个账号的订单。游客必须使用原单的访问凭据。
6. 库存不足、商品下架、商品版本变化、伪造金额应被服务端阻止。重试原提交只产生同一订单。
