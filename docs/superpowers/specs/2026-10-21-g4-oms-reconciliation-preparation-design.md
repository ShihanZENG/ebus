# G4 ERP↔OMS 只读对账准备设计

## 意图

为 ERP 和独立部署 OMS 准备可审查的订单对账输入与差异结果，同时不伪造身份、店铺或订单关联，不对任一系统写入。

## 目标

- ERP 端仅导出当前用户有权读取的订单最小字段，附来源系统、导出时间、期间、币种和记录数。
- 提供只读比较预览，精确匹配候选以来源系统、人工指定的 ERP↔OMS 店铺对应关系、`source_channel`、订单号、币种为键。
- 输出 ERP-only、OMS-only、amount/status mismatch、duplicate candidate 和不可映射条目；不自动合并/改写订单。
- 在外部 ID/店铺映射未确认时保持未匹配，并说明需要配置的身份映射。

## 非目标

- 不直连 OMS 数据库，不复用 OMS 演示账号或 ERP token。
- 不把两个数据库里同名/同 UUID 的店铺或用户视为同一身份。
- 不创建同步任务、重放、冲正、导入或自动对账状态。

## 数据交换与安全

- ERP 和 OMS 分别提供当前系统登录态下的 JSON 只读订单导出，字段名固定为 `shop_id`, `shop_code`, `source_channel`, `source_order_no`, `currency`, `grand_total`, `status`, `created_at`。ERP 用户将 OMS JSON 文件上传到 ERP 页面做临时预览；本批不建立服务到服务连接。
- 上传文件限制 10 MiB；按 OMS schema/version、导出日期范围、币种、金额、状态、时间戳校验后，只把 allowlist 字段复制到页面状态，额外列（含姓名、地址、电话、邮箱、支付凭据和完整订单明细）直接丢弃，不上传。
- ERP 权限按当前 ERP 用户和 shop scope 过滤。结果显示两侧来源和匹配置信等级。
- ERP↔OMS 店铺映射仅由用户在本次预览中临时选择，不保存；只提供下载差异报告。需要可复用映射时另行批准映射表及审计设计。

## 精确阻断项

生产级自动对账仍需业务确认唯一写主、OMS 身份认证/服务账号、ERP/OMS 店铺映射、平台外部订单 ID 字段、币种/退款/状态口径、同步方向、幂等策略、重放和差异确认人。未确认前只交付本地只读准备流程。

## 验收边界

- 未授权 ERP shop 不可导出；OMS 上传字段非法/缺失时拒绝预览；重复候选显示歧义而非任意选择。
- 金额以两位小数整数分比较，只在币种相同时匹配；未映射到 ERP 店铺的订单不误报为 OMS-only。重复候选显示候选订单而不任意选择；状态差异只报告，不按系统名推断优先级。
- 上传文件不发往后端，不写 ERP/OMS 数据库。
