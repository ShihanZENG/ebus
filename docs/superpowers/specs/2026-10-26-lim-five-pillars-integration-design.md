# LIM 五大能力集成设计

## 目标

把压缩包中的多智能体编排、时序检索、记忆与技能、可信执行、观测评测及工作台接入当前 ERP/LIM 项目。压缩包是实现素材；是否完成以现有业务 API、持久化和权限测试为准。

## 约束

- 保留现有 ERP、OMS、Storefront 路由与数据；先在主 ERP 数据库建立权威订单/库存状态，再定义独立 OMS 的交接契约。
- 新 LIM 路由沿用 `session_db`、`require` 和用户店铺/仓库范围，不接受客户端声明的租户权限。
- 演示图谱、内存 checkpoint、内存库存/付款状态只能作为沙盘；不能写入生产业务状态或标成需求已闭环。
- 结账预占、释放、订单与 Outbox 必须在同一数据库事务；外部交接失败应可重试且不重复建单。
- 未验证付款不能推动真实商城订单发货；模拟付款不得进入真实收款口径。真实支付凭证的验签契约取决于支付服务提供方。
- 前端工作台明确区分沙盘与真实运行记录，通过现有鉴权 API 读取后端状态。
- 文档台账按测试证据逐项更新；不要统一改为“已实现”。

## 实施顺序

1. 建立基线与测试矩阵，审计压缩包和现有实现。
2. 接入五大模块的可复用部分，封装认证、作用域和持久化适配器；保留已有 LIM Registry、Workflow、Skill 治理为权威实现。
3. 为主业务链路增加原子 Hold、Outbox、支付证据门禁和外部流水号幂等，涵盖并发、重复请求、过期及回滚测试。
4. 接入工作台路由与数据请求，提供加载、错误和空状态，明确沙盘标识。
5. 运行后端及前端测试，复核迁移和文档台账，再决定提交与远端集成。

## 外部依赖

Neo4j/Redis/PostgreSQL 实例、独立 OMS 消费接口、真实支付网关与验签格式由部署环境提供。缺少这些接口时可以完成本地适配与受控沙盘，但对应生产链路保持未验收。
