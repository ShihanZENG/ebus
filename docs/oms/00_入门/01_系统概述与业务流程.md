# 01 系统概述与业务流程

## 文档状态

本文描述当前代码已经提供的 OMS 订单能力，并区分已实现与规划能力。渠道 API 自动拉单、收货地址、风险异常等能力尚未实现。

## 当前范围

当前 OMS 以销售订单为中心：支持人工创建或通过结构化 JSON 行数据导入订单，查看和筛选订单、审核、申请发货、取消，以及记录付款和售后申请。店铺、币种、SKU、仓库来自基础资料。代码没有 Amazon、eBay、Shopee 等平台连接器或自动同步任务。

## 当前订单流程

```text
人工创建 / JSON 导入
        ↓
draft（前端显示“待审核”）
        ↓ POST /orders/{id}/approve，指定履约仓库
approved（已审核）
        ↓ POST /orders/{id}/shipment-request
shipping_requested（待出库；建立 WMS 出库单并预留库存）
        ↓ WMS 出库单确认
fulfilled（已发货/订单履约完成）
```

允许在 draft、approved、shipping_requested 状态取消。取消 shipping_requested 订单时会释放仍处于拣货中的库存预留。WMS 确认出库会扣减在库和预留数量、记库存流水，并将订单置为 fulfilled。

售后申请仅允许从 `approved`、`shipping_requested`、`fulfilled` 发起；成功时创建 `AfterSale` 待处理记录，订单履约状态保持原值。处理售后记录为完成或驳回不会自动执行退款或退货收货。旧版留下的 `after_sale` 订单，在全部售后记录处理完后会按出库单状态恢复为 `approved`、`shipping_requested` 或 `fulfilled`。不存在地址校验、异常标记或自动风险拦截流程。

## 当前数据模型

销售订单保存店铺、来源渠道及单号、状态、币种、商品金额/优惠/应付金额、履约仓、客户名称和联系方式、备注及取消原因。订单项保存 SKU 快照、数量、单价、优惠和行金额。模型没有收件地址、物流渠道、运单号或订单时间线字段；物流单号属于 WMS 出库单。

## 业务操作细化与验收建议

### 场景和输入

运营人员把尚未进入仓库履约的销售单录入系统，核对店铺、渠道来源、来源单号、币种及 SKU 行；审核人员选择履约仓；仓库人员再到 WMS 处理出库。录入和审核不会自动触发下一步，操作者需要分别提交。

一笔订单的金额口径为：每行商品金额 = 单价 × 数量；订单商品总额为各行商品金额之和；订单优惠为各行优惠之和；应付金额 = 商品总额 − 优惠。金额保留两位小数，按四舍五入处理。付款记录只是记录实际收款信息，不会反向改变应付金额或订单履约状态。

### 状态与跨模块交接

| 当前状态 | 可进行的订单操作 | 结果与后续责任 |
|---|---|---|
| `draft` | 审核、取消 | 审核写入履约仓；此时没有库存预留 |
| `approved` | 申请发货、取消、申请售后 | 申请发货才创建一张 WMS 出库单并预留全部订单 SKU |
| `shipping_requested` | 取消、申请售后 | WMS 出库确认后状态变为 `fulfilled`；取消会尝试释放仍在拣货中的预留 |
| `fulfilled` | 申请售后 | 已完成履约，不能使用取消接口 |
| `cancelled` | 无订单状态操作 | 不能登记付款，不能再次审核或申请发货 |
| `after_sale` | 以售后记录流程处理 | 此状态由订单售后申请设置；并不代表退款已执行或仓库已收到退货 |

订单和 WMS 是两个交接步骤：`orders:write` 用户发起申请，`shipments:write` 用户确认出库。WMS 确认时记录运单号（可空）、发货时间、出库库存流水并完成订单；实际平台回传、物流轨迹和签收没有实现。

### 权限、范围与建议验收

列表/详情需 `orders:read`，写入订单需 `orders:write`。订单创建与导入必须在用户 `shop_scope` 内；审核和申请发货需有效履约仓，实际仓库接口另受 `warehouse_scope` 约束。WMS 出库确认另需 `shipments:write`。无效令牌返回 401，权限不足返回 403，跨店铺订单查询按不存在处理，状态或输入规则不符返回 422。管理员角色可通过权限依赖，但仍应确认账号有效。

建议验收：在测试店铺录入两个 SKU，确认金额按行金额汇总且状态为 `draft`；审核后检查仓库已保存但没有预留；申请发货后检查 WMS 出库单及预留数量；WMS 确认后检查在手/预留变化、出库流水及 `fulfilled`；另以超出可用库存的数量申请发货，预期请求失败且订单仍为 `approved`、无部分预留。以上为建议步骤，未执行。
