# 04 全局通用操作

## 文档状态

页面交互依模块而异。以下描述以订单页面及主布局的实际交互为准，不代表所有列表页都有相同筛选、导出或详情能力。

## 当前订单页面操作

- `/orders` 页面提供刷新和新建订单按钮；列表当前加载第一页最多 50 条，不显示分页控件。
- 点击订单行打开右侧详情抽屉；操作列提供符合状态条件的审核、申请发货或取消。
- 新建和审核使用弹窗；取消通过浏览器提示框输入原因。
- 当前订单列表页没有导出、排序、多条件筛选或批量操作栏。

## 布局与权限

左侧菜单和页面标签由 `frontend/src/layouts/MainLayout.tsx` 实现。菜单项受权限映射影响；用户未登录会被引导到登录页，缺少页面权限会跳回首页。接口权限仍由后端执行。

## 代码位置

- 布局：`frontend/src/layouts/MainLayout.tsx`
- 订单交互：`frontend/src/pages/Orders.tsx`
- API 请求封装：`frontend/src/api.ts`、`frontend/src/api/client.ts`

## 订单页逐步操作

1. 从“销售 → 销售订单”进入页面。页面请求 `GET /api/v1/orders?page=1&page_size=50`；刷新会重新请求同一页。当前没有分页、筛选、排序或导出控件，若有超过 50 条记录，页面不会显示后续页。
2. 单击订单行查看详情。页面再请求 `GET /api/v1/orders/{order_id}`；详情展示来源号、渠道、状态、客户信息、应付金额、SKU 快照、数量和行金额，有付款记录时显示其金额、方式和来源。
3. 新建时点击“新建订单”。表单先加载最多 100 个启用店铺、币种和 SKU；选店铺后币种联动到店铺币种。填入至少一条商品行后提交 `POST /api/v1/orders`。成功后重新加载列表并打开新订单详情。
4. 审核时选择“审核”，选择履约仓并提交 `POST /api/v1/orders/{id}/approve`。审核成功只改变状态和履约仓，不预留库存。
5. 对 `approved` 订单点击“申请发货”，调用 `POST /api/v1/orders/{id}/shipment-request`。成功后转到待出库，WMS 继续处理。
6. 对未发货订单点击“取消”，浏览器提示输入原因，再调用 `POST /api/v1/orders/{id}/cancel`。留空或取消提示框会停止操作；服务端还会验证状态和原因长度。

### 字段与错误处理

必填字段及边界以服务端 schema 为准：来源渠道 1–80 字符、来源单号 1–120 字符、客户名称最多 120、联系方式最多 200、备注最多 1000；商品行 1–200 条，数量 1–1,000,000，金额非负且最多两位小数。重复 SKU 不允许；同店铺 + 同渠道 + 同来源单号重复会冲突（409）。店铺币种不匹配、停用资料、优惠大于该行金额、非法状态通常返回 422。网络或权限错误由请求拦截器提示；列表失败显示错误消息，选项只部分加载时提示检查资料读取权限。

建议验收：创建有效订单后刷新并打开详情，确认表格无分页且只返回首 50 条；新建时逐一尝试漏填店铺、重复 SKU、币种不匹配、重复来源号；确认服务端拒绝且不产生第二笔订单。取消已发货订单应失败。建议步骤未执行。
