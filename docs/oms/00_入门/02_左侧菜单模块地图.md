# 02 左侧菜单模块地图

## 文档状态

以下菜单以当前前端配置为准。OMS 订单入口为“销售 → 销售订单 / 订单导入”；售后和客服工单分别位于“客服”分组。本文不把尚不存在的规划页面描述为当前菜单。

## 当前左侧菜单

菜单由 `frontend/src/config/menu.ts` 配置，页面路由见 `frontend/src/App.tsx`。

| 分组 | 当前菜单项 |
|---|---|
| 首页 | 首页（业务总览） |
| 商品中心 | 商品、SKU、Listing 映射 |
| 采购 | 采购计划、补货建议、采购单、采购变更、审批工作台、收货单、供应商、供应商报价、当前供货价 |
| 仓库物流 | 库存余额、入库单、出库单、库存流水、仓库档案 |
| FBA | FBA 发货流程、库存与费用相关页面 |
| 广告 | 广告管理 |
| 客服 | 客服工单、售后 |
| 财务 | 结算管理 |
| 统计 | 经营统计 |
| BI | 经营看板 |
| 工具 | 币种与单位 |
| 设置 | 店铺资料、账号与角色、操作日志 |
| 销售 | 销售订单、订单导入 |

## 页面和操作

订单列表、新建订单、订单详情抽屉、审核及取消均在同一个 `/orders` 页面内，没有独立的订单总览、异常订单、渠道同步、客户管理等 OMS 子页面。布局会按权限过滤菜单，并用顶部 Tabs 保存已打开路由页面；不是每个业务动作都对应一个菜单页。

## 权限行为

导航项依据 `NAV_PERMISSION` 过滤；订单页面路由由权限守卫保护。API 仍会在后端按权限和店铺范围校验。当前代码支持管理员角色特例、角色权限集合以及用户店铺/仓库范围；不能据此推断仓管、客服等预置岗位角色已按本表配置。

## 已实现与规划

- **已实现**：当前菜单、页面路由、权限过滤和页面标签行为。
- **未实现**：独立订单看板、异常订单页面、平台同步日志、客户列表/详情、退款执行页面等本目录旧草稿中列出的入口。

## 代码位置

- 菜单与权限映射：`frontend/src/config/menu.ts`
- 路由与路由权限守卫：`frontend/src/App.tsx`
- 布局与菜单标签：`frontend/src/layouts/MainLayout.tsx`

## 销售订单入口使用说明

左侧“销售 → 销售订单”路由为 `/orders`，承载列表、新建弹窗、详情抽屉、审核弹窗和取消提示框；“销售 → 订单导入”路由为 `/order-import`，支持手动 CSV/TSV 导入预览与结果回报。它们尚不构成独立的多标签订单工作台。首页“业务总览”有订单状态卡片与最近订单，卡片可跳到订单页；待出库卡片则跳 WMS 出库单页。

在订单页中，列表行点击打开详情；行内操作依订单状态显示。用户需要 `orders:read` 才能进入页面，缺少路由权限会被重定向到 `/dashboard`。页面将菜单配置用于导航显示；最终接口仍单独校验权限和店铺范围，因此隐藏菜单并不构成数据授权边界。

### 入口边界和验收建议

当前菜单中没有“异常订单”“订单编辑”“拆单/合单”“渠道同步日志”或“客户主档”入口。售后在客服分组中，WMS 出库单在仓库物流分组中，两者不是订单详情内的完整操作面板。

建议验收：分别用有/无 `orders:read` 权限的账号登录，确认销售订单菜单与 `/orders` 路由行为；从首页点待审核订单卡片进入 `/orders`，从待出库卡片进入 `/shipments`；确认订单行操作与订单状态对应。不要把菜单中出现一个入口当作后端权限检查已通过的证据。
