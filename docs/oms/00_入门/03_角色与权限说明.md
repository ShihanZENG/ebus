# 03 角色与权限说明

## 文档状态

代码实现了通用角色权限、管理员特例、店铺范围与仓库范围检查。当前实现不能证明系统预置了“运营/客服/仓管/财务”等岗位角色及其固定权限组合。

## 权限模型

- 用户会话关联角色；角色拥有权限代码集合。后端通过 `require()` 校验接口权限，管理员角色可通过权限检查。
- 用户可配置 `shop_scope`；订单列表按店铺范围过滤，单笔订单查询/操作也会检查范围。
- WMS 出库单按 `warehouse_scope` 检查访问范围。
- 前端根据用户权限过滤菜单并控制订单页面操作入口；后端校验仍是实际接口边界。

## 订单权限示例

| 操作 | 后端权限 | 前端条件 |
|---|---|---|
| 查看订单、订单详情 | `orders:read` | 订单路由权限守卫 |
| 新建、导入、审核、申请发货、取消 | `orders:write` | 写权限；新建另需店铺、币种、SKU 查看权限，审核另需仓库查看权限 |
| 查看/登记付款 | `payment_records:read` / `payment_records:write` | 订单页当前没有付款录入交互 |
| 售后读写 | `after_sales:read` / `after_sales:write` | 独立客服售后页面 |

## 已实现与未实现

- **已实现**：管理员检查、权限代码校验、店铺/仓库数据范围、前端菜单和路由的权限控制。
- **未证实/未实现**：固定岗位角色权限模板、金额分级审批、细粒度字段权限、按按钮自定义角色配置流程。账号与角色维护页面是否提供完整角色编辑，应以对应页面和接口为准；本文不假设可自由创建岗位角色。

## 按订单场景核对权限

| 操作 | 必要权限 | 额外范围/依赖 | 当前限制 |
|---|---|---|---|
| 查看订单列表、详情 | `orders:read` | 后端按 `shop_scope` 限制可见店铺 | 详情抽屉未提供付款/售后写入操作 |
| 新建订单 | `orders:write` | 创建页另外读取店铺、币种、SKU；请求校验店铺范围 | 页面缺少任一读取权限时禁用新建；商品行需至少一行 |
| 审核订单 | `orders:write` | 页面要求 `warehouses:read` 以加载仓库选项；仓库必须有效 | 后端审核只检查仓库存在且启用，并写入 `warehouse_id` |
| 申请发货/取消 | `orders:write` | 订单仍须在用户可见店铺范围且状态允许 | WMS 库存预留作为申请发货的副作用 |
| WMS 确认出库 | `shipments:write` | 出库单需在仓库范围内 | 不由订单审核权限代替 |
| 查看/登记付款 | `payment_records:read` / `payment_records:write` | 仍按订单店铺范围检查 | 当前订单页无付款录入按钮；需调用接口或其他明确入口 |
| 查看/创建售后 | `after_sales:read` / `after_sales:write` | 按订单店铺范围检查 | 由客服售后入口承载，不等于退款执行权限 |

权限是“功能权限 + 数据范围”两层：角色决定能否调用某类能力，用户的 `shop_scope` 决定哪些订单可见；WMS 则使用 `warehouse_scope`。空范围与 `null` 的具体配置语义应以用户数据和 `security.py` 的范围实现为准，不应从页面下拉选项推断可访问全部数据。前端可隐藏/禁用按钮，但 API 仍必须返回 403 或范围内的 404，不能只依赖 UI。

### 建议验收

建立有 `orders:read`、无 `orders:write` 的只读账号，确认可以查看授权店铺订单、不能创建或变更；再撤销某一店铺范围，确认该店铺订单不出现在列表且详情/操作不能越权。移除 `warehouses:read` 后确认订单页提示无法审核；直接请求审核接口仍由 `orders:write` 检查并要求有效仓库。最后用无 `shipments:write` 的账号确认无法确认出库。建议同时覆盖 401、403、范围外订单和已发货订单取消的 422；未执行。
