# 21 渠道映射

## 实现状态

**部分实现：人工维护的本地 Listing 与内部 SKU 映射已实现；平台连接和自动订单匹配未实现。** 本地映射是 OMS 主数据，不是平台同步日志或平台 API 缓存。

## 业务场景

一个店铺在销售渠道上的商品标识（Listing ID、ASIN 或渠道 SKU）需要人工对应到 OMS 内部 SKU，以便团队统一识别商品。当前保存该对应关系，但订单导入并未自动使用它来解析 SKU；导入仍要求提供内部 SKU 编码。

## 当前入口与操作

- 菜单“商品中心 → Listing 映射”，路由 `/listings`，页面 `frontend/src/pages/ListingsPage.tsx` 的“本地映射”标签。
- 列表 `GET /api/v1/listings` 支持 `shop_id`、`sku_id`、`status`、`q`、分页；详情 `GET /{listing_id}`。
- 新建 `POST /api/v1/listings`；编辑 `PATCH /{listing_id}`；启停 `POST /{listing_id}/activate`、`POST /{listing_id}/deactivate`。以上前缀为 `/api/v1/listings`。
- 页面可新建、查看、编辑内部 SKU/标题、启停。创建后的店铺和平台标识不可编辑；需要纠正标识时停用旧记录并新建。

## 字段、规则与权限

- `shop_id`、`sku_id` 必填；`listing_id`、`asin`、`channel_sku` 至少填写一个；`title` 可空，最多 500 字。
- 平台标识长度：Listing ID/渠道 SKU 最多 160，ASIN 最多 32。每店铺内 listing_id、asin、channel_sku 各自唯一；不同店铺可使用相同值。
- 关联店铺与 SKU 必须存在、启用且在用户店铺范围内；创建时映射状态为 active。状态值 `active/inactive`。
- 查询需 `listings:read`，新建/修改/启停需 `listings:write`。前端新建还要求 `shops:read` 和 `skus:read` 以加载选择项；后端所有单条/列表操作均按 `shop_scope` 限定店铺。

## 边界与异常

- 唯一键冲突会导致创建失败；停用旧映射不释放该标识的唯一性，仍不能在同店铺重复创建同一标识。
- 编辑只接收 `sku_id` 和 `title`；没有通过 PATCH 修改店铺或三个平台标识的能力。
- 启用映射不会检查平台 Listing 是否真实存在，也不会触发同步或改变平台数据。
- 当前订单导入使用提交的 SKU code，不读取该映射；缺失映射不会自动告警。

## 建议验收（未执行）

1. 为启用店铺和启用 SKU 创建仅含 ASIN 的映射；预期 active 并可按 ASIN 搜索。
2. 同店铺再次使用同一 ASIN 创建；预期唯一性冲突；另一个店铺可建立同一 ASIN。
3. 尝试不填三个标识，或关联停用 SKU/范围外店铺；预期校验失败。
4. 编辑 SKU/标题后核对标识不变；停用后列表状态变 inactive，订单导入行为不因此改变。
5. 无 `listings:write` 账号不能创建/修改/启停；范围外映射不可查询。
