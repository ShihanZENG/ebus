# 20 渠道订单导入与同步日志

## 实现状态

**部分实现：人工录入/JSON 批量导入已实现；销售平台 API 同步及持久化同步日志未实现。** 当前导入结果只在请求响应中返回，不保存为可查询的同步批次。

## 业务场景

运营人员将平台导出数据整理为订单后导入 OMS，或通过订单页面/API 手工创建订单。目标中的平台自动同步需授权店铺、选择时间/状态范围，按增量游标拉取订单并记录每批成功、跳过和失败，支持安全重试。

## 当前入口与 API

- 后端导入：`POST /api/v1/orders/import`，由 `backend/app/orders.py` 实现。页面是否提供导入操作应以当前订单页为准；本章不将 API 能力描述为平台同步按钮。
- 普通新建：`POST /api/v1/orders`；订单列表：`GET /api/v1/orders`。
- 导入请求指定 `shop_id`、`source_channel`、`currency_id` 和 rows（来源单号、SKU 编码、数量、单价、折扣及可选客户文本）。服务端按来源单号分组，逐单返回 created、skipped、errors 和计数。

## 当前规则与权限

- 需 `orders:write`；用户的 `shop_scope` 必须包含目标店铺。店铺需启用，导入币种必须是启用币种且与店铺币种相同。
- 同店铺、同来源渠道、同 `source_order_no` 已存在的订单会跳过；一笔订单中重复 SKU、SKU/商品不存在或已停用等会返回该组错误。
- 新导入订单状态为 `draft`；数据写入销售订单及订单明细，不自动审核、付款、申请发货或预留库存。订单金额以店铺币种记账。
- 导入响应包含行号、单号和错误信息，但没有持久化的导入文件、批次、原始请求、重试次数或同步游标。

## 边界与异常

- `source_channel`/`channel` 等文本标识只标注来源，不会触发第三方 API 调用。
- 分组导入可能一组多行；重复单跳过整个来源单号组。校验错误逐组返回，不等同平台拒单或数据同步失败事件。
- API 不提供按导入历史查询、定时任务、手动重试、断点续传、分页增量拉取或上游变更回写。
- `AfterSalesPage` 等页面取订单首 100 条，也不能被当作渠道同步日志或所有订单的全量视图。

## 目标流程与待开发（规划）

- 数据：渠道连接/授权引用、同步批次、同步明细/错误、外部订单 ID、增量游标、重试次数及开始/结束时间；凭证不得明文存入日志。
- 接口：手动启动同步、查看批次/明细、重试失败项、取消运行任务；后台任务按店铺权限和平台限流执行，并以外部订单 ID 做幂等。
- 页面：渠道同步批次列表、按店铺/时间/状态筛选、错误详情与重试入口；明确显示平台拉取时间和 OMS 落库时间。
- 前置依赖：店铺平台授权能力、各平台 API 合约、订单字段映射和限流/数据保留策略。

## 建议验收（当前能力，未执行）

1. 同店铺同渠道同来源单号重复导入；预期第二次进入 skipped，只有一笔订单。
2. 请求含无效 SKU 和重复 SKU；预期错误包含对应行，不产生该订单半成品。
3. 店铺币种与请求币种不一致或用户无店铺范围；预期拒绝且无订单写入。
4. 成功导入后订单状态为 draft；不应自动生成付款、发货或平台同步批次。

## 代码位置

导入与订单创建：`backend/app/orders.py`；订单模型：`backend/app/models.py`；接口输入 schema：`backend/app/schemas.py`。当前没有 `backend/app/channel_sync.py` 或同步批次路由。
