# 19 店铺列表与授权状态

## 实现状态

**部分实现：店铺业务资料 CRUD 已实现；平台授权、Token 管理及订单自动同步未实现。** 店铺是 OMS 内的来源站点档案。`channel` 只是人工维护的渠道文本，不能说明已登录、已授权或正在同步。

## 业务场景

管理员维护店铺编码、名称、渠道、国家站点、时区和结算币种，供订单归属、币种校验、页面筛选和本地 Listing 映射使用。停用店铺可保留历史关联，但创建订单/映射或工单时需使用有效店铺。

## 当前入口与操作

- 菜单“基础资料 → 店铺资料”，路由 `/shops`，页面 `frontend/src/pages/ShopsPage.tsx` 使用通用 `ResourcePage`。
- API：`GET /api/v1/shops`（支持 `q`、`is_active`、`page`、`page_size`），`GET /api/v1/shops/{id}`，`POST /api/v1/shops`，`PATCH /api/v1/shops/{id}`。
- 页面可新增、查看和编辑资料；店铺编码创建后不可改。渠道默认值 `manual`；币种下拉依赖币种字典。

## 字段、状态与权限

- `code` 唯一且创建后不可变；`name`、`channel`、`market`、`timezone`、`currency_id` 必填；`is_active` 表示本地档案启停。
- 渠道、站点和时区目前是字符串资料；时区由 schema 校验为有效时区；币种必须引用启用中的 currency 字典。
- 列表/详情需 `shops:read`，写操作需 `shops:write`。有受限 `shop_scope` 的账号只可读取其范围内店铺，后端不允许其创建店铺；创建/维护店铺属于全范围资料权限。
- 店铺作用范围由用户 `shop_scope` 控制订单、工单和 Listing 等业务数据访问；这不等同于第三方平台授权范围。

## 边界与未实现能力

- 当前 `Shop` 模型只有编码、名称、渠道、市场、时区、币种、启用状态及通用时间戳；没有授权状态、平台账号、Token、授权过期时间、同步时间或操作人绑定字段。
- 没有 OAuth 授权/回调、Token 加密与续期、平台连通性检查、撤销授权、提醒或自动拉单接口。不能仅凭 channel 值显示“已授权”。
- 店铺停用不代表平台断开连接；启用也不代表渠道 API 可用。

## 规划功能与验收条件

若要加入平台授权，建议新增独立连接凭证实体（平台、外部账号/站点、加密凭证引用、授权状态、过期时间、最近校验时间、最近同步时间），由后端安全管理 Token；增加授权回调、刷新/撤销/校验接口及管理员授权页面。验收应覆盖 Token 不回显、过期可识别、刷新失败告警、跨店铺权限隔离；“已授权”只在凭证校验成功后显示，且不得与订单同步成功混为一谈。

## 代码位置

`Shop` 模型：`backend/app/models.py`；通用资源及店铺范围：`backend/app/resources.py`；字段 schema：`backend/app/schemas.py`；前端：`frontend/src/pages/ShopsPage.tsx`；路由注册：`backend/app/main.py`、`frontend/src/App.tsx`。
