# OMS 功能文档编写与验收规范

本规范用于把 `docs/oms/` 的章节写成可阅读、可开发和可验收的说明。每篇仍以当前仓库代码为准，不能把目标系统或参考产品的功能写成已交付。

## 每篇应回答的问题

1. **业务场景：**谁在什么时候使用，输入是什么，期望得到什么结果。
2. **当前入口：**真实的菜单路径、页面路由和后端接口；若没有入口，明确写“当前无页面/接口”。
3. **数据与规则：**关键字段、必填约束、状态变化、金额或库存口径，以及店铺/仓库范围。
4. **操作步骤：**当前能在页面完成什么；仅有 API 而没有按钮时，分开说明。
5. **异常与边界：**重复单号、库存不足、无权限、状态不允许、上游数据不完整等实际情况。
6. **验收方法：**给出可操作的样例和预期结果；未执行的步骤标为“建议验收”，不声称已通过。
7. **实现状态：**分别列“已实现”“部分实现”“尚未实现”，并链接到真实代码或接口定义。

## 规划功能写法

当前没有实现的功能可以保留业务目标，但要单独列出：目标流程、需要新增的数据结构/接口/页面、前置依赖、权限与验收条件。规划中的路径和字段应标为“建议”，不得写成系统当前可访问的地址或已有数据表。

## 交叉模块边界

- OMS 订单审核只确定履约仓；申请发货才创建 WMS 出库单并预留库存，WMS 确认出库才扣减在库。
- 订单售后记录、客服工单、真实退款流水是三类不同对象；一个对象状态完成不自动完成另外两个对象。
- 店铺资料的渠道字段、本地 Listing 映射、DataLab 只读表和电商平台 API 同步是不同来源。
- DataLab 页面对返回行求和不等于全量报表；应写明取数上限、币种与数据更新时间的限制。

章节目录中的“文档已校对”只表示内容已按代码核对，不代表功能完成。功能新增后应先改相应章节，再更新目录中的能力速览。
