# 23 客户列表

## 实现状态

**尚未实现客户目录。** 当前没有独立客户主档表、客户列表接口或客户列表页面。订单保存的是订单级客户名称/联系方式文本，不能据此认定已建立客户档案。

## 业务场景与目标

客服或运营需要在授权范围内查找客户，查看其跨订单关系、联系偏好和售后风险，以便服务跟进。客户列表应提供可靠的客户标识和可解释的汇总指标，同时避免将不同客户错误合并或暴露不必要的个人信息。

## 当前入口与相关数据

- `App.tsx` 没有客户列表路由；菜单未注册客户目录。
- `sales_orders` 字段 `customer_name`、`customer_contact` 是订单快照。订单列表 `GET /api/v1/orders` 可按关键词搜索来源订单号或客户姓名，但没有客户 ID、消费汇总或 `customer_id` 筛选。
- `customer_tickets` 通过可选 `order_id` 关联订单，不关联客户实体；工单主题/描述也不是客户档案。
- 当前不存在 `backend/app/customers.py`、`customers` 表或 `/api/v1/customers` 接口。

## 规划的数据与接口

建议先明确客户归并策略，再实现：

- 客户主档：内部 `customer_id`、来源标识/来源渠道、标准化客户标识、姓名/联系方式、国家地区、首次/最近交易时间、状态及审计字段。敏感联系方式应按最小权限展示并设置保留/脱敏规则。
- 订单关联：订单新增可空 `customer_id`，保留创建时客户文本快照；迁移历史数据时仅对高置信标识自动归并，模糊姓名不能自动合并。
- 查询接口：建议 `GET /api/v1/customers` 支持关键词、国家、标签、订单数/消费区间、最近下单时间及分页，并返回明确币种和汇总口径；记录详情和聚合数据需遵守店铺范围。
- 页面：建议客户列表包含客户编号/脱敏联系信息、订单数、按币种拆分的累计实付、最近订单/购买时间和标签。不要把不同币种直接求和。

## 权限与边界（规划）

建议定义独立 `customers:read/write` 权限，并以客户关联订单的可见店铺范围控制访问。若一个客户跨多个店铺，需说明只有部分店铺权限的用户看到哪些订单数和消费汇总，避免通过总数泄露其他店铺数据。联系方式查看可再设敏感字段权限。

客户匹配应优先使用可信的渠道客户 ID 或经验证的邮箱/电话规范化值；姓名、地址或模糊字符串不应单独作为唯一键。多个渠道对同一客户的标识可能不同，应支持人工合并/拆分和审计。

## 建议验收（未实现）

1. 两笔订单使用同一稳定客户标识时，在授权范围内归为一个客户；仅姓名相同但标识不同的客户不得自动合并。
2. 客户跨店铺下单时，受限用户的列表统计和订单明细不泄露其无权店铺的数据。
3. 累计金额按币种分别呈现，并明确统计订单状态、退款是否扣减及取消订单排除口径。
4. 联系方式默认脱敏；缺少敏感字段权限时 API 不返回完整值。
5. 空档案、无历史订单、重复导入及历史数据归并冲突均有可解释处理与审计。

## 代码位置

订单客户文本字段：`backend/app/models.py`；订单接口：`backend/app/orders.py`；路由注册：`frontend/src/App.tsx`。尚无客户目录实现。
