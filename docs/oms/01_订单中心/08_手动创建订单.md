# 08 手动创建订单

## 文档状态

页面支持人工录入订单，字段以当前表单和 API schema 为准。表单没有收件地址或手机号专用字段；客户联系方式是一个自由文本字段。

## 当前表单

- 店铺、来源渠道（默认 `manual`）、来源单号、币种。
- 可选预选履约仓、客户名称、客户联系方式、备注。
- 至少一条商品行：SKU、数量、单价、行优惠。商品行金额及订单金额由后端计算。

创建接口要求店铺币种与订单币种一致、SKU 有效、SKU 不重复，且明细至少一行。来源单号在同店铺、同渠道范围内不可重复。创建后状态为 `draft`（页面显示“待审核”）。创建本身不检查或预留库存。

## 操作

在“销售 → 销售订单”点击“新建订单”，填写表单后提交。页面加载店铺、币种及 SKU 选项；还要求相应读取权限。

## 状态与导入

- **已实现**：订单表单及 `POST /api/v1/orders`。
- **未实现**：地址校验、地址簿、自动库存提示、渠道订单自动抓取。
- **订单导入页面**：“销售 → 订单导入”支持上传或粘贴 CSV/TSV，在浏览器解析、预览后将 JSON 行提交给 `POST /api/v1/orders/import`；不是平台连接器，也不支持 Excel 工作簿格式。

## 代码位置

- 前端：`frontend/src/pages/Orders.tsx`
- 输入结构与校验：`backend/app/schemas.py` 的 `OrderCreate`、`OrderItemInput`
- 业务校验及金额计算：`backend/app/orders.py` 的 `create_order`
- 字段模型：`backend/app/models.py` 的 `SalesOrder`、`SalesOrderItem`

## 创建步骤和字段校验

1. 进入“销售 → 销售订单”，具备订单写权限且具备店铺、币种、SKU 读取权限后点击“新建订单”。页面最多加载 100 个启用资料；若选项不完整先处理权限或基础资料。
2. 选择店铺。表单会将币种设为该店铺币种，币种候选也限定为匹配项；来源渠道默认 `manual`，但可输入任意非空渠道字符串（最多 80 字符），这不代表平台已连接。
3. 填来源单号、客户名称/联系方式（可选），必要时填备注。来源单号最多 120 字符；客户名称最多 120、联系方式最多 200、备注最多 1000。
4. 至少保留一条商品行，选一个未停用 SKU，输入数量（1–1,000,000）、非负单价和非负行优惠。一个订单内不允许同一 SKU 出现两次；如需同 SKU 多批次数量，应合并数量录入。
5. 提交后服务端再次校验店铺与币种有效、店铺币种一致、SKU/所属商品启用及同店铺/渠道/来源号唯一性。服务端重算金额，不接受客户端计算结果作为权威值。成功生成 `draft` 订单和创建审计事件；此时没有库存检查或预留。

### 失败场景与建议验收

没有 `orders:write` 会被前端阻止且 API 也会拒绝；缺少 `shops:read`、`dictionaries:read` 或 `skus:read` 时按钮禁用；店铺超出 `shop_scope` 返回 403；重复单号返回 409；停用/无效引用、重复 SKU、优惠超过行金额、店铺币种不一致返回 422。创建库存为零的 SKU 订单仍可能成功，因为库存只在申请发货时校验。

建议验收：录入单价 10.00、数量 3、优惠 2.50 的行，预期总额 30.00、优惠 2.50、应付 27.50；重用相同店铺/渠道/来源号应冲突；停用 SKU 应拒绝；使用无可用库存 SKU 创建仍可成功，但申请发货时失败且不部分预留。另通过导入页验证 CSV/TSV 解析、1000 行上限、重复来源单号分组跳过及逐组错误返回。建议步骤未执行。
