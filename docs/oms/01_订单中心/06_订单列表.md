# 06 订单列表

## 文档状态

后端和订单页面均已接入分页、状态/店铺/创建时间和关键词筛选。店铺筛选依赖 `shops:read` 权限。

## 页面显示

表格显示来源单号、客户名称、应付金额、状态、创建时间及操作。点击行打开详情；行操作依状态提供审核、申请发货或取消。没有独立系统订单号列、商品列、店铺列或渠道列。

## 后端接口

`GET /api/v1/orders` 支持 `page`、`page_size`（最大 100）、单个 `status`、`shop_id`、`date_from`、`date_to` 和 `q`。关键词匹配来源单号或客户名称。响应为 `items/total/page/page_size`。这里的日期筛选使用记录 `created_at`，不是渠道下单时间。

## 状态

- **已实现**：后端分页和上述筛选；前端表格、详情入口和状态操作。
- **部分实现**：店铺筛选选项只加载前 100 个启用店铺；表格仍未显示店铺名称列。
- **未实现**：订单列表导出、批量操作、列配置、状态标签页。

## 当前查询步骤与字段说明

页面进入时调用 `GET /api/v1/orders`，默认 `page=1&page_size=20`。可以选择每页 10/20/50/100 条、翻页、按状态/店铺/关键词/创建日期范围筛选，刷新沿用当前条件；页面显示服务端返回的 `total`。页面把用户本地日期的起止边界转换成 UTC 查询时间，结束日使用下一日零点的排他边界。表格显示来源单号、客户、应付金额、状态、创建时间和按状态可执行的操作；金额旁的币种代码来自页面加载的币种选项，若代码未加载则可能只显示金额。

接口查询可直接支持 `status`、`shop_id`、`q`、`date_from`、`date_to` 与分页参数。`q` 匹配来源单号或客户名称；日期过滤使用 `SalesOrder.created_at`，`date_to` 在实现中是排除边界。接口允许 `page_size` 1–100。列表不含订单行、商品、店铺显示名或付款/售后明细；需用详情接口补充。

### 数据范围、错误边界和建议验收

`orders:read` 是接口权限；即使请求指定其他 `shop_id`，结果仍叠加用户 `shop_scope`，不会因此扩大范围。请求无效的页码/页大小由参数约束拒绝；未授权返回 403。页面店铺下拉仅对有 `shops:read` 的用户显示。

建议验收：准备同一客户不同来源号、不同店铺和跨日期订单；分别通过页面及列表 API 验证关键字命中来源号/客户名、状态和店铺交集、`date_to` 不包含边界时刻、翻页与总数稳定。建议步骤未执行。
