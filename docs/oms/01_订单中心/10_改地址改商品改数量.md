# 10 订单编辑与履约阶段变更

## 当前实现

后端已提供 `PATCH /api/v1/orders/{id}`，可修改客户名称、联系方式、备注、预选履约仓和商品明细。前端订单行和详情已接入编辑抽屉。当前订单没有结构化收货地址字段，因此本接口不能修改地址。

## 请求字段

| 字段 | 规则 |
|---|---|
| `reason` | 必填，去除首尾空白后 1–500 字符，保存到审计记录 |
| `customer_name` | 可选，最多 120 字符，空值清空 |
| `customer_contact` | 可选，最多 200 字符，空值清空 |
| `remark` | 可选，最多 1000 字符，空值清空 |
| `warehouse_id` | 可选；省略保持原值，显式 `null` 清空；指定时须启用且在账号仓库范围内 |
| `items` | 可选；省略保持原明细，提供时整组替换，1–200 行，不接受 `null` 或空数组 |

商品行使用 `sku_id / quantity / unit_price / discount_amount`，与创建订单规则相同。数量必须为正整数，金额最多两位小数，SKU 不重复且有效，优惠不能超过该行商品金额。店铺、币种、来源渠道和来源单号不可通过编辑接口更改。只有原因而没有待修改字段的请求会被拒绝。

## 状态和金额规则

- `draft` 可以修改；`approved` 修改成功后退回 `draft`，必须重新审核。
- `shipping_requested`、`fulfilled`、`cancelled`、旧版 `after_sale` 状态禁止直接编辑。
- 存在任何出库单时禁止编辑，即使出库单已取消，以免原履约记录与商品明细不一致。
- 服务端重新计算商品总额、优惠总额和应付金额；新应付金额不得低于订单累计付款记录金额。
- 修改不预留或扣减库存，不执行退款；已预留订单的变更申请流程尚未开发。

## 权限、事务和追溯

要求 `orders:write`，并校验订单所属 `shop_scope` 和有效履约仓的 `warehouse_scope`。范围外订单返回 404，范围外仓库返回 403；无操作权限返回 403；字段、状态或金额不符返回 422。

编辑、审核、发货申请、取消和登记付款获取同一订单的行锁。编辑在校验完成后写入，订单与明细替换及审计在同一事务提交。审计 `action=edit`，`before/after` 包含商品快照，`after.edit_reason` 保存原因。SQLite 测试用于接口行为回归，不能证明 PostgreSQL 的并发行锁行为。

## 调用示例

```json
{
  "reason": "客户要求调整购买数量",
  "customer_name": "张三",
  "items": [
    {"sku_id": "替换为真实的36字符SKU标识", "quantity": 3, "unit_price": "20.00", "discount_amount": "5.00"}
  ]
}
```

示例商品应付金额为 55.00；需要用真实 SKU ID 替换占位文本后提交。响应返回编辑后的订单与商品明细。

## 后续范围

结构化地址、独立变更申请与审批、已预留订单撤销并重建履约和变更历史页面仍待开发。不能通过直接修改已出库原单纠正交易。

## 前端操作

销售订单行或详情中点击“编辑”，填写变更原因后保存。已审核订单提示退回待审核。页面按权限加载商品及仓库，未改变的字段不提交；保存失败保留表单，成功后刷新列表与详情。前端构建已通过，登录后的实际保存操作尚未联调。
