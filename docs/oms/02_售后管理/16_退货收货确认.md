# 16 退货收货确认

## 实现状态

**尚未实现。** 当前只有 `type=return` 的订单售后文本记录和 pending/completed/rejected 状态；没有退货物流、收货、质检或退货入库对象。将售后记录标记 completed 不表示仓库已收到商品，也不会增加库存。

## 业务场景与目标流程（规划）

适用于客户寄回全部或部分商品的申请。目标是将客户申请、逆向物流、仓库实物验收和可售库存处理串成可追溯链路：

1. 受理退货申请，绑定订单明细/SKU、申请数量、原因和退货地址规则；批准后生成退货授权号。
2. 记录承运商、退货运单号、寄出/签收时间，跟踪未寄回、运输中、已签收、超时等状态。
3. 仓库按授权单扫描商品，记录实收数、商品状况、照片/差异和验收人；超量、错 SKU、破损进入异常处理。
4. 按验收结果决定可售入库、质检/残次库存或不入库；只有库存事务成功后才将收货状态结案，并与后续退款申请关联。

以上是目标流程，不是现有页面或 API。

## 当前可用能力

- 创建退货分类记录：`POST /api/v1/orders/{order_id}/after-sales`，`type=return`；字段只有原因、数量、金额、备注。
- 查询订单售后记录：`GET /api/v1/orders/{order_id}/after-sales`。
- 记录状态处理：`POST /api/v1/after-sales/{after_sale_id}/resolve`，仅将 pending 改为 completed/rejected。
- `/after-sales` 页面只显示汇总记录并提供完成/驳回，没有退货签收入口。

## 需新增的数据、接口与页面（建议）

- 数据：退货授权/退货单（来源售后记录、订单行/SKU、批准数、状态）、逆向物流事件、收货验收明细（实收数、状况、图片、差异原因）、退货库存事务（仓库/库存状态/数量/幂等来源）及操作审计。
- 接口：申请审核/批准/拒绝、物流信息更新与事件查询、仓库收货、验收确认、退货入库/隔离及异常处理。需校验订单/店铺范围、可收数量、重复扫描和幂等键。
- 页面：客服/运营退货申请列表与详情；仓库待收货、验收及差异处理页。客服审批与仓库验收应分别授权。
- 前置依赖：确认 WMS 是否支持退货入库和库存状态区分；如无，新增 WMS 退货入库单与库存流水，不能直接改库存余额。

## 边界与验收条件（规划）

建议验收：批准后生成唯一退货单；仅批准数量可收；超量、错 SKU、重复提交被拒绝或进入差异队列；可售品增加对应仓库可用库存，残次品进入隔离库存；库存事务失败时退货单不结案且可安全重试；收货/入库可追溯操作者和原申请；退货签收与退款执行状态分别显示，不互相冒充完成。

## 代码位置

当前售后记录在 `backend/app/models.py`、`backend/app/orders.py`；页面在 `frontend/src/pages/AfterSalesPage.tsx`。没有退货收货模型、路由或页面。
