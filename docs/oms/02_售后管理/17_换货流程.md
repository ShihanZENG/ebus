# 17 换货流程

## 实现状态

**尚未实现。** 售后类型目前只有 `refund` 与 `return`，不存在换货单、换入 SKU、换出库存预留、补差价或换货出库接口。客服工单不是换货申请。

## 业务场景与目标流程（规划）

客户因尺码、颜色、错发或质量问题要求更换商品时，客服确认原订单和可换数量，再由运营审核换货条件；仓库接收并验收原商品，库存/质量判定后安排换出商品。若新旧商品价格或运费不同，应在发货前确认差额承担方与收付款状态。

建议流程：提交申请 → 审核通过/拒绝 → 生成原商品退回单 → 退回签收与验收 → 检查换出 SKU 可用库存 → 预留库存并生成换出发货单 → 物流签收/异常 → 关闭换货。各阶段需要取消、缺货和超时处理。

## 当前相关入口

- 客服工单：菜单“销售 → 客服工单”，`/customer-tickets`。工单字段是店铺、可选订单、主题、描述、优先级和处理人，不含换货品项。
- 订单售后：菜单“销售 → 售后”，`/after-sales`。只能查看/完成/驳回 refund/return 记录。
- 售后 API 的类型不含 exchange；不能用 `type=return` 或创建工单表示换货已建立。

## 需新增的数据、接口与页面（建议）

- 换货申请主表：申请号、原订单/订单行/SKU、申请数量、换入 SKU、原因、差价、运费承担、审核人/时间、状态及关联客服工单。
- 退回端复用或建设退货授权、物流、收货验收和库存入库；换出端关联 OMS 新出库单/WMS 库存预留，保留原订单与换出单的关系。
- 接口覆盖申请、审核、退回物流、验收、换出库存检查/预留、发货、取消、差异处理及事件查询；操作需幂等并检查店铺/仓库范围。
- 页面：售后换货申请/审批页、仓库退回验收页、换出履约跟踪页；详情展示双向物流和差额。

## 边界与建议验收（未实现）

验收覆盖：同一订单行不能超过可换数量；换入 SKU 停用/无货时不能预留；原货未按规则验收时不得自动发出换货品；重复提交不能重复占库存；取消换货释放已预留库存；价差/运费未确认时阻止发货；换货完成仅在退回处置与换出履约均达到定义条件后成立。退回入库和换出发货分别记录库存流水。

## 代码位置

订单售后 schema 在 `backend/app/schemas.py`；客服工单在 `backend/app/customer_tickets.py`；库存及出库在 WMS 路由。当前没有换货专属实现。
