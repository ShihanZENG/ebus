# 14 客服工单列表

## 实现状态

**已实现：客服跟进工单基础闭环。** 工单用于记录客户问题、内部处理过程和责任人。它与订单售后记录、退款流水、退货收货单是不同业务对象；工单完成只代表客服跟进结束。

## 业务场景

客服收到客户关于订单、商品或配送的咨询/投诉后，建立工单，指定店铺与可选订单，标记紧急程度并跟踪处理。一个工单可不关联订单；系统没有客户主档，也不会从订单姓名自动识别客户。

## 当前入口与操作

- 菜单“销售 → 客服工单”，路由 `/customer-tickets`（`frontend/src/App.tsx`），页面 `CustomerTicketsPage.tsx`。
- 列表调用 `GET /api/v1/customer-tickets`，支持状态、优先级、店铺、处理人、工单号/主题/描述筛选及分页；页面目前固定请求前 100 条，再由表格本地分页。
- 新建：选择启用店铺，选填同店铺销售订单，填写主题、描述、优先级；调用 `POST /api/v1/customer-tickets`。
- 详情调用 `GET /api/v1/customer-tickets/{ticket_id}`，返回工单及按时间排序的事件。
- 处理接口：`POST /{id}/assign` 分派（可清空处理人）；`/start` 开始；`/notes` 追加记录；`/resolve` 完成；`/reopen` 重新打开；`/close` 关闭。路径前缀均为 `/api/v1/customer-tickets`。

## 字段、状态与权限

- 工单号由服务端生成 `CT-日期-随机码`；店铺 `shop_id` 必填；`order_id` 可空；主题 1–200 字，描述 1–10000 字。
- 优先级：`low / normal / high / urgent`；状态：`open` 待处理、`in_progress` 处理中、`resolved` 已完成、`closed` 已关闭。
- 允许转换：open → in_progress → resolved → closed；resolved 可重新打开为 open。open 可直接完成；关闭后不能追加记录。状态动作会写事件与审计日志。
- 查看需 `customer_tickets:read`，操作需 `customer_tickets:write`。创建还需页面可读取店铺（`shops:read`）；关联订单选择依赖 `orders:read`。后端按用户 `shop_scope` 过滤/校验，关联订单必须属于所选店铺；分派的处理人必须启用且覆盖该店铺范围。

## 边界与异常

- 店铺不存在、停用或超出店铺范围会拒绝创建；无权查看的工单按不存在处理。关联订单不存在、跨店铺或无范围访问会拒绝。
- 只有 open 可开始；只有 open/in_progress 可完成；只有 resolved 可重开或关闭；closed 不可追加处理记录。非法状态操作返回 422。
- 工单描述/事件是内部记录，不会自动向客户发邮件/站内信；没有“客服拒绝”状态、SLA、附件或退款/退货/换货联动。
- 页面订单选择只拉取前 100 条订单，工单列表也只请求前 100 条，超出时不能据此认定为全量列表。
