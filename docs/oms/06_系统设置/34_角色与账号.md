# 34 角色与账号

> **实现状态：已实现（基础账号及角色权限管理）**。管理员可维护账号、自定义角色权限和店铺/仓库数据范围；姓名字段不在当前账号模型中。

## 业务说明

管理员在账号管理页创建账号、分配角色和数据范围，调整账号启停状态或重置密码；角色权限由系统注册的权限项组成。权限检查在前端路由和后端 API 中执行。管理员角色为保留角色，拥有全部已注册权限。

## 账号字段

| 字段 | 说明 |
|------|------|
| 用户名 | 登录账号 |
| 角色 | 关联角色 |
| 店铺范围 | 可访问店铺 ID 列表；`null` 表示全范围 |
| 仓库范围 | 可访问仓库 ID 列表；`null` 表示全范围 |
| 状态 | 启用/停用 |

当前没有独立姓名字段；角色名称也由管理员自定义，不预设管理员/运营/客服/仓管/财务这些固定角色。

## 操作路径

系统设置 → 角色与账号（账号管理页的账号、角色标签页）。仅管理员可访问。

## 数据来源与接口

- 本地表：`users`、`roles`。
- 管理接口：`GET /api/v1/users`、`POST /api/v1/users`、`PATCH /api/v1/users/{id}`、`PUT /api/v1/users/{id}/password`。
- 角色及权限接口：`GET /api/v1/roles`、`POST /api/v1/roles`、`PUT /api/v1/roles/{id}`、`GET /api/v1/permissions`。

## 页面行为、权限和异常边界

`/users` 路由由前端管理员守卫限制；后端账号/角色 API 均再检查管理员角色，不能只依赖前端隐藏菜单。页面并行读取最多 100 个账号、店铺、仓库，以及全部角色和注册权限；账号表的搜索只针对当前已加载账号的用户名/角色名。角色权限集合按 `resource:read|write` 管理，另有 `audit:read` 和 `dashboard:read`；管理员角色绕过权限集合并拥有全部注册权限。

新建账号需用户名、8–128 位密码、有效角色、启停状态和店铺/仓库范围。空数组表示不分配任何范围，数据库 `null` 才表示全范围；编辑资料可传 `null`，因此配置范围时应明确区分“无范围”和“全范围”。接口校验范围中的 ID 均存在。用户名唯一冲突、未知角色或无效范围会失败；角色编码唯一且创建后不可修改，`admin` 是保留编码不能创建或编辑；角色权限必须全部属于后端注册权限。密码重置成功后目标账号全部现有会话被撤销。管理员不能停用或降权当前自己的账号，页面亦禁止停用自身；管理员角色账号不可在页面改为普通角色。

数据范围由后端业务接口分别执行：订单和售后按店铺范围隔离，库存/出入库按仓库范围隔离；并非每个模块都同时应用两类范围。账号权限不能替代业务数据范围设计。密码只在提交时传送，接口返回不含密码或密码哈希。

## 建议验收

1. 管理员创建普通角色并仅授予订单读取权限，用户能读取授权店铺订单但不能写订单；前端隐藏入口之外，直接调用对应 API 也应收到 403。
2. 分别设置 `shop_scope=[]`、`shop_scope=null`，验证前者无店铺数据、后者按全范围处理；无效范围 ID 创建/更新账号预期 422。
3. 重置密码后旧会话访问接口返回 401，新密码可登录；停用账号后会话不可用。管理员尝试降权或停用自己预期 422。
4. 创建含未知权限的角色、修改 `admin` 角色或修改既有角色编码均被拒绝。账号列表超过 100 条时注意当前页面只请求前 100 条，建议后续增加真正的分页/搜索再验收全量管理能力。
