# 31 物流渠道配置

> **实现状态：未实现**。当前未发现物流渠道档案模块、数据表、API 或配置页面。

## 业务说明

规划维护可用承运商/物流渠道及其服务范围，供发货选择和后续运费、轨迹对接使用。现有出库单可保存运单号，但没有渠道主数据或物流商接口；保存运单号不代表已配置或对接物流渠道。

## 规划字段

| 字段 | 说明 |
|------|------|
| 渠道名称 | 承运商及服务产品名称 |
| 运输方式 | 空运、海运、快递等 |
| 可发国家 | 渠道服务范围 |
| 时效 | 参考运输时效 |
| 单号规则 | 运单号格式或前缀 |

## 操作路径

系统设置 → 物流渠道（当前无对应页面）。

当前无 `logistics.py` 等物流渠道后端模块或对应 API；出库单及运单号字段见 `backend/app/models.py`、`backend/app/wms.py`。

## 建议目标流程与数据设计

规划中先由管理员建立渠道档案，配置承运商、服务产品、服务国家/区域、运输方式、币种及时效说明，并以启停/生效日期控制可选范围；运营或仓库在发货单上选择渠道后，才允许请求物流商下单、获取面单与跟踪号。渠道档案与渠道 API 凭证应分开存放，凭证加密且不可在列表/审计快照中回显。物流下单需带幂等键并保存请求关联 ID，错误、超时和取消应有明确状态及人工重试流程。

建议新增物流渠道、渠道服务区域/产品及渠道账户配置对象；新增渠道 CRUD、可用渠道查询、创建运单、取消运单、轨迹同步/回调接口。出库单需要扩展 `channel_id`、渠道订单号、面单文件引用、物流状态及失败信息等字段。页面建议包含渠道配置页和出库单渠道选择/物流详情，不把当前自由文本运单号当成渠道已对接的证据。物流选择、下单、取消权限需和仓库范围绑定并留审计。

当前 WMS 确认出库可以保存 `tracking_no` 文本，但没有承运商主档、渠道选择或 API 调用；物流渠道不可通过现有仓库档案或运单号配置出来。

## 建议验收

1. 管理员新增、编辑、停用渠道并配置服务区域；停用或服务国家不适用的渠道不出现在发货可选项。
2. 对可服务订单发起物流下单，成功时只创建一个渠道运单并持久化渠道号、跟踪号和面单引用；同一幂等请求重放不重复下单。
3. 模拟鉴权失败、承运商拒单和网络超时，界面显示可诊断状态；超时重试先核实渠道结果，不能盲目重复创建运单。
4. 无仓库范围权限的用户不能查看或操作范围外出库单；敏感凭证不会通过 API 响应或审计页面暴露。以上均属新增功能验收条件。
