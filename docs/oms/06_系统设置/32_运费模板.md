# 32 运费模板

> **实现状态：未实现**。当前没有运费模板数据模型、管理页面、运费计算服务或对应 API。

## 业务说明

规划根据国家、物流渠道、重量/计费规则计算订单运费。现有订单金额和出库信息不包含按运费模板计算的费用，不能据此认为系统已经自动算运费。

## 规划模板结构

| 字段 | 说明 |
|------|------|
| 模板名称 | 例如美国专线标准 |
| 适用国家/渠道 | 模板适用范围 |
| 首重价格 | 首个计费重量区间价格 |
| 续重价格 | 后续计费重量价格及单位 |
| 处理费 | 每票固定费用 |
| 附加规则 | 偏远地区、燃油等附加费 |

计算示例仅作规则说明，具体计费进位、重量单位和币种需在实现时确定。

## 操作路径

系统设置 → 运费模板（当前无对应页面）。

## 建议计费流程与数据要求

计费前必须具备包裹目的国家/邮编、渠道服务产品、计费重量及尺寸；当前 OMS 订单/出库流程未形成完整包裹计费输入，不能仅依订单商品数量推断运费。建议模板设定币种、生效时间、优先级、适用国家/邮编范围和渠道；首重/续重、计费单位与进位方式、最低费用、处理费、燃油/偏远地区附加费均应明确，并支持按实际重量或体积重取大值。费率变更需保留版本，历史订单应引用计算时的版本和费用快照。

建议新增模板、费率阶梯、适用区域、附加费规则及订单运费报价/费用明细对象；新增模板 CRUD、试算、订单报价/确认接口。试算返回费用明细、计费重量、命中的规则和版本，不应直接改动订单应收；用户确认后固化报价快照。模板停用或过期不影响历史快照。页面建议支持模板维护、规则试算和订单运费明细下钻，并对币种与权限做店铺/仓库范围隔离。

## 建议验收

1. 用首重、续重和重量进位边界样例试算，费用分项、总额、币种、规则版本和命中区域均符合已确认的费率规则。
2. 缺重量/目的地、无适用渠道或无有效模板时返回明确“无法报价”原因，不得静默显示 0 运费。
3. 模板更新后新报价使用新版本，既有订单报价保持原费率快照；并发/重复确认不会创建重复运费明细。
4. 页面展示金额与接口明细相符，权限外店铺/仓库订单不能读取或改价。以上都需要相关模型、接口和页面实现后再验收。
