# 29 对账报表

> **实现状态：未实现**。没有 OMS 与平台结算单的导入、逐笔匹配、差异处理或财务对账报表。

## 业务说明

规划用于比较平台结算单与 OMS 记录，定位订单金额、退款、平台手续费、广告费和物流费差异。当前财务页面读取 DataLab `dws_finance_day` 的每日汇总并展示，不会导入平台结算文件，也不会执行匹配或核销；每日汇总展示不能视为已实现对账。

FBA 收货相关页面展示 DataLab 中的 FBA 收货数据，属于仓储收货信息，不是平台财务结算对账。

## 规划流程

1. 导入平台结算单或接入结算数据。
2. 按订单号、金额、币种及费用类型匹配系统记录。
3. 展示未匹配项和金额差异，供人工核对。
4. 记录核对结论，并生成期间汇总。

以上流程尚未实现。

## 目标数据与匹配规则

建议导入批次保存来源渠道、店铺、结算期间、结算币种、文件名/文件摘要、上传人、导入时间和解析结果；原始行至少保留平台交易号、订单号、交易类型、发生时间、币种、订单金额、退款金额、佣金/其他费用、结算净额及原始行内容。导入应先做格式与必填校验，再按交易号和文件摘要防重；重复文件应提示已导入批次，不得重复计入金额。

匹配应分层进行：优先用平台交易 ID，其次使用来源订单号、交易类型、币种和金额容差。匹配结果应分为自动匹配、人工确认、未匹配、金额差异、重复记录等状态，并记录匹配依据、差额、操作人、处理时间和备注。不能将仅有每日汇总字段的 `dws_finance_day` 行与订单付款逐笔匹配；OMS 付款记录、退款流水和平台结算交易必须保留各自来源身份。

建议新增对账批次、导入行、匹配关系和差异处理记录等对象，以及上传/校验、批次查询、逐行匹配/人工调整、差异关闭、汇总和导出接口。页面规划为“财务 → 对账”，提供批次状态、金额汇总、未匹配/差异队列、订单侧与平台侧并排明细及处理审计。权限建议至少区分导入、查看、核销/关闭差异；以店铺范围隔离数据。财务汇总页面现有 `dashboard:read` 仅授权 DataLab 看板查询，不能作为对账操作授权。

## 建议验收

1. 导入一份含销售、退款、平台费、重复行和无效行的样例文件，系统返回逐行解析结果与批次汇总；重复导入相同文件不会重复入账。
2. 交易号唯一且金额/币种一致的行自动匹配；无交易号但可疑似匹配的行进入待人工确认；金额、币种不一致进入差异队列，不自动核销。
3. 人工关闭差异必须填写处理结论和说明，记录操作者与时间；无对账权限或无对应店铺权限不能查看/操作该批次。
4. 批次汇总与其导入行逐项加总相符，筛选和导出范围一致。导入、匹配和差异处理接口均为规划，当前没有可执行验收入口。
