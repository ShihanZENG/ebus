# 28 订单利润核算

> **实现状态：未实现**。当前没有 OMS 订单利润计算或利润报表。

## 业务说明

规划按订单、SKU、店铺和期间核算利润。利润口径需明确收入、商品成本、头程/尾程运费、平台佣金、广告费分摊、退款损失及币种换算，当前代码没有实现这些成本归集与计算。

## 规划利润构成

```text
订单收入
  - 商品成本
  - 头程运费
  - 尾程运费
  - 平台佣金
  - 广告费分摊
  - 退款损失
= 净利润
```

## 展示维度

- 按订单：每笔订单利润
- 按 SKU：SKU 利润排行
- 按店铺：店铺利润
- 按月份：月度趋势

以上均为规划内容。

## 操作路径

左侧菜单 → 财务管理 → 利润报表（当前无对应页面）。

## 数据来源

订单和采购数据分别存在 OMS；广告等数据可能由 DataLab 提供。但当前不存在将这些数据关联、归集、换汇并计算利润的服务或接口。DataLab 广告页面（如有）展示广告数据，不等于订单利润核算。

## 建议口径与目标流程

利润报表开发前应确认核算粒度和确认时点。建议以订单币种输出订单毛利与净利润，分别展示订单商品净额、退款损失、商品成本、平台佣金、广告分摊、头程/尾程物流费及其他调整；只有具备来源凭证的费用才进入已确认利润，缺少成本的数据标为“成本待补”，不可静默按零成本计算。需保存汇率来源、汇率日期、基准币种和换算精度，并区分订单创建、发货、结算等统计日期口径。

建议新增成本/费用明细及计算快照对象，关联订单、订单行或 SKU、店铺、费用类型、币种、原币金额、汇率、基准币金额、来源单据、确认状态和生效日期。成本可从采购收货或供货价映射，但必须明确成本版本/批次；广告费需定义按销售额、点击、订单归因或人工规则分摊，并保留分摊明细。退款需关联实际退款流水；OMS 当前只有申请记录，因此不可将售后申请金额直接当成已退款损失。

建议新增利润计算服务及可重算的批次/版本，输出订单、SKU、店铺和期间汇总 API；前端建议新增“财务 → 利润报表”页面，支持店铺、渠道、订单日期/结算日期、币种、成本完整度筛选，订单明细下钻及 CSV 导出。DataLab 最多 100 行的查询不适合作为全量利润核算输入；应使用有完整性/更新时间约束的数据接口或经核验的同步明细。

## 建议验收

1. 用固定样例订单验证收入、折扣、采购成本、运费、平台费和退款项的逐项计算；逐项展示原币、汇率及换算金额，汇总结果与定义公式一致。
2. 无成本、缺汇率、广告映射缺失的订单应明确标记不完整并从“已确认净利润”口径排除或按确定规则处理；不得显示为看似准确的零成本利润。
3. 同一数据版本重复计算结果可复现；成本或汇率规则变更后，新旧计算快照可区分和追溯。
4. 店铺权限、日期边界和币种筛选准确；导出结果与筛选后的页面明细及汇总一致。以上均为规划验收条件。
