## 0. 结论先行

**建议先做「阶段一：点亮观测」**，不要一上来做多供应商路由。

理由：系统已经把模型网关该产出的四个指标（`token_usage / cost / cache_hit / tenant`）
**预留并显式声明为 unavailable**（见 §1.3）。也就是说，网关的价值锚点已经写死在代码里了 ——
先把它点亮，02 面板才有真东西可看；而多供应商路由在当前只有一家模型的情况下，
做出来也只能演示配置、演示不了真实切换（还容易踩「演示数据必须标来源」的硬约定）。

## 1. 现状盘点

### 1.1 好消息：已经有天然收口点

所有 LLM 调用**都**走 `backend/app/supply_agent_llm.py` 的 `completion()` 一个函数：

| 调用方 | 位置 |
|---|---|
| `agent_generation.py`（利润/广告/客服生成） | `:18` |
| `assistant.py` | `:17` |
| `listing_agent.py` | `:14` |
| `operations_agent.py` | `:11` |
| `product_agent.py` | `:10` |
| `supply_agent_llm.py` 自身 | `:136` |

全仓 `/chat/completions` 字面量只出现一次（`supply_agent_llm.py:57`）。
**这意味着网关可以在这一个函数里插入，5 个调用方零改动** —— 这是本项目最有利的结构条件。

### 1.2 现有实现已经做对的事（不要重复造，要继承）

`supply_agent_llm.py` 里已有不少工程质量，网关必须继承：

- **地址校验** `:46` —— 必须 HTTPS，或本机 HTTP（`127.0.0.1/localhost`）。
- **统一错误码** `:45,60,67,69,71` ——
  `MODEL_NOT_CONFIGURED / MODEL_CONFIG_INVALID / MODEL_HTTP_ERROR / MODEL_TIMEOUT /
  MODEL_CONNECTION_ERROR / MODEL_RESPONSE_INVALID`。
- **错误脱敏** `:59` —— 注释明确写「不记录供应商原始错误，避免其回显 token/请求内容」。
  这条尤其重要：网关加重试/降级后，日志量会变多，**脱敏策略必须保持**。
- **thinking 开关按供应商分支** `:50-54` —— deepseek 用 `thinking:{type:'disabled'}`，
  其他用 `enable_thinking:false`。说明"供应商差异"已经实际存在，只是硬编码在 if 里。

## 2. 目标架构

新增 `backend/app/lim_model_gateway.py`，作为**唯一**的模型调用出口，对内承接
`supply_agent_llm.completion()`，对外被 LIM 控制台观测。

职责对应 PRD 那行的四项：

| PRD 能力 | 网关实现 |
|---|---|
| 模型网关 | Provider 注册表 + Model 别名表 + 按场景路由 + 降级 + 重试 + 熔断 |
| 缓存 | `request_hash` → 响应 TTL 缓存，命中标记 `cache_hit` |
| 观测 | 每次调用落 `lim_model_calls`，回写 `lim_spans` / `lim_runs` 的 token/cost |
| 评测 | 同一 eval 数据集换模型 A/B，接既有 `lim_eval_comparison` |

### 2.1 新增表（`0038_lim_model_gateway.py`）

**`lim_model_providers`** —— 供应商注册
`provider_id`, `name`, `protocol`（先只支持 `openai_compatible`）,
`base_url`, **`api_key_env`**（⚠️ 只存 env 变量名，不存明文）,
`enabled`, `priority`, `timeout_ms`, `status`, `created_at/updated_at`

**`lim_model_catalog`** —— 逻辑模型别名 → 实际供应商+模型
`alias_id`, `alias`（如 `default` / `ops`）, `provider_id`,
`model_name`, `scene`（agent 类型或 `*`）, `enabled`, `priority`

**`lim_model_calls`** —— 调用级观测（阶段一的核心产出）
`call_id`, `run_id`(可空), `span_id`(可空), `actor_id`,
`alias`, `provider_id`, `model`,
`status`（`SUCCEEDED`/`FAILED`/`CACHED`/`REJECTED`）, `error_code`,
`latency_ms`, `prompt_tokens`, `completion_tokens`, `total_tokens`,
`cost`, `cache_hit`, `request_hash`, `created_at`

索引参考 `0037` 写法：`(created_at)`、`(actor_id, created_at)`、
`(provider_id, created_at)`、`(run_id)`，缓存用 `request_hash` 唯一索引。

> 缓存表 `lim_model_cache` 放到阶段二，阶段一不建。

### 阶段二「路由与韧性」

多供应商注册 → 按 alias/scene 路由 → 主失败切备 → 重试（指数退避+jitter，仅 429/5xx/超时）
→ 熔断（连续失败暂停）→ `request_hash` TTL 缓存 → 供应商健康检查。

### 阶段三「预算与评测」

按 actor 的日/月 token 与金额配额，超限触发 **已预留的 `BUDGET_EXCEEDED`** 状态；
接入 `lim_alerts`；同一 eval 数据集换模型 A/B 对比，接 `lim_eval_comparison`；
维护单价表以把 token 折算成金额。

## 4. 关键设计决策与坑（动手前务必确认）

1. **保持 `completion()` 签名与错误码完全不变。**
   5 个调用方零改动，是本次改造风险最低的关键。网关新增能力全部在函数内部消化。

2. **继承错误脱敏。** `supply_agent_llm.py:59` 明确不记录供应商原始错误以防回显 token。
   网关加重试/降级后日志量翻倍，**只记 `error_code` + HTTP 状态码，绝不记 response body**。

3. **重试必须受总超时预算约束。** 现有调用方传的是 `min(40, remaining)`（`:136`），
   网关重试不能把 40s 变成 40s×3。要把"剩余预算"作为参数传进网关。

4. **API Key 不落库。** provider 表只存 env 变量名（如 `PURCHASE_AGENT_LLM_API_KEY`），
   运行时 `os.getenv` 读取。这直接呼应刚完成的 key 明文清理 ——
   该 key 曾在 git 历史 `1abf0bf8…` 泄露，**绝不能再引入第二个明文落点**。

5. **缓存键必须含身份维度。** `messages` 里本身带业务数据（用户选中的配置、业务日期），
   但仍要把 `actor_id`/scope 纳入 hash，防止越权命中他人缓存。

6. **token 取不到就诚实标 null。** OpenAI 兼容响应有 `usage`，但不同供应商字段名可能不同
   （deepseek 兼容层尤其要实测）。拿不到时写 null 并把状态标 `partial`，
   **不能填 0 假装准确** —— 这是本项目「演示数据必须标来源」的硬约定。

7. **只有一家供应商时，不伪造"路由/降级"演示。** 02 面板若展示多供应商能力，
   必须标明是"已配置能力"而非真实切换；不可 mock 第二家响应充数。
