# 统计：报表分析

## 当前可用的只读页面

“统计 → 经营统计” `/statistics` 已接入 [`StatisticsPage.tsx`](../../../frontend/src/pages/StatisticsPage.tsx)。页面调用 `GET /api/v1/datalab/table/dws_sales_store_day?limit=365`，展示本次返回的销售日汇总，支持在前端按店铺名称筛选。卡片对筛选后的行累加订单数、订单金额和退款金额，并以“订单金额减退款”显示净销售额；表格显示日期、店铺、平台、订单数、订单金额、已付金额和退款。

“365”是最多读取的**行数**，不是页面上的日期范围。前端没有服务端分页、日期筛选、导出、图表或同比环比。销售金额固定显示美元符号，实际币种与汇率口径必须核对 DataLab 数据源；不能直接当作跨币种总销售额。顶部数字只代表本次返回并通过店铺筛选的行。

## 权限与边界

菜单配置使用 `dashboard:read`，后端 DataLab 代理接口也要求该权限。`/statistics` 路由自身没有额外 `PermissionGuard`，但仍在登录保护下；无权限用户直接打开 URL 时会遭遇接口拒绝。上游查询没有接收 ERP 用户的店铺范围，需在 DataLab 侧补齐数据隔离。

- **已实现：** DataLab 销售日汇总只读表和店铺前端筛选。
- **部分实现：** 统计只基于最多 365 行；金额币种、数据时效及完整性未在页面说明。
- **尚未实现：** 服务端全量聚合、日期/站点筛选、明细钻取、导出、趋势图、利润与广告财务联合分析。

人工验收应拿一组已知 DataLab 行核对筛选和卡片求和，并检查行数上限、上游错误和无权限访问表现。本文编写时未执行该操作。
