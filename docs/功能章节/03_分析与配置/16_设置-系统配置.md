# 16：设置与系统配置

## 页面用途

“设置”分组提供店铺资料、账号与角色、操作日志三个入口，分别用于维护业务站点基础资料、分配系统访问权限，以及审计已记录的操作。系统配置目前不包含全局参数中心、通知、集成凭据或安全策略管理页面。

## 页面入口与操作

### 店铺资料 `/shops`

店铺页通过通用资源组件查看、搜索、分页、新建和编辑店铺编码、名称、渠道、国家站点、时区、结算币种及启用状态。编码不可编辑；币种选项来自启用的币种字典。店铺时区供业务日期等功能使用，但不代表现有所有报表都已按店铺时区计算。

### 账号与角色 `/users`

该页面仅管理员可进入。账号页可创建用户、设置角色、启停账号、分配店铺/仓库范围及重置密码；角色页可维护角色名称和权限列表。内置 `admin` 角色不能修改或删除（当前界面没有删除操作），也不能创建同编码角色。停用用户会撤销其会话；重置密码会撤销该用户现有会话。不能由当前管理员自行停用或降权自己。

### 操作日志 `/audit-logs`

有 `audit:read` 权限的用户可按资源筛选并分页查看时间、动作、记录 ID 与变更前后快照。页面还有刷新入口。日志接口可按操作者、资源、记录、时间范围筛选，但当前页面只暴露资源筛选；仅具有全店铺及全仓库范围的账号可读全局日志。

## 后端接口与权限

- 店铺：`GET/POST /api/v1/shops`、`GET /api/v1/shops/{id}`、`PATCH /api/v1/shops/{id}`，分别受 `shops:read`、`shops:write` 控制；数据范围账号只能看到其店铺范围，且不能创建店铺。
- 账号和角色：管理员专用 `GET /api/v1/users`、`POST /api/v1/users`、`PATCH /api/v1/users/{id}`、`PUT /api/v1/users/{id}/password`、`GET/POST /api/v1/roles`、`PUT /api/v1/roles/{id}`、`GET /api/v1/permissions`。服务端通过 `admin_user` 校验，不依赖前端隐藏按钮。
- 审计：`GET /api/v1/audit-logs`，读取要求 `audit:read`；提供 `actor_id`、`resource`、`record_id`、`date_from`、`date_to`、`page`、`page_size` 参数，单页上限 100。

具体登录令牌、路由守卫、权限和数据范围实现分别见 [`App.tsx`](../../../frontend/src/App.tsx)、[`main.py`](../../../backend/app/main.py) 和 [`security.py`](../../../backend/app/security.py)。

## 实现状态与缺口

### 已实现

- 店铺资料维护及币种引用校验。
- 管理员管理用户、角色、权限和店铺/仓库范围；后端强制管理员校验。
- 用户停用和密码重置时撤销会话；管理角色权限时记录审计事件。
- 审计日志分页、资源筛选和快照查看；后端支持更细筛选参数并限制非全局范围账号访问。

### 部分实现

- 设置分散在三个页面，没有统一系统参数中心；账号角色仅管理员使用。
- 店铺页面所需 `shops:read` 与编辑所需 `shops:write` 分属不同权限；创建店铺还要求全范围权限。
- 审计日志页面不提供操作者、记录 ID、日期筛选，也没有导出或详情页；日志是否覆盖某项操作取决于业务路由是否调用审计记录函数。
- 多数资源按范围限制列表，但不能假定所有模块都统一应用店铺/仓库范围；例如 DataLab 看板需单独核实上游隔离。

### 尚未实现

- 全局系统设置、密码策略/会话时长管理、通知和审批策略。
- API 凭据、平台连接、汇率与税务配置中心。
- 审计日志导出、保留周期管理、完整性告警和未留痕操作盘点。

## 人工验收

文档编写时未执行。用管理员账号创建测试角色并分配权限，再创建有店铺/仓库范围的测试用户，核对其菜单可见性、直接访问路由和后端接口结果。停用测试用户后确认已有令牌失效；执行密码重置后确认旧会话失效。使用非管理员尝试访问用户/角色接口应被拒绝。打开审计日志检查资源筛选、快照与分页；以受限范围账号访问全局日志应返回拒绝。最后核对店铺币种引用和停用行为。
