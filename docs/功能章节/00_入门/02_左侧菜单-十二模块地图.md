# 左侧菜单：当前模块地图

本文根据当前前端导航配置和路由实现整理，帮助读者从左侧菜单找到页面，并区分已经接入页面与暂时占位的入口。菜单名称代表本项目当前的导航结构；它不是参考网站“十二模块”的复刻，也不意味着每个模块都已完整实现业务流程。

## 菜单怎么使用

系统登录后进入 `/dashboard`。左侧分为两级：第一列是首页和业务分组，选择分组后，第二列显示该组页面；点击页面进入对应路由。页面打开后会出现在顶部标签栏，可以切换或关闭。面包屑和标签标题由导航配置生成。

首页是单独入口。其余分组来自 `frontend/src/config/menu.ts` 中的 `NAV`。分组节点以 `g-` 开头，只用于组织菜单，不对应页面路由；叶子节点的 `key` 对应 URL 路径，例如 `products` 对应 `/products`。访问根路径 `/` 会跳转到 `/dashboard`，未知路径也会回到 `/dashboard`。

## 登录与权限规则

所有业务路由都位于登录保护之下。应用尚未完成登录状态校验时显示“正在校验登录状态…”，没有登录令牌则跳转到 `/login`。登录页本身不要求先登录。

页面权限在 `App.tsx` 的 `PermissionGuard` 中检查：管理员可以通过权限门禁；其他用户需要拥有路由指定的权限码。权限不足时跳转回 `/dashboard`。`/users` 使用管理员专属检查。侧栏也会按当前用户过滤导航：有权限的页面才显示；管理员可以看到所有页面。因而直接输入受保护页面的 URL 也会受到路由权限检查。

首页不要求额外页面权限。广告、财务、统计和 BI 的菜单配置都使用 `dashboard:read`，但这些路由目前没有包裹 `PermissionGuard`；直接输入 URL 时只检查是否登录，数据接口仍由后端校验 `dashboard:read`。这是前端页面门禁仍需补齐的地方。其他业务页面使用 `menu.ts` 中声明的权限码，例如商品需要 `products:read`，库存余额需要 `inventory:read`。

## 实现位置

- `frontend/src/config/menu.ts`：导航分组、页面名称、路由 key、页面权限映射和部分接口映射。
- `frontend/src/App.tsx`：登录保护、页面路由、页面权限门禁，以及各路由对应的页面组件或占位组件。
- `frontend/src/layouts/MainLayout.tsx`：左右两级菜单、按权限过滤菜单、页面标签、面包屑和用户退出入口。

新增页面时，需要让菜单叶子 key 与 `App.tsx` 中的路由路径一致，并按需配置权限码和页面组件；若功能尚未实现，可以明确使用占位页，避免把入口误认为已交付功能。
