# 首页：业务总览

## 页面用途

首页路由为 `/dashboard`，用于登录后快速查看订单、库存、采购和补货的当前待办。它把业务模块已有的数据放在同一页，点击卡片或待办行可进入对应模块继续处理。该页面是浏览型入口，不在首页直接审核订单、审批采购单或调整库存。

前端实现见 [`DashboardPage.tsx`](../../../frontend/src/pages/DashboardPage.tsx)，路由入口见 [`App.tsx`](../../../frontend/src/App.tsx)。

## 页面内容与口径

| 区域 | 展示内容与计算方式 | 跳转入口 |
|---|---|---|
| 指标卡片 | 订单数、待审核订单、待出库订单、可用库存、低库存预警数、待补货 SKU 数。订单数、库存和补货统计都标明“当前页”；待出库卡片要求同时有订单读取和出库单读取权限。 | 订单、出库单、库存、补货建议 |
| 销售金额（按币种） | 对已取回的订单按 `currency_id` 分组累加 `grand_total`，用币种字典的 `code` 显示。多币种不换算、不合并为单一金额。 | 无单独的点击入口；可用“查看订单”进入订单模块 |
| 订单状态分布 | 对当前取回订单按状态计数，展示待审核、待发货、待出库、已完成、售后中、已取消的数量和比例。 | 卡片跳转订单模块 |
| 运营待办 | 待审核订单、待发货订单、待确认出库单、待审批采购单和待处理补货建议；各行点击进入对应处理页面。 | 订单、出库单、采购审批、补货建议 |
| 库存预警 | 取当前库存结果按可用量升序排列，显示前 8 条；阈值固定为每个“SKU-仓库”库存余额可用量不高于 120 件。表格显示 SKU、仓库、在手、占用、可用数量。 | 卡片跳转库存模块 |
| 最近订单 | 显示当前订单结果中的前 8 笔，包含来源订单号、客户、金额和原币种、状态、下单时间。订单接口按创建时间倒序返回。 | 通过“查看全部”链接跳转销售订单 |

**统计范围限制：**首页各列表请求 `page=1&page_size=100`，前端只在本次响应的 `items` 上汇总。因此这里不是全量经营报表；超过 100 条时，订单金额、状态、订单数、库存汇总、低库存数和补货建议数都只反映这一页。SKU 名称、仓库名称和币种代码映射也各自最多读取 100 条。完整数据请到相应模块查询。相关取数逻辑见 [`DashboardPage.tsx`](../../../frontend/src/pages/DashboardPage.tsx) 和 [`lookups.ts`](../../../frontend/src/api/lookups.ts)。

低库存阈值是前端常量 `120`，不是商品级补货点，也不是后端告警规则。库存按 SKU 与仓库余额记录求和；若同一 SKU 位于多个仓库，会分别作为库存行计数。销售金额按原始币种分别汇总，当前页未实现汇率折算。

## 数据来源

首页没有专用聚合 API。页面按用户权限并行读取下列接口，接口请求经统一客户端加上登录令牌（见 [`client.ts`](../../../frontend/src/api/client.ts)）：

| 数据 | 接口 | 首页用途 |
|---|---|---|
| 销售订单 | `GET /api/v1/orders?page=1&page_size=100` | 订单状态、金额、待办、最近订单 |
| 库存余额 | `GET /api/v1/inventory?page=1&page_size=100` | 可用量总和、低库存计数及库存预警表 |
| 采购单 | `GET /api/v1/purchase-orders?page=1&page_size=100` | `submitted` 状态采购单作为待审批数 |
| 补货建议 | `GET /api/v1/replenishment-suggestions?page=1&page_size=100` | `pending` 且建议数量大于 0 的记录作为待处理数 |
| SKU、仓库名称 | `GET /api/v1/skus`、`GET /api/v1/warehouses`（各取第一页 100 条） | 将库存记录中的外键 ID 转成名称 |
| 币种字典 | `GET /api/v1/dictionaries?page=1&page_size=100&kind=currency` | 将订单币种 ID 转为币种代码 |

后端相关路由和读取权限定义分别见 [`orders.py`](../../../backend/app/orders.py)、[`wms.py`](../../../backend/app/wms.py)、[`scm.py`](../../../backend/app/scm.py) 和 [`resources.py`](../../../backend/app/resources.py)。订单接口会按用户店铺范围过滤；库存接口会按用户仓库范围过滤。采购单及补货建议列表的代码当前按状态等筛选条件查询，没有在列表函数内应用店铺或仓库可见范围过滤。

接口返回部分失败时，首页会显示“部分首页数据暂时无法加载”的提示，并以空列表显示失败接口对应的数据；基础资料名称映射加载函数会吞掉异常并返回空映射，所以名称可能退回显示短 ID 或 `—`。页面打开后加载一次；离开后重新进入会再次加载。当前页面没有日期范围筛选、统一刷新按钮、自动刷新或数据更新时间标记。

## 操作入口

- 左侧导航选择“首页”，或直接访问 `/dashboard`。
- 页面顶部快捷入口依据权限显示：查看订单、查看库存、采购管理、审批工作台、采购下单、商品资料、采购收货、其他入库。
- 指标卡片和待办行可点击进入对应业务页面；库存表和最近订单提供各自模块入口。
- 主界面顶部的首页图标可返回首页。菜单分组、叶子菜单与面包屑由 [`menu.ts`](../../../frontend/src/config/menu.ts) 和 [`MainLayout.tsx`](../../../frontend/src/layouts/MainLayout.tsx) 管理。

## 权限说明

首页本身只要求已登录，`/dashboard` 路由没有额外的 `dashboard:read` 权限门槛。每块数据按各自读取权限单独加载：

- `orders:read`：订单卡片、销售金额、状态分布、订单相关待办和最近订单。
- `inventory:read`：库存卡片和库存预警。
- `purchase_orders:read`：采购管理、审批工作台、采购收货入口及采购审批待办。
- `purchase_orders:write`：采购下单入口。
- `inbound_orders:read`：其他入库入口。
- `products:read`：商品资料入口。
- 待出库指标需同时具有 `orders:read` 与 `shipments:read`；待确认出库单待办同样要求这两项权限。
- `replenishment:read`：待补货卡片和补货待办。
- `skus:read`、`warehouses:read`、`dictionaries:read`：分别加载名称映射；缺少权限时会显示回退名称，不影响其他已授权数据。

前端的权限过滤在 [`DashboardPage.tsx`](../../../frontend/src/pages/DashboardPage.tsx) 实现；后端接口还会通过 `require(...)` 再次验证权限，例如 [`orders.py`](../../../backend/app/orders.py) 中的 `orders:read` 和 [`wms.py`](../../../backend/app/wms.py) 中的 `inventory:read`。导航权限配置见 [`menu.ts`](../../../frontend/src/config/menu.ts)。管理员在前端按全部权限处理；其他角色按用户权限清单控制显示。

## 当前实现边界

### 已实现

- 登录后首页汇总订单、库存、采购单和补货建议接口数据。
- 按币种分别累加订单金额，展示订单状态分布、待办、库存预警和最近订单。
- 根据权限隐藏无权读取的数据块和操作入口；接口错误会提示部分数据加载失败。
- 点击卡片及待办进入相关业务模块。

### 部分实现

- 首页统计只使用接口第一页最多 100 条，数据量大时不能代表完整业务总量。
- 低库存阈值固定为 120 件，不能按 SKU、仓库或店铺配置；同一 SKU 多仓记录分别计数。
- 最近订单取返回结果前 8 条；金额按原币种统计，没有汇率换算。
- 加载错误时部分数据以空状态呈现；名称字典失败可能显示 ID，页面没有逐块标记数据是否完整。

### 尚未实现

- 首页筛选日期、店铺、站点或仓库，以及全量分页聚合。
- 统一刷新按钮、自动刷新和数据更新时间。
- 毛利、广告、结算、退款等经营指标及其数据校验口径。
- 可配置的低库存阈值、跨币种汇率折算和自定义首页卡片。

广告、结算、经营统计等路由当前由占位页面承载，不能视为首页已接入的真实经营数据，路由可核对 [`App.tsx`](../../../frontend/src/App.tsx)。

## 验收步骤

以下为人工验收步骤，文档编写时未执行：

1. 使用已配置的管理员账号登录，进入左侧“首页”，确认页面显示“业务总览”。
2. 在订单模块准备至少一笔不同状态订单，在库存模块准备可用量分别大于和不高于 120 的 SKU-仓库记录，并确保存在采购单和待处理补货建议。
3. 返回首页，检查订单数和状态分布、原币金额、待审批采购单、待补货数、库存合计及阈值提示；确认最近订单最多 8 条、预警最多 8 行。
4. 点击订单、库存、审批、补货相关卡片或待办，确认进入对应路径；检查顶部快捷入口按当前账号权限出现。
5. 使用只读角色或权限不完整的账号登录，确认无权数据块不显示，已授权模块仍可使用；直接请求无权限接口应由后端拒绝。
6. 准备超过 100 条的接口记录时，确认首页显示的是第一页汇总，并与模块全量结果对照，避免把首页数值误认为全量报表。
