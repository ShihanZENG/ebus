# FBA：补货与发货计划

## 当前可用入口

“FBA → 发货流程 → FBA 发货计划”对应 `/fba-plans`。本地计划从 `draft` 经 `submitted`、`approved`、`shipped` 到 `received`，发货前可取消。页面见 [`FbaPage.tsx`](../../../frontend/src/pages/FbaPage.tsx)，规则与库存记账见 [`fba.py`](../../../backend/app/fba.py)。同组的货件、发货单、海外发货计划、FBA 总览、库存、对账和标签打印目前是占位入口。

| 动作 | 本地数据影响 | 接口 |
|---|---|---|
| 新建或编辑草稿 | 记录店铺、国内来源仓、海外目的仓、SKU 与数量 | `POST/PATCH /api/v1/fba-plans` |
| 提交与审批 | 更新计划状态和操作记录 | `POST /api/v1/fba-plans/{id}/submit`、`approve` |
| 标记发货 | 校验来源仓可用量，扣减国内仓在库数量，写出库流水和追踪号 | `POST /api/v1/fba-plans/{id}/ship` |
| 确认收货 | 一次按全部计划数量增加海外目的仓库存，写入库流水 | `POST /api/v1/fba-plans/{id}/receive` |

当前“海外仓”是本系统中的仓库档案和库存余额；`received` **不等于 Amazon 平台已签收或入账**。重复发货、重复收货和库存不足会被拒绝。计划列表、详情和操作还会检查店铺范围以及来源、目的仓范围。

## 与补货建议的关系

现有 `/replenishment` 是采购补货建议，不能自动生成 FBA 发货计划。建立 FBA 计划前，运营人员仍需人工判断目的仓需求、在途量和来源仓可用量。

## 操作示例和权限

选择有货的国内仓、启用的海外仓和一个 SKU，新建数量为 5 的草稿；提交并审批后填写追踪号发货，核对国内仓减少 5；确认收货后核对海外仓增加 5 和两条库存流水。查询需要 `fba_plans:read`，创建与状态操作需要 `fba_plans:write`；这些步骤是人工验收建议，本文编写时未执行。

## 当前边界

- **已实现：** 本地 FBA 计划状态、审批、追踪号、跨仓全量库存流转和审计。
- **部分实现：** 只支持一次全量签收，没有箱数、短少、损坏和部分收货模型。
- **尚未实现：** Amazon 货件 API、FBA 平台库存同步、箱贴/FNSKU 标签、承运商轨迹、运费、FBA 对账及自动生成计划。
