# 销售：订单从哪来

## 页面用途与入口

销售订单页 `/orders` 展示和维护本地 OMS 订单。当前订单来源可以是人工录入，也可通过后端批量导入接口写入；代码没有店铺平台订单拉取任务或平台连接器，因此“来源渠道”字段只是来源标记，不代表订单已从电商平台同步。

从左侧“销售 > 销售订单”进入。页面首次加载最多取 50 条订单，不提供列表筛选或分页；点击行查看详情。新建、审核、申请发货、取消等操作由页面按状态显示。见 [`Orders.tsx`](../../../frontend/src/pages/Orders.tsx)、[`orders.py`](../../../backend/app/orders.py)。

## 订单字段和金额

订单头包含店铺 `shop_id`、`source_channel`、`source_order_no`、币种 `currency_id`、状态、客户信息、可选履约仓、备注和总金额。唯一性按“店铺 + 来源渠道 + 来源单号”约束。同一号码在不同店铺或不同来源标记下可分别存在。

明细包含内部 `sku_id`、SKU 编码/名称快照、数量、单价、行优惠和行金额。后端从 SKU 主数据取快照，避免日后改名导致历史订单显示错位。页面展示应付金额和币种；没有汇率换算。付款记录有单独权限，页面详情只有接口返回付款信息时才显示。

## 来源与处理流程

**人工创建：** 新建订单选择启用店铺；店铺选择会带出其币种。录入来源渠道（默认 `manual`）、来源单号、客户信息、至少一条 SKU 明细（数量、单价、行优惠），可选预选仓。提交后状态为 `draft`（待审核）。创建依赖 `orders:write`、`shops:read`、`dictionaries:read`、`skus:read`；选项各自最多加载 100 条。

**批量导入：** 后端提供 `POST /api/v1/orders/import`，接受批次币种及多个来源订单/明细，校验来源键重复并为订单生成草稿。当前订单页面没有导入按钮或文件上传流程；必须通过受控 API 客户端调用，不能描述成 UI 已支持导入。

**履约：** 有写权限者对草稿审核并选择履约仓，状态进入 `approved`；之后“申请发货”生成 WMS 出库处理并进入 `shipping_requested`。仓库确认出库后订单成为 `fulfilled`。未发货订单可取消，申请发货后取消还涉及释放占用。允许对符合条件订单发起售后，状态会变为 `after_sale`。状态与转换校验在后端，不应仅凭页面按钮判断。

| 状态 | 页面文案/含义 | 主要后续动作 |
|---|---|---|
| `draft` | 待审核 | 审核、取消 |
| `approved` | 已审核 | 申请发货、取消、符合条件时售后 |
| `shipping_requested` | 待出库 | 仓库完成出库或取消 |
| `fulfilled` | 已发货/履约完成 | 可按业务条件发起售后 |
| `after_sale` | 售后中 | 在售后模块处理 |
| `cancelled` | 已取消 | 终态 |

## 数据与权限

主要接口为 `GET/POST /api/v1/orders`、`GET /api/v1/orders/{id}`、`POST /api/v1/orders/import`、`POST /{id}/approve`、`POST /{id}/shipment-request`、`POST /{id}/cancel`。读取需要 `orders:read`，录入/审核/发货申请/取消需要 `orders:write`；审核还要求仓库读取权限以选择履约仓。后端会按 `shop_scope` 限制订单读取和操作。付款记录另需 `payment_records:read/write`；售后需要 `after_sales:read/write`。

订单数据来自本地数据库 `sales_orders`、`sales_order_items` 等表。店铺、币种和 SKU 下拉来自基础资料接口；发货单与库存变化通过 OMS 调用 WMS 形成。路由和模型见 [`orders.py`](../../../backend/app/orders.py)、[`models.py`](../../../backend/app/models.py)、[`wms.py`](../../../backend/app/wms.py)。

## 当前实现边界

**已实现：** 手工创建、详情查看、批量导入 API、审核分配履约仓、申请出库、取消、金额与明细快照、后端店铺范围检查。

**部分实现：** 订单页只显示接口第一页 50 条，不能筛选/翻页；创建选项最多取 100 条；状态流转需结合 WMS 出库确认。批量导入有 API 但无页面入口，源数据必须由调用方提供。

**尚未实现：** 平台订单自动拉取、定时同步、平台状态回写、自动汇率折算，以及当前订单页的文件导入、过滤与完整分页管理。

## 人工验收

1. 准备启用店铺、币种、SKU 和有库存的履约仓，使用有订单读写和基础资料读取权限的账号创建一笔手工订单。
2. 检查新订单状态为待审核，明细显示 SKU 快照、数量、行金额和币种；重复来源键应失败。
3. 审核时选择履约仓；确认订单成为已审核，再申请发货并到出库单页面确认出库，返回订单检查成为已发货。
4. 对未履约订单取消并核对原因；验证已完成订单不出现可用取消操作。
5. 使用无订单权限或店铺范围受限账号检查菜单、列表和直接 API；确认导入端点需通过 API 调用，界面没有导入入口。
