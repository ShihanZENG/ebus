# 财务：对账结算

## DataLab 财务快照

“财务 → 结算管理” `/finance-settlements` 从 `GET /api/v1/datalab/table/dws_finance_day?limit=365` 读取最多 365 行 DataLab 财务日汇总，展示日期、类型、状态、币种、笔数和金额，并分别累加返回行中的 CNY 与 USD 金额。行数可能不完整；这部分仍是只读快照，不代表本地逐笔对账或平台实时同步。

后端销售订单另有付款记录接口和 `PaymentRecord` 模型，采购单保存采购金额，见 [`orders.py`](../../../backend/app/orders.py)、[`models.py`](../../../backend/app/models.py)。这些记录与 DataLab 日汇总尚未构成逐笔可追溯的对账链。页面里的“总额”只是本次取回行的代数和，不能称为净利润或账户余额；不同币种分别显示，不做汇率换算。

## 本地平台费用复算

同一页面的“本地平台费用复算”表单把一条账单费用、费率来源与结算调整提交至 `POST /api/v1/profit-reconciliations/fee-discrepancies`。后端按币种计算应收费用、已入账调整、净实扣和差异；币种、凭据来源及费用行逐条保留，不合并不同币种。每条记录同时保存已提交的证据快照及摘要，方便回看账单行、计费基数、费率、生效期和调整项。缺少账单行、交易日期、适用费率、实扣金额或调整项核对时，状态为“待补证”，`confirmed_overcharge` 保持 `false`。复算发现多扣时记录仍须人工审核。

历史由 `GET /api/v1/profit-reconciliations/fee-discrepancies` 分页读取，并可按授权店铺、币种和凭据来源筛选。接口遵守 `finance_agent:read` 和 `shop_scope`；写入需 `finance_agent:write`。表单录入的来源编号和证据字段是用户提供的引用，不等于已上传或由系统验证过的账单文件；当前未接入平台结算单自动导入或银行流水匹配。

## 权限与边界

菜单使用 `dashboard:read`，DataLab 代理接口也要求此权限。前端路由当前只检查登录，直接访问 URL 时没有额外 `PermissionGuard`；接口会在后端拒绝无权限请求。ERP 店铺/仓库数据范围未传给 DataLab 查询。

- **已实现：** DataLab 日汇总只读页面、按币种汇总本次返回行、订单付款记录；本地单笔平台费用复算、按权限分页查询历史、按币种和来源筛选及缺证据门禁。
- **部分实现：** DataLab 仅取最多 365 行；费用复算依赖人工录入的来源引用、账单和费率字段，完整多扣结果还须人工审核。
- **尚未实现：** 平台结算单自动导入、银行流水匹配、应收应付、费用分摊、完整利润核算、发票及统一对账审批。

人工验收应验证不同币种不合并、来源筛选与店铺权限、缺证据不确认多扣、调整冲回单独扣减，以及多扣结果继续等待人工审核。DataLab 快照和人工录入的复算记录均不代表平台或银行已完成对账。
