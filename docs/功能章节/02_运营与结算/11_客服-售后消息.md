# 客服：售后消息

## 当前可用入口

“客服 → 客服工单” `/customer-tickets` 管理内部问题处理；“客服 → 售后” `/after-sales` 管理订单退货或退款记录。工单代码见 [`customer_tickets.py`](../../../backend/app/customer_tickets.py)，售后代码见 [`orders.py`](../../../backend/app/orders.py)。这两个页面没有向 Amazon、Shopify 等平台发送消息的能力。

## 客服工单

工单可填写所属店铺、关联订单、主题、问题描述和 `low/normal/high/urgent` 优先级。状态依次可以是 `open → in_progress → resolved → closed`，已解决工单可重开；工单可分派处理人并追加内部处理记录，每次动作留事件历史和审计。列表、详情、创建和动作入口为 `/api/v1/customer-tickets`。账号须有 `customer_tickets:read/write`，且只能访问其店铺范围内的工单；被分派人也须能访问该店铺。

## 订单售后

售后与销售订单关联，当前类型为退货或退款，处理结果按现有后端状态流转。接口包括 `POST/GET /api/v1/orders/{id}/after-sales` 和处理接口 `/api/v1/after-sales/{id}/resolve`。需要 `after_sales:read/write`，并继承订单的店铺可见范围。工单与售后记录目前是两类独立数据，不会自动互相创建。

**已实现：** 内部工单创建、分派、记录、状态流转；订单售后登记与处理。**部分实现：** 工单可以关联订单，但没有客户主档、SLA 计时或统一客户会话。**尚未实现：** 平台站内信收发、AI 自动回复、物流实时查询、退款网关回传和完整退货入库闭环。

人工验收可建立一张关联订单的工单，分派、添加处理记录、解决并关闭，再确认事件时间线完整；关闭后尝试追加记录应被拒绝。本文编写时未执行该操作。
