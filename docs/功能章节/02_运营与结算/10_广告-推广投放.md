# 广告：推广投放

## 广告日报导入与查看

“广告 → 广告管理” `/ad-campaigns` 现在以人工上传的逐日活动报表为主要工作区。页面通过 `POST /api/v1/ads-reports/preview` 在服务端校验 CSV，再由 `POST /api/v1/ads-reports/import` 原子写入；任意行有错误时整批拒绝。单次最多 5,000 行，文件上限 5 MB。按店铺、日期、活动 ID、币种建立唯一记录；同一 CSV 重复提交幂等，不同内容再次导入会更新同一活动日记录并记录更正审计。批次历史保留来源名、导入人、日期范围、币种和新增/更正数量。

日报可按店铺和日期筛选，花费、归因销售额、ACOS、ROAS 只按单行币种展示，不跨币种相加。用户可按店铺、币种设置“高花费无成交”阈值；只有花费达到阈值且归因订单和销售额均为 0 才提示，阈值可以停用。目标 ACOS 按店铺、活动设置；有归因销售额时才计算并比较，零销售额不计算 ACOS。配置变更会写入审计记录。店铺选择器优先复用 `shops:read`；仅有广告报表读取权限时，也可读取当前店铺范围内的广告店铺选项，不会超出 `shop_scope`。

活动有精确匹配的 ERP `sku_code` 时，页面可显示当前账号可访问仓库中的**本地可用库存**：在库减预留，并按库存归属排除其他店铺专属库存；沿用仓储模块“可用量 ≤ 120 件”的低库存筛查线。此数字不是 Amazon FBA 库存，也不能证明活动只投放该 SKU。SKU 为空、未精确匹配或已停用时，不显示库存诊断；没有 `inventory:read` 权限时不返回库存数量或低库存标签。

日报行可记录人工处理状态（待处理、已检查、继续观察、已调整）和 1,000 字以内备注。处理记录按店铺、日期、活动、币种保存，并写入审计记录；它描述内部检查结果，不会修改广告平台或投放状态。

CSV 格式和字段规则见[导入格式约定](#人工广告报表导入格式第一版约定)及[下载模板](../模板/广告活动日报导入模板.csv)。写入接口需要 `ads_reports:write`，已导入日报和批次读取沿用 `dashboard:read`，店铺范围在后端强制执行。

## DataLab 只读快照

“DataLab 快照”页签调用 `GET /api/v1/datalab/table/dws_ads_campaign?limit=100`，从外部 DataLab 读取最多 100 行。源表只有活动、SKU、平台、店铺、状态、花费和销售额，没有日期、币种或全量记录数；页面明确显示币种未知，不把快照混入人工导入的逐日报表。

这是一张**数据观察页**：页面没有创建活动、改预算、暂停投放或回写广告平台的操作。本次返回数不代表全部活动；由于没有报表日期、币种、完整总数或分页游标，当前不能可靠提供日期筛选、跨币种汇总或整体 ROAS。显示的读取时间是本机成功取数时间，不是 DataLab 的数据更新时间。

## 权限与数据范围

页面路由及日报查询使用 `dashboard:read`，日报写入需 `ads_reports:write`；导入时用户选择已授权 ERP 店铺，后端检查 `shop_scope`。由于上游 `store_name` 尚未映射到 ERP 店铺范围，带有限定店铺范围的账号仍不能读取 DataLab 快照，避免跨店铺数据泄漏。详见 [`menu.ts`](../../../frontend/src/config/menu.ts)、[`App.tsx`](../../../frontend/src/App.tsx)、[`ads_reports.py`](../../../backend/app/ads_reports.py) 与 [`datalab.py`](../../../backend/app/datalab.py)。

## 人工广告报表导入格式（第一版约定）

由于 DataLab 当前广告表没有报表日期、币种和诊断所需的流量指标，第一版以人工上传广告平台导出的**逐日活动报表**为准。CSV 模板见 [`广告活动日报导入模板.csv`](../模板/广告活动日报导入模板.csv)。一行代表一个店铺在一个自然日内的一条广告活动记录；导入页面选择 ERP 店铺，店铺市场和时区从店铺资料读取，不把自由文本店铺名当成权限依据。

| 列名 | 必填 | 说明 |
|---|---|---|
| `report_date` | 是 | `YYYY-MM-DD`，按所选店铺时区的自然日汇总；不能把周报/月报总数写成某一天 |
| `campaign_id` | 是 | 平台活动稳定 ID，用于重复检查和后续更新 |
| `campaign_name` | 是 | 报表中的活动名称，仅用于展示 |
| `campaign_status` | 是 | 原样记录报表状态，不据此自动暂停或修改活动 |
| `currency` | 是 | ISO 4217 代码，如 `USD`、`CAD`；逐行提供，不从店铺结算币种推断 |
| `spend` | 是 | 非负广告花费，使用英文小数点，最多 2 位小数 |
| `impressions` | 是 | 非负整数；没有该列的数据不能用于曝光/点击诊断 |
| `clicks` | 是 | 非负整数，且不得大于曝光量 |
| `orders` | 是 | 非负整数；使用该广告报表自身的归因订单口径 |
| `attributed_sales` | 是 | 非负归因销售额，币种与本行 `currency` 相同 |
| `sku_code` | 否 | 可确定归属单一 SKU 时填写 ERP SKU 编码；活动覆盖多个 SKU 或无法确认时留空，不猜测归属 |

文件使用 UTF-8（可带 BOM）、逗号分隔和英文列名。金额按十进制解析，不接受千位分隔符、货币符号、负数或科学计数法。店铺 ID、导入人、文件名和导入时间由页面/API 元数据记录，不要求用户在 CSV 里重复填写。每次导入需预览行数、日期范围、币种分布和错误行；存在格式错误时整批不写入。首版只保存与分析报表，不触发广告平台写操作。

示例数据行：`2026-10-17,CAMPAIGN-001,US Brand Exact,ENABLED,USD,12.50,1200,31,2,49.98,SKU-001`。此行为格式示例，不代表真实广告表现。

重复导入以“店铺 + 报表日期 + 活动 ID + 币种”识别同一活动日记录；文件内部重复键拒绝导入。已有记录再次导入时应作为同一日数据更正并保留导入批次审计，不得累加花费或销售额。原始来源文件摘要与批次信息应可追溯。`sku_code` 未提供或无法映射时，活动级高花费无成交、ACOS 对比仍可分析；“低库存仍投放”只针对已映射 SKU 的记录生成提示。

目标 ACOS 不采用全局硬编码值，由用户按店铺/活动设定阈值；高花费阈值按店铺/币种设置，避免跨币种比较。缺少可靠的每日完整报表或币种时，不展示跨币种汇总。CSV 只有活动级记录时，低库存提示属于筛查信号，不代表活动仅投放该 SKU。

DataLab 密钥改由 `backend/.env` 的 `DATALAB_API_KEY` 提供，示例配置见 [`backend/.env.example`](../../../backend/.env.example)。更换为轮换后的密钥前，DataLab 读取接口会返回“未配置”；旧密钥应在 DataLab 服务端撤销，不能继续用于本地配置。

人工验收应确认模板行可预览，任意错误行阻止整批导入，重复文件不会重复写入，修改同一活动日会覆盖并计为更正，店铺越权写入被拒绝，ACOS/ROAS 的零分母显示“—”。DataLab 快照应继续标记 100 行上限和币种/日期缺失。
