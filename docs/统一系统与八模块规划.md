# 统一系统与八模块规划

## 已确认方向

以主系统 frontend/ + backend/ 为持续开发入口，共用账号、权限、基础资料和审计。业务划分为八个模块：商品中心、客户与客服、订单中心、采购与供应链、库存与仓储物流、售后管理、财务与经营分析、AI工作台。

| 模块 | 业务归属 | 后续重点 |
|---|---|---|
| 商品中心 | 商品、SKU、多语言资料、Listing映射 | 统一资料及渠道映射 |
| 客户与客服 | 客户档案、沟通、工单 | 轻量CRM与订单关联 |
| 订单中心 | 导入、审核、履约、取消 | 异常处理及渠道接入 |
| 采购与供应链 | 供应商、报价、采购、补货 | 建议到收货的业务衔接 |
| 库存与仓储物流 | 库存、预留、收发、FBA | 调拨、物流和库存异常 |
| 售后管理 | 申请、退款凭据、退货验收 | 单据关联及进度 |
| 财务与经营分析 | 收付款、费用、对账、报表 | 对接平台结算单和银行流水 |
| AI工作台 | 业务查询、解释、建议、执行记录 | 统一来源、单据跳转与轨迹 |

公共能力：登录、权限、审批、审计、主数据、系统集成。SAP作为将来企业客户要求的外部集成目标。独立oms/保留现状，待核对专有功能和数据后确定收拢方案，不能直接当作与主系统同步。

5. 统一AI回答、证据、单据入口与运行记录。

本文件表达模块归属与开发方向，不代表所有模块已实现，也不表示已迁移独立OMS数据。

## 本批：全量运营统计

实现：GET /inventory/summary（数量、低库存仓库SKU组合数、全局最低8条）；GET /purchase-orders/summary（状态数）；GET /replenishment-suggestions/summary（待处理建议数及去重SKU数）。各自复用业务读取权限，按warehouse_scope限制，空范围返回0。首页采用这些结果，低库存阈值120，与原页面口径一致。库存数量表示仓库余额，不是指定店铺的可分配库存。

验证：超过100条记录、不同仓库范围、无权限、空范围、全局低库存排序及前端构建。

## 分币种财务对账首版（2026-10-16）

- 新增 `GET /api/v1/profit-reconciliations/summary`，按登录账号的店铺授权范围分币种汇总未取消订单额、本地登记收款、已登记退款、净登记现金、未收订单额和平台费用核验记录。
- 平台费用记录同时给出实扣金额记录数、总核验记录数和待审核记录数；无实扣金额的未完整凭据不会按0金额伪装成费用数据。
- 首页新增“分币种收款与费用对账”表。需同时有财务、订单、付款记录和售后读取权限；空店铺范围返回空结果。
- 金额均以原币汇总，不做汇兑。净登记现金=本地登记收款-已登记退款；未收订单额逐订单以应付减登记收款计算，最低记0。平台费用单独列出，不从净登记现金再次扣减。
- 这些数字来自本地录入和费用核验凭据，不代表银行到账、平台结算实收或正式会计账。平台费用实扣金额只合计已填写金额的核验记录，审核状态另行列示。
- 定向验证：`tests/test_finance_currency_summary.py tests/test_profit_reconciliation.py tests/test_finance_agent_permissions.py tests/test_order_summary.py tests/test_after_sales_execution.py` 共13项通过（68.06秒）；前端生产构建通过，仍提示主JS包超过500KB。
- 下一步建议：在真实/演示数据上走通客户建档→订单→客服工单关联；再依据你实际使用感受决定是否增加客户沟通记录。

## 轻量客户档案首版（2026-10-16）

- 新增店铺级客户档案（名称、联系方式、备注、启停状态），按用户 `shop_scope` 隔离；客户档案使用 `customers:read/write` 权限。
- 订单、客服工单新增可空 `customer_id`；支持新建时填写，也支持在客户档案中显式关联同店铺的已有订单与工单。
- 读取关联订单/工单仍分别校验 `orders:read` 和 `customer_tickets:read`；关联写入额外要求相应模块的 `:write` 权限。
- 关联不覆盖订单内既有客户名称/联系方式快照，不按姓名或联系方式自动合并；不提供硬删除，停用保留历史。
- 当前未扩展联系人层级、跨店客户主档、营销同意/退订、消息触达及自动去重；关联候选页面首版取同店铺最近 100 条未关联记录。
- 验证：CRM 专项测试 3 项通过；订单、订单编辑及客服工单回归合计 30 项通过（CRM 权限用例修正测试账号店铺范围后，专项重跑通过）；前端生产构建通过。当前主 JS bundle 仍超过 500KB 的既有拆包提示。
- 页面补充：无客户档案时直接展示店铺授权范围内未关联订单/工单和数量，可逐条核对后创建档案并关联；不会批量导入或自动按姓名匹配。订单金额显示币种代码。后续专项测试覆盖 5 项（未关联列表、订单/工单建档关联、跨店/权限和快照保留），前端构建通过。

## AI 客服内部处理记录草稿（2026-10-16）

- AI 总助手新增客服处理记录草稿：需同时具备 `assistant:read` 与 `customer_tickets:read` 才可生成；模型仅接收工单号、状态、优先级和用户填写的处理事实，不发送工单描述、联系方式等客户字段。
- 生成本身不修改工单。草稿可编辑；只有具备 `customer_tickets:write` 的用户点击“确认写入内部处理记录”后，才通过现有工单记录接口新增内部事件并审计。
- 不向客户发送消息、不自动变更工单状态；关闭工单仍由现有接口拒绝新增记录。普通 AI 问答保持只读。
- 这不是“解除试用版”或完整客服自动化：知识仍为本地关键词检索，生成质量需人工审核，模型服务仍按后台配置处理必要摘要。

## 采购与补货读取权限对齐（2026-10-16）

- 列表的分页记录与total均按warehouse_scope过滤；请求指定未授权仓库时返回空列表，不能通过筛选参数绕过授权。

## 采购与补货写入权限对齐（2026-10-16）

- 采购单创建按目标仓库检查范围；编辑、提交、审批、驳回、取消、关闭及收货按采购单所属仓库检查。
