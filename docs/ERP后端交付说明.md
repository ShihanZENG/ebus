# ERP + OMS + WMS + SCM 后端交付

日期：2026-10-08。范围为第一至第四批后端子阶段，前端业务页面尚未实施。

## 已实现

### 第一批：ERP 基础资料与权限
- FastAPI 服务、版本化 Alembic 迁移与 PostgreSQL 数据持久化。
- 登录、退出、会话过期、密码重置、失败登录临时锁定。
- 管理员、普通角色、功能权限及店铺/仓库范围控制。
- 商品、SKU、店铺、仓库、供应商、单位及币种管理。
- 分页、搜索、启停用、重复编码及外键引用校验。
- 操作日志查询、合成演示数据初始化及生成的 OpenAPI 契约。

### 第二批：OMS 销售订单
- 手工建单、批量导入（来源单号去重、错误行定位）、审核、发货申请、取消。
- 付款记录（标明方式与来源）、售后（退货/退款分别记录）。
- 订单按 shop_scope 行级过滤。

### 第三批：WMS 仓储与履约
- 手工入库、库存余额查询（在库/预留/可售）、库存流水。
- 订单申请发货时行锁预留库存，不足则整单回滚。
- 出库确认扣减在库和预留，订单自动变为 fulfilled。
- 取消已预留订单自动释放库存；盘点调整留痕。

### 第四批：SCM 采购与补货
- 供应商-SKU 供货信息（供货价、交期、启停用）。
- 采购单创建、提交、审核、驳回、取消；采购单号唯一（PO-YYYYMMDD-XXXX）。
- 分批收货：合格数量经 WMS 入库增加在库；不合格数量单独记录不计入可售。
- 重复收货单号被唯一约束拦截（409），不重复收货；超量收货受明细已收数量约束。
- 采购单状态：draft → submitted → approved → closed（全部收齐自动关闭）；亦可 rejected / cancelled。部分收货时保持 approved。
- 补货建议公式：reorder_point = round(日均销量 × 交期) + 安全库存；建议量 = max(0, reorder_point − 有效库存 − 有效在途)。公式输入与中间值写入 formula_inputs 可追溯。
- 人工调整建议数量并保留理由；建议转采购草稿单时引用供货信息单价，重复转单被拦截（已转状态）。

## 2026-10-08 补充修复

- **采购超量收货未拦截（真实缺陷）**：收货接口只累加合格数、从未与订购量比较，且校验与写库存混在同一循环，导致"先入库再关单"。已拆为先校验后写入：`po_item_received_totals()` 汇总历次回执，单条明细累计（合格+不合格）超过订购量即 422，并报出 SKU、订购量、已收量、超出量；库存与采购单状态保持不变。新增 4 项回归用例（超量被拒且库存/状态未变、收齐后再收被拒、不合格量占用订购量、未审批不能收货）。
