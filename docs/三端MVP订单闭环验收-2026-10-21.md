# 三端 MVP：演示订单闭环

依据企业经营管理端 PRD 的 BIZ-FLOW-03，以及 `docs/PRD/00_总体说明与跨端矩阵.md` 第七节。本轮只验收消费者商城提交演示订单、企业端处理订单、商城回读状态。ERP 是该演示订单的唯一写入方；不接真实支付、税务或外部物流，也不宣称独立 OMS 已与 ERP 自动双向同步。

## 本轮接口契约

- `GET /api/storefront/v1/products/{slug}` 返回商品 `id`、`slug`、`version`、图文信息及 `variants`；每个规格含 `id`、`color`、`size`、`price`、`available_qty`。
- `POST /api/storefront/v1/checkout` 请求头带 `Idempotency-Key` 和 `X-Checkout-Recovery`（各 32–128 位字母、数字、下划线或短横线）。请求体是 `items: [{variant_id, quantity, product_version}]` 与 `address`。首次成功为 201，等内容重试为 200；响应是 `{order, access_token}`。恢复重试会轮换访问凭据，应保存最新的 `access_token`。
- `GET /api/storefront/v1/orders/{public_id}` 用 `Authorization: Bearer <access_token>` 查询。`status` 依次为 `draft`、`approved`、`shipping_requested`、`fulfilled`；响应还含 `status_label`、`fulfilment_events`、`tracking_no`、`payment_status`。

## 一次性隔离环境启动与演示

以下命令均在本仓库运行，后端只监听本机回环地址。不要使用共享或生产数据库。后端正常退出时，其系统临时目录中的 SQLite 数据库会被删除；强制终止进程后应检查并清理 `crossborder-mvp-*` 临时目录。

1. 在 `backend` 目录运行 `.\.venv\Scripts\python.exe -m scripts.mvp_isolated_demo`。入口会新建临时 SQLite、迁移、创建临时管理员、灌入 1 款虚构商品的 6 个规格（每规格 3 件），并启动 `127.0.0.1:18081`。终端会打印本次临时管理员的账号和随机密码；不要把它们提交到仓库。
2. 在 `storefront` 目录运行 `npm run dev`，打开 `http://127.0.0.1:15174/products/everyday-knit`。若另用商城端口，应在启动后端前把对应完整 origin 加入 `STOREFRONT_ALLOWED_ORIGINS`。
3. 在 `frontend` 目录设置 `VITE_API_TARGET=http://127.0.0.1:18081`，运行 `npm run dev -- --port 15175`，打开 `http://127.0.0.1:15175`。用后端终端打印的临时管理员登录，不使用页面可能预填的其他本机演示账号。

5. 如需连带展示 AI 端只读能力，在同一临时企业端打开“LIM 运行治理”，选择“企业经营只读助手”，Run 目标填“查看只读运营快照”、参数 `{}`，运行完成后查看脱敏 Trace。此步骤不参与订单状态写入。

## 四系统串联的最小演示（无浏览器，一次性库）

`backend/scripts/cross_system_chain_demo.py` 在一次性 SQLite 库上，用 FastAPI TestClient 驱动真实 HTTP 路由，把上文三端闭环再向前接上 **AI 经营 Agent**，证明四个系统被串起来，且全程无需打开浏览器：

1. 第 0 跳：ERP 管理员登录（后续履约 / AI 调用所需）。
2. 第 1 跳：Storefront `GET /products` 读 ERP 主商品与库存。
3. 第 2 跳：Storefront `POST /checkout` 真实写入主 ERP 库 `SalesOrder(draft)`，消费者凭 token `GET /orders/{public_id}` 回读。
4. 第 3 跳：ERP `GET /orders?q=` 读回 → `POST /approve` → `POST /shipment-request`（WMS 预占库存）。
5. 第 4 跳：AI 经营 Agent `POST /agents/operations/ask` 读取 ERP，输出“待发货订单 × 库存按 SKU 联合核对”（自然语言回复 + 结构化证据）。运行环境未配置 LLM 时降级为直接调用同一确定性工具并打印证据，并明确标注。

运行（在 `backend/` 下）：`.\.venv\Scripts\python.exe -m scripts.cross_system_chain_demo`。输出为带溯源的四跳链路与结论。独立 OMS(`oms/`) 是重复实现、与主线无自动交接（见 `INTEGRATION_GAPS.md` G-01），本演示不包含 Storefront→OMS→ERP 的伪链路。
