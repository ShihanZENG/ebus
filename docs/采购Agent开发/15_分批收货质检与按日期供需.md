# 分批收货、质检与按日期供需

## 操作顺序

1. 在「采购 → 发货计划」创建路线，提交、审核并登记发运和预计可用时间。
2. 到仓后点「登记实收」，按 SKU 填本批实到数量。可以分多批登记，累计实收不得超过发运量。此时货物属于待质检，尚不可售、不可分配。
3. 在该批记录点「质检」，填写合格与拒收，两者之和必须等于本批实收。只有合格数量进入目的仓可用库存。FBA 路线合格货归目标店铺专属；国内仓至海外仓的混合货需按实物标签明确其中专属数量。
4. 如果确认后续不会再到货，质检完已收批次后用「关闭短收」填写差异原因。发货计划保留计划、实收、合格、拒收和短收数量，不自动补单。
5. 在「库存 → 库存归属与需求」选择目的仓及 SKU，看「未来 21 天供需日历」。可展开每天查看各店铺的未占用订单、额外预测、专属库存消耗和公共库存需求。

## 计算口径

- 初始库存取查询时的可分配余额，已占用部分已扣除；店铺专属优先，剩余需求合并使用公共库存。公共库存跨店铺的优先顺序尚未配置，所以只展示总缺口，不将公共缺口武断分派给某一家店铺。
- 日销沿用补货配置的 7/21 天订单加权算法；仅在订单数据连续 21 天完整、业务时间字段有效时计算。每天预测件数用累计预测向上取整之差，避免逐日取整累计放大。
- 未履约且未占用的已确认订单视为首日需求；首日额外预测扣除已确认订单量，避免把同一批订单再算一遍。订单尚无交付截止日字段，这个首日假设会在页面说明。
- 未来供应只计已发运且有未来预计可用日的未实收到货。合格入库已在现货中，拒收和待检不会重复算作可用供应。国内仓至海外仓的货若尚未确定到仓归属，暂不抵扣店铺需求。
- 缺少店铺配置、21 天完整性证明、业务下单时间、可靠 ETA，或存在待检和归属不明的货时，日历标记「资料待补齐」，不输出净缺口。

## 仍需录入的真实资料

每个参与补货的「店铺 + SKU + 目的仓」需有唯一配置，确认订单同步的起止日期与业务下单时间。发运后需维护预计可用日；每批到仓需登记实收、质检和货主标签。采购报价、运输和箱规仍按原业务配置维护。当前日历是只读参考，不自动创建采购单或发货单。
