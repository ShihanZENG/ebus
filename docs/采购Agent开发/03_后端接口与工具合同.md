## 1. 接口清单

所有接口位于 `/api/v1/purchase-agent`，新增权限资源：`purchase_agent`（decide/runs 读写）、`purchase_agent_drafts`（草稿读写/审批）。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| POST | `/api/v1/purchase-agent/decide` | purchase_agent:write | Agent 入口，返回运行+草稿或 BLOCKED |
| GET | `/api/v1/purchase-agent/runs` | purchase_agent:read | 运行记录分页查询 |
| GET | `/api/v1/purchase-agent/runs/{run_id}` | purchase_agent:read | 运行详情（含工具调用） |
| GET | `/api/v1/purchase-agent/drafts` | purchase_agent_drafts:read | 草稿列表 |
| GET | `/api/v1/purchase-agent/drafts/{draft_id}` | purchase_agent_drafts:read | 草稿详情 |
| POST | `/api/v1/purchase-agent/drafts/{draft_id}/approve` | purchase_agent_drafts:write | 审批通过 → 创建采购计划 |
| POST | `/api/v1/purchase-agent/drafts/{draft_id}/reject` | purchase_agent_drafts:write | 驳回（需原因） |

## 2. decide 请求 Schema

```json
{
  "sku_id": "36位UUID",
  "shop_id": "36位UUID(可选)",
  "warehouse_id": "36位UUID，本地仓",
  "as_of": "2026-10-09T08:00:00Z",
  "daily_sales": 10,
  "lead_time_days": 21,
  "safety_days": 7,
  "budget_limit": 3000.00,
  "case_id": "CASE-001(可选)",
  "supplier_id": "36位UUID(可选)"
}
```

字段校验规则：

- sku_id/warehouse_id 必填且必须存在且启用。
- as_of 必填；daily_sales 可选（不传则从证据层读取；传 null 视为缺失 → BLOCKED）。
- lead_time_days、safety_days 可选；不传时从供应商供货价（SupplierSku.lead_time_days）与 SKU 参数读取；都没有 → BLOCKED。
- 请求禁止多余字段（extra=forbid）。

## 4. 工具合同（内部函数）

| 工具 | 输入 | 输出 | 说明 |
|---|---|---|---|
| get_inventory | sku_id, as_of | local_available, fba_available, in_transit_on_time, in_transit_late | 本地可售=FBA 海外仓可售；在途按 ETA 过滤（on_time 为预计可售 ≤ 目标到仓日） |
| get_supplier_sku | sku_id, supplier_id | supply_price, lead_time_days, is_active, quote_valid | 取当前供货价与交期；报价过期 → quote_valid=false |
| get_sku_params | sku_id | moq, case_pack, safety_days(可选), compliance_ok | SKU 采购参数与合规状态；缺失字段返回 null 供校验 |
| replenish | 证据对象 | calculation | 纯函数确定性计算 |
| create_draft | run, calculation, snapshot | draft | 幂等创建草稿 |
| approve_draft | draft_id, user | plan | 审批通过 → 创建 PurchasePlan |

每条工具调用写入 agent_tool_calls（tool/params/result/snapshot_id/status/elapsed_ms）。

**可解释性约定**：decide 各分支响应均携带 `evidence`（工具采集证据）与 `calculation`（完整中间量 + `steps` 人类可读步骤数组），前端据此展示"证据盘点 + 计算明细"，审计运行记录（runs/{id}）可完整回放单次决策全过程。

## 5. 错误约定

沿用项目统一错误格式：`error.code / error.message / error.fields`；401/403/404/409/422 语义一致。业务级停止（BLOCKED/CONSTRAINT_CONFLICT）**不是 HTTP 错误**，以 200 + status 字段返回，便于前端展示可读原因。

## 6. 采购参数读取规则（决定 MOQ/箱规/合规）

- MOQ、箱规（case_pack）从 SKU.attributes 读取（keys：`moq`、`case_pack`），缺失时：MOQ 缺省 0（不起约束）、箱规缺省 1（不取整）；两者必须 ≥ 0。
- 合规状态 compliance_ok：SKU.attributes 的 `compliance` 字段；`missing` 或显式 `false` → BLOCKED（本批默认演示数据无合规字段时视为 ok，但显式 false 必须拦截）。
- 演示数据 seed 中可为演示 SKU 增加 attributes：`{"moq": "120", "case_pack": "12", "compliance": "ok"}`（bootstrap 不强制，运行 decide 时可显式传入或读属性）。
