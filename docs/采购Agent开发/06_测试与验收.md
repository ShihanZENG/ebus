## 2. 验收样例（硬性，逐一断言）

### 2.1 正常样例

输入：日销 10、交期 21、安全天数 7、本地可售 20、FBA 可售 10、按期在途 20、MOQ 120、箱规 12、单价 12.00、预算 3000。

期望：

- target_stock = 10 × (21+7) = 280
- net_gap = max(0, 280 − 20 − 10 − 20) = 230
- base = max(230, 120) = 230；suggested = ceil(230/12)×12 = 240
- total_amount = 240 × 12.00 = 2880.00 ≤ 3000
- status = DRAFTED；draft.status = WAITING_APPROVAL
- snapshot 与 calculation 字段完整；幂等键非空

### 2.2 晚到在途

输入：本地 20、FBA 10、在途 20 件 ETA 晚于目标到仓日（不计）、日销 10、交期 21、安全 7、MOQ 120、箱规 12。

期望：in_transit_on_time = 0 → net_gap = 250 → suggested = ceil(max(250,120)/12)×12 = 252。

### 2.3 null 销量

输入：daily_sales=null（且无可读销量）。

期望：status = BLOCKED，blocked_reason 含"日销量"，不生成草稿。

### 2.4 预算不足

输入：预算 2000，其余同 2.1。

期望：status = CONSTRAINT_CONFLICT，不生成草稿，消息含预算。

### 2.5 缺口为 0

输入：本地 200、FBA 100、在途 50，其余同 2.1。

期望：status = CALCULATED，draft=null，suggested_qty=0。

### 2.6 幂等

对同一输入连续 POST decide 两次。

期望：第二次不重复建草稿；两次返回同一 draft_id；草稿表仅一条。

### 2.7 审批

- 无 purchase_agent_drafts:write 权限的账号 approve → 403。
- 有权限账号 approve → 200；draft.status = EXECUTED；生成一条 purchase_plans 记录且 po 关联正确；审计日志存在。
- 重复 approve → 409。
- reject：需要原因；reject 后 status = REJECTED。

### 2.8 权限

- 无 purchase_agent:write 权限账号 POST decide → 403。
- 无 purchase_agent:read 权限账号 GET runs → 403。
- 范围受限账号请求范围外 warehouse → 403/422。

### 2.9 合规缺失

SKU.attributes.compliance = "false" 或 "missing"。

期望：status = BLOCKED，blocked_reason 含"合规"。
