# 04 权限与安全

## 1. 新增权限

在 `backend/app/schemas.py` 的 `RESOURCE_NAMES` 与 `PERMISSIONS` 中新增：

- 资源 `purchase_agent`：`purchase_agent:read`（查运行记录）、`purchase_agent:write`（发起 decide）
- 资源 `purchase_agent_drafts`：`purchase_agent_drafts:read`（看草稿）、`purchase_agent_drafts:write`（审批/驳回）

管理员角色 code=admin 自动拥有全部权限。

## 2. 权限矩阵

| 操作 | 权限 | 附加范围校验 |
|---|---|---|
| POST decide | purchase_agent:write | 请求的 shop_id/warehouse_id 必须在该账号 shop_scope/warehouse_scope 内（若账号有范围限制） |
| GET runs | purchase_agent:read | 返回结果按账号范围过滤 |
| GET drafts | purchase_agent_drafts:read | 返回结果按账号范围过滤 |
| POST approve | purchase_agent_drafts:write | 草稿 warehouse_id 必须在范围；审批人写入 approved_by |
| POST reject | purchase_agent_drafts:write | 同上 |

## 3. 安全约定

- 沿用 `require(permission)` 依赖与 `current_user` 会话校验；角色和数据范围每次请求重新读取。
- 无权限 → 403（不泄露存在性）。
- 草稿创建后不可 PATCH；任何关键内容变更需重新 decide 生成新草稿（旧草稿保留历史）。
- approve/reject 幂等：已审批/已驳回/已执行的草稿重复操作返回 409，禁止重复执行。
- approve 事务：草稿状态更新 + 创建 PurchasePlan + 审计，在同一事务提交；失败整体回滚。
- 审计：decide、approve、reject 均写入 AuditLog（resource=purchase_agent / purchase_agent_drafts）；工具调用明细在 agent_tool_calls。
- 不在日志、响应中回显 token、密码、.env 内容。
- 幂等键与快照是内部契约字段，可对外返回（不含敏感信息）。
