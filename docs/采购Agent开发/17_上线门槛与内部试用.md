# 上线门槛与内部试用

在「采购与补货 Agent → 上线准备」按一条 SKU 补货配置查看当前检查结果。此页只读，不会创建或批准采购、发货单。它区分三种状态：

- **资料可查**：系统当前能查到对应记录，不表示业务负责人已完成实物核对。
- **当前阻断**：缺少实际下单时间、完整订单来源或有效报价等，不应据此生成正式采购决策。
- **待人工验收**：库存实物与货主标签、承运与预计可售日、端到端业务对账、正式部署及权限密钥，需要负责人拿证据确认。系统不会自动把这些事项标成通过。

## 内部试用准则

内部试用可以演练建配置、规则分析、审批草稿、发货、分批实收与质检，核对页面数字和状态转换。用于演练的资料必须与真实业务资料区分；不要把未核实的订单日期或同步范围写成已确认。正式采购和发货仍由业务人员以原凭证核定。

## 正式试点放行条件

1. 指定店铺、SKU、路线和负责人，确认仓库实物、公共/店铺专属归属与库存差异。
2. 有平台订单号、真实下单时间、SKU 映射及完整区间的订单同步或导出依据；零订单日期也在来源范围内。
3. 有有效报价、供应商交期、箱规、运输与入库时效，以及实际发运和收货凭证。
4. 用真实业务单据对账一次：订单需求、采购与调拨占用、发出、分批实收、质检合格、拒收和最终可售数量一致；异常有处理负责人。
5. 建立正式部署、监控告警、定期备份、恢复演练和回滚流程；复核角色权限并轮换曾暴露的密钥。
6. 完成回归与安全验收后，由业务负责人决定试点范围和开始时间。
