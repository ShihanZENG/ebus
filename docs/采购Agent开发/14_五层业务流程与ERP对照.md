# 五层业务流程与当前 ERP 对照

依据用户提供的 `E:/21_跨境业务-分层理解/业务流程/01_业务流程.md` 至 `05_业务流程.md` 整理。这些文件是业务学习资料，其中的数字为教学假设；本页将其作为业务框架，不把示例数量写入真实业务配置。

## 业务主线

01 讲商品、销售渠道、履约方式、售后和资金的完整循环。02 强调每件事有“意图 → 确认 → 执行 → 核实”四层。03 要将多渠道需求与分仓供应按时间、能力和现金共同协调。04 要区分已核实事实、待验证解释、建议动作和复查。05 将试卖、扩量、稳定经营与退出放进商品生命周期。

对采购与补货 Agent 而言，关键对象是：需求来源、可用库存、已占用库存、不同阶段的在途、预计可售日、采购与发货任务、实收差异、费用与现金约束。每一个建议都应能指出所用资料、时间范围和待核实事项。

## 与当前实现对照

| 文档要求 | 当前实现 | 仍需补的业务闭环 |
| --- | --- | --- |
| 01：销售渠道与发货方式分开 | SKU、店铺、仓库分开建模；发货计划有三种路线 | 仓库用途尚未严格区分普通海外仓与 FBA；商品与平台映射及真实渠道数据需核实 |
| 02：意图、确认、执行、核实分层 | 供需建议与审批生成草稿；调拨已支持分批实收、质检合格放行、拒收及短收结案 | 实际承运凭证和独立上架工序仍需补充 |
| 02：采购实收与质量差异 | 采购收货可记录合格和拒收数量，合格量入库 | 未形成完整的待检、隔离、放行库存状态与批次追溯 |
| 03：多渠道共享库存不重复承诺 | 公共/店铺专属库存、订单与调拨统一占用；目的仓可按店铺汇总未来 21 天预测需求 | 跨路线采购量仍不自动汇总；公共库存跨店铺优先级需业务确定 |
| 03：按日看缺口与到货 | 目的仓供需日历把已发运且有可靠预计可用日的店铺专属在途货按日入账 | 归属未定、待检货暂不抵扣；促销和缺货造成的销量失真尚未处理 |
| 04：分析结论有证据和复查 | Agent 保存证据版本及运行记录；经营分析有利润、推广、回款、退货四类公式 | 经营资料主要依赖录入和确认；尚未建立统一异常责任人、复查时间与执行结果反馈 |
| 05：扩大投入要看现金与退出 | 补货配置有预算、报价和币种 | 现金流入流出时点、采购付款与平台回款延迟情景尚未纳入决策；商品退出与剩余库存处置需单独闭环 |

## 接下来的落地次序

1. 先把仓库实际用途、商品适用的履约路线、库存归属和真实 ETA 核实清楚。现有数据不能自动推定为已确认。
2. 补充承运签收凭证和独立上架记录；目前实收与质检已分开，质检合格后直接计入可售库存。订单交运也应有真实承运商记录。
3. 以 SKU、店铺、履约路线和日期汇总确认订单与剩余预测，再从目的仓逐级推回国内仓，避免同一需求在多层仓库重复算采购。
4. 同时提供采购金额、预计付款日、物流费用、预计回款日与延迟情景，让批准人看到库存和现金两方面的约束。
5. 形成固定复查机制：每个异常和建议有依据、负责人、下一次检查日期、实际执行结果。

当前已完成的库存归属与任务占用，是第 2、3 项所需的基础；当前单据缺口不能直接当作自动采购数量。
