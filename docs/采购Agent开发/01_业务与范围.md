## 1. 业务目标

采购 Agent（课程名：补货 Agent）是供应链侧的受控 AI 编排模块：接收采购补货请求，采集并校验证据，执行确定性补货计算，检查停止条件，生成采购草稿，等待人工审批，审批通过后写入采购计划/采购单，全程可复算、可审计。

一句话定位：**会查证据、会调用计算工具、会判断能不能继续、最后生成采购草稿，但不能越权直接采购。**

## 2. 一期范围（本批实现）

| 能力 | 实现方式 |
|---|---|
| 请求校验 validate_request | 结构化输入（SKU、店铺、as_of、可选参数） |
| 证据校验 validate_evidence | 从数据库读取库存/SKU/供应商/报价并校验 |
| 确定性计算 replenish | 纯函数实现目标库存、净缺口、建议量（MOQ/箱规取整） |
| 停止条件 | BLOCKED / CONSTRAINT_CONFLICT 返回 |
| 采购草稿 | 新增草稿表，状态机流转，幂等键防重复 |
| 人工审批 | approve / reject，审批绑定快照 |
| 审批后写入 | 创建采购计划（purchase_plans）草稿，回读复核 |
| 审计 | agent_runs + agent_tool_calls + 审计日志 |

## 3. 一期边界（非目标）

- 不接入真实 LLM（本批为 L0 离线编排，输入为结构化请求；L1 模型接入留扩展点）。
- 不写入远程 ERP / 不调用平台 API。
- 不做多 Agent 总控路由（归 AI 总助手后续阶段）。
- 不实现销量预测模型：日销量来自请求参数或现有补货建议口径（由调用方传入）。
- 不改变现有 `/api/v1/replenishment-suggestions/*` 行为，采购 Agent 是新增独立模块。

## 4. 与现有系统关系

- 复用：SKU、仓库、供应商、供应商供货价（SupplierSku）、库存（InventoryBalance）、审计（AuditLog）、权限（require + scope）。
- 新增：agent_runs、agent_tool_calls、purchase_agent_drafts 三张表；`purchase_agent`、`purchase_agent_drafts` 权限。
- 衔接：草稿审批通过后创建 `purchase_plans`（草稿状态），沿用现有采购计划流转，不直接创建正式采购单。

## 5. 关键业务口径（硬约束）

- 目标库存 = 日销量 ×（总提前期 + 安全天数）
- 净缺口 = max(0, 目标库存 − 本地可售 − FBA可售 − 按期在途)
- 若净缺口 ≤ 0：建议量 = 0，状态 CALCULATED（不生成草稿）
- 否则 base = max(净缺口, MOQ)；建议量 = ceil(base ÷ 箱规) × 箱规
- MOQ 是最小起订量，不是倍数；箱规是取整步长。
- **null 销量 ≠ 0**：销量缺失必须 BLOCKED，禁止当作 0 计算。
- 负库存、快照不一致、在途 ETA 未知、报价过期、合规缺失 → BLOCKED。
- 在途货件：按货件身份去重、按预计可售时间过滤（到港 ≠ 可售）；晚到在途不计入"按期在途"。
- 预算不足 → CONSTRAINT_CONFLICT，不擅自改数量，交人工决策。
- 建议数量 ≠ 采购授权：只生成草稿，审批后才写入。
- 幂等键：`{case_id}-{sku_code}-{suggested_qty}-{snapshot_id}`；重复提交返回既有草稿，不重复建单。
