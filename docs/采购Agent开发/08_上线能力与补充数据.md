# 08 采购与补货 Agent 上线能力、配置和验收

版本：supply-v2；日期：2026-10-10；适用于当前本地 ERP。

课程依据：[第12章补货 Agent](https://www.billycoder.cn/wolin/html/course/cross-border/#doc-12)。课程区分 L0 离线编排与 L1 模型接入；教师线上演示使用 ERP 订单、7/21 天加权销量、逐日供需、采购与运输分别排期。课程演示数量属于其三 SKU 数据集，不能直接作为本地数据的验收结果。

本文件取代 00–07 的一期边界、快照、幂等、审批和页面说明。00–07 保留为首次 L0 开发历史；其中过往测试、库存和服务器状态不代表今天的状态。

## 1. 实施步骤与交付边界

1. 备份 PostgreSQL，执行迁移 0008：新增补货配置、供需草稿、模型运行记录，补订单业务下单时间和 FBA 可售 ETA。
2. 在 ERP 维护有效报价，确认业务下单时间、订单同步完整范围、仓库映射、物流天数和合规依据。
3. 在「采购 Agent → ERP 供需规划 → 业务配置」创建配置；一条配置对应一个 SKU、店铺、来源国内仓、目的海外仓和供应商。
4. 先运行规则分析，核对销量窗口、库存、采购与发货分别排期及逐日缺口。
5. 配置真实模型服务，重启后端，使用自然语言分析并检查实际工具调用记录。
6. 允许保存草稿后，人工打开草稿查看数字和证据，再复核批准或驳回。
7. 批准时重新查 ERP；数据、配置、规则或证据版本变化则拒绝执行。通过后同事务生成采购计划草稿及 FBA 待配货发货草稿，并回读数量。
8. 按 ERP 既有流程提交采购计划、审核、转采购单、收货入库；发货计划走提交、审核、实际配货发运、签收。Agent 的模型工具没有批准、下正式单、扣库存或发货权限。

支持最多 10 条配置的批量分析，每条配置独立预算；总预算池、跨店铺库存额度和多目的地最优化不是当前算法。发现同一目的仓同 SKU 配给多个店铺时停止，避免把共享库存重复当作店铺独享。

## 3. 业务资料及必须补充的内容

| 资料 | 维护位置或来源 | 缺失处理 |
| --- | --- | --- |
| SKU、店铺、来源国内仓、目的海外仓、供应商 | 业务配置 | 范围或基础资料不合法则拒绝保存 |
| 真实业务下单时间 ordered_at | 订单新增；CSV/TSV 导入列 ordered_at / 下单时间，使用带时区 ISO 时间 | 真实下单时间口径遇历史缺值停止；禁止把导入时间默认为下单时间 |
| 订单数据完整范围 | 订单数据负责人确认连续21天同步完整，填配置开始/截止日 | 数据不完整不能推断零销量 |
| 已接受且未过期报价 | 供应商报价页面，创建有 valid_until 的报价并接受 | 当前供货价与历史报价不一致、无到期日或过期都停止 |
| 采购交期 | 已接受报价的 lead_time_days | 不用其代替完整跨境补货周期 |
| 运输、入库上架天数 | 物流与仓储负责人，填写配置 | 必须显式输入，可明确为0，不能让模型猜 |
| MOQ、箱规、复核周期、安全天数 | 采购负责人，填写配置 | 箱规/MOQ须正整数；负数与缺值不自动修正 |
| 币种、预算、每件运费 | 配置；确认采购报价与运费采用此币种 | 按单条配置检查总采购金额+运费；不自动汇兑 |
| 合规 | 明确确认、证据编号、有效截止日 | 默认待确认；缺依据或过期停止 |
| 采购在途入库 ETA | 采购单 expected_arrival_date | 未知或已逾期需更新，不能按即刻可用计算 |
| 海外货件预计可售 ETA | FBA 发货计划「维护可售 ETA」 | 到港不是可售；未知/逾期停止 |
| 季末日期 | 配置可选项，来自经营计划 | 建议可售日在季末后，停止并要求人工评估 |

历史订单不能直接改数据库回填虚构时间。请从订单来源取得真实下单时间；现有已发货订单不能通过常规草稿编辑修改，应使用经业务确认的数据修复/导入方案。若仅教学演示，配置中可明确选择系统创建时间口径，结果会标注局限；正式业务使用 ordered_at。

## 4. 数字的定义

- 订单按所选店铺与 SKU 查询全部记录，不使用前端分页的前100条。包含 approved、shipping_requested、fulfilled、after_sale，排除 draft、cancelled。口径为确认订单毛需求量；未把退款金额直接换算为销量扣减。
- 在店铺 IANA 时区按业务截止日划分最近7/21个自然日。默认加权日销 = 7天总量/7 ×0.6 + 21天总量/21 ×0.4，权重可维护。连续21天同步完整的确认独立于实际订单是否为0。
- 销量按订单业务时间取数；库存是采集时当前余额，不冒充历史截止日库存。证据分别保存 business_date、planning_date、captured_at。排期从采集时店铺日期开始，逐日模拟从次日起算；不模拟今天剩余小时。
- 规划周期 = 采购交期 + 运输天数 + 入库上架天数 + 复核周期 + 安全天数，最多365天。
- 海外目标 = ceil(日销 ×规划周期)。海外净缺口扣除目的仓可售和规划期内可售的已提交/批准/发出货件；按箱规向上取整得到发货建议。
- 国内库存支持发货，不抵扣补货到达前的海外需求。国内可用扣除预留和尚未发运的其他FBA计划承诺。采购在途只取已批准订单未收货且未拒收的数量。
- 采购净缺口 = max(0, 发货建议 −国内空闲现货 −可在规划期内转运到目的仓的采购在途)。有缺口才应用MOQ、箱规；无缺口建议采购0。
- 分别安排现货发运、既有采购在途转运和新采购到仓后的发运批次；新采购超MOQ的剩余货可留在国内，不强行全部发出。
- 每日先加入可售到货、再扣预测需求；不足计入该日时效缺口，期末库存不为负。时效缺口为累计未满足量的向上取整，不表示靠追加正常交期采购可以弥补过去缺货。
- 建议货值 = 采购数量×已接受报价；运费 = 发货数量×配置每件运费。预算不足保留标准建议，CONSTRAINT_CONFLICT，不偷偷修改数量。

这是可解释的业务规则预测和模拟，不是通用机器学习预测，也不保证未来零断货。规则显示加急/调拨等待人工事项，没有未经成本与权限审批自行实施这些操作。

## 5. 模型接入

在 backend/.env 配置下列值，密钥只放本地/服务器环境，不写聊天、页面或文档：

```dotenv
PURCHASE_AGENT_LLM_BASE_URL=<服务商控制台的OpenAI兼容基础地址，结尾通常为/v1>
PURCHASE_AGENT_LLM_API_KEY=<本地密钥>
PURCHASE_AGENT_LLM_MODEL=<有权限且支持tools的模型名称>
PURCHASE_AGENT_LLM_DISABLE_THINKING=true
```

BASE_URL 不包含 /chat/completions；系统自行拼接路径。百炼地区/工作空间地址按自己控制台填写；参考[官方 Function Calling 文档](https://www.alibabacloud.com/help/en/model-studio/qwen-function-calling)。百炼非流式调用可设 DISABLE_THINKING=true；其他兼容服务保留false，避免发送不支持的扩展参数。没有默认为已接入课程模型，没有配置时明确 MODEL_NOT_CONFIGURED。

修改 .env 后重启后端。自然语言入口发起真实HTTP请求，模型返回工具调用后，由后端校验schema、所选配置、数据范围和状态并实际执行。只允许：

1. get_supply_evidence：读取所选配置的ERP证据。
2. calculate_supply：先有证据，才运行固定计算函数；模型不能传入自定数量。
3. create_supply_draft：先完成计算且界面授权保存草稿，才可创建；不能批准或创建正式采购单。

最多12轮、40次工具、单轮最多10次工具；单次HTTP最多40秒、总模型等待约150秒（数据库操作及网络超时边界可能有少量开销）。参数长度限制、未知工具/配置ID拒绝、无工具证据的文字答复判失败。调用失败回滚该次未提交的草稿，持久化失败原因；不静默改为规则结果冒充模型。只发送业务配置和聚合销量/库存，不发送订单客户联系方式或原始订单客户记录。

## 6. 接口与页面

前缀 /api/v1/purchase-agent；权限沿用 purchase_agent:read/write 和 purchase_agent_drafts:read/write。

| 方法、路径 | 内容 |
| --- | --- |
| GET /lookups | 全部启用的可选基础资料简表，店铺/仓库按用户范围过滤 |
| GET/POST /profiles | 查询/建立补货配置 |
| PUT /profiles/{id} | 修改参数；SKU/店铺/仓库/供应商身份不可变，换身份另建配置 |
| POST /supply-decide | profile_ids、business_date、create_drafts；批量规则分析 |
| GET /runtime | 模型是否已配置、模型名与工具列表，不返回密钥 |
| POST /chat | message、profile_ids、business_date、allow_drafts；真实模型工具调用 |
| GET /chats | 本人可见且当前仍有范围权限的模型运行记录 |
| GET /supply-drafts | 供需草稿服务端分页 |
| GET /supply-drafts/{id} | 不可变证据、计算、有效期、版本和生成记录 |
| POST /supply-drafts/{id}/approve | 请求 evidence_hash，重采证据并原子生成业务草稿 |
| POST /supply-drafts/{id}/reject | 请求 reason，保留历史 |
| GET /runs、/runs/{id} | 原有运行接口兼容；检查来源仓、店铺、目的仓范围 |

FBA新增 PUT /api/v1/fba-plans/{id}/eta，创建/编辑也可传 expected_available_at。订单新增/导入可传 ordered_at。

工作台使用「业务配置 → 供需工作台 → 采购与发货草稿 → 运行记录」；采购建议、发货建议、时效缺口分别展示。打开草稿后才能看到绑定的证据和审批按钮。创建后的采购/发货计划仍需走ERP业务流程。

## 7. 快照、审批与并发

- 每次读证据保存实际订单记录版本、库存余额版本、报价及主数据、采购与FBA在途、业务配置；快照不是用一个时间字符串伪造来源一致。
- evidence_hash = 这些影响规划的数据的规范JSON哈希，采集时钟不影响内容哈希；captured_at独立保存。审批也重新计算结果并比较规则及计算哈希。
- 批准需要提交当前草稿 evidence_hash，草稿有效期默认24小时，可配置1–72小时。超期、变化必须驳回旧草稿后重新分析。
- 幂等按配置、业务日期、证据版本和规则版本绑定。同证据的有效待审批草稿重复调用复用；不同证据不能悄悄覆盖旧草稿；驳回后可重新生成。唯一键与配置行锁处理重复创建。
- 草稿领取执行权采用条件状态更新，业务单据与草稿状态同事务提交；PostgreSQL另对同SKU加锁，审批回查国内共享现货及新增计划承诺。任一数量回读不一致则整体回滚。
- 草稿生成权限不等于业务单据写入权限。批准生成采购计划需要 purchase_plans:write；生成FBA计划需要 fba_plans:write。
- 当前使用当前库存余额与最近销量证据；历史截止日早于最近完整业务日只可测算，禁止直接生成本次线上草稿。

## 8. 验收方法

在 backend：

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m alembic check
.\.venv\Scripts\python.exe scripts/supply_agent_readiness.py
```

在 frontend：npm run build。

自动化验收使用隔离临时数据库；模型协议用可控模拟响应/传输验证，不能将其称为真实云模型已通过。完成真实模型配置和业务资料后执行：

```powershell
.\.venv\Scripts\python.exe scripts/probe_supply_model.py --profile-id <配置ID> --business-date <最近完整业务日>
```

默认只分析。需要演示保存草稿时增加 --allow-drafts，再在界面人工审批；脚本不会替人批准。验收必须实际看到 get_supply_evidence → calculate_supply 工具成功，输入与数量可复核；纯文字回复不能通过。真实模型超时、循环上限、证据缺失、过期报价、预算冲突、范围越权、版本变化和重复审批都要停止。
