# 当前系统与跨境软件竞品的功能差距

核验日期：2026-10-16。用途：调整已批准的开发优先级，不以竞品菜单数量作为开发目标。

## 资料范围与可信度

用户提供的《跨境-官网有AI-120.csv》有 120 条公司记录。按官网域名小写并去除 www. 去重后有 111 个域名；这不代表 111 个独立产品。

这是一份关键词命中线索表，不是已确认的跨境 AI 产品名录。例如：有的命中 LLMs.txt，有的是 AI 硬盘型号、教育课程、园区地址或行业新闻；还有多个分公司共用官网，以及第三方企业查询页面。

本轮选择与现有系统相关的店小秘、领星、船长 BI、云雅科技产品矩阵与易仓作初步对照。没有逐家验证 120 条，也没有注册或实操竞品。下文的竞品能力代表官方公开声明/操作手册，不能据此证明实际效果、准确率、付费版本可用范围或 API 权限。

## 按业务任务比较

| 业务任务 | 竞品公开证据 | 当前主系统 | 差距与下一步 |
|---|---|---|---|
| 把平台订单变成可处理单据 | 店小秘公开列出平台连接与订单处理 | 有 CSV 导入、渠道框架、SKU 映射；真实渠道主动拉单未完成 | 优先补导入批次、来源、错误清单；获得授权后接一个渠道 |
| 判断采购多少、何时到货 | 领星说明连续补货、在途库存与采购/发货建议 | 已有库存/在途证据、确定性供需计算、采购与发货草稿、人工审批、运行轨迹 | 主要缺口是数据完整性和实际运营验证，不能简单归类为“没有智能补货” |
| 仓库准确发货 | 店小秘说明订单规则、打单与物流对接；易仓提供独立 WMS 产品入口 | 本地预留、出库扣库、取消释放已有实现 | 物流面单/轨迹、平台回写、部分履约等需分别验收；先保证本地数量一致 |
| 退货退款后核对货与钱 | 领星公开说明退货等损失进入利润计算 | 主系统售后完成目前更新记录，不等于执行退款或退货入库；独立 OMS 有另外的退款实现 | 缺少主系统内的退款执行记录与退货验收链；先确定金额、数量及累计上限 |
| 知道实际赚多少、回款多少 | 领星说明平台流水、利润、结算回款链 | 有收款登记和费用差异核算；首页金额为当前页未取消订单金额 | 缺完整结算导入、费用归集、差异处理、全量汇总；不能把订单金额称为利润 |
| 提前发现运营异常 | 船长 BI 手册明确榜单来源、缺货/退款等入口 | 有固定库存阈值和部分待办；采购 Agent 已有预计库存走势 | 缺可配置阈值、异常负责人、处理状态及复查记录；先做一种可追溯缺货预警 |
| 优化商品内容 | 店小秘公开列出 AI 描述与翻译；云雅区分选品与运营工具 | 已有多语言 Listing 草稿、来源快照及审核基础 | 待验证批量维护、事实检查和修改对比的任务价值；不承诺排名提升 |
| 解释 AI 为什么执行某操作 | 本轮没有足够公开证据比较竞品完整运行轨迹 | 采购 Agent 已有请求结束后的事件时间线、工具结果与失败记录 | 可继续做运行中进度，但不能据此宣称优于竞品；先解决中断恢复和持久化边界 |

## 最关键的判断

当前系统的主要差距集中在数据来源、跨模块闭环与持续运营，而不是缺少 Agent 名称。菜单和功能入口已经较多；部分能力只完成了本地或单点验证。

主系统和独立 OMS 尚不能视为一套已同步的系统。同一笔单据不应两边手工重复处理并各自扣库存。建议本轮继续以主系统为验收入口，独立 OMS 作为参考实现。

“缺证据就停止、数量可复算、草稿人工审批、运行轨迹可追溯”可以作为产品设计重点；这只是定位假设，尚无真实用户验证，也没有证据证明竞品缺少这些能力。

## 对原开发计划的调整建议

1. 保留第一批业务连续验收，给每个环节留下数量、金额与状态证据，明确 API 和页面验收范围。
2. 第二批优先做可追溯导入。每批记录文件标识、店铺、渠道、操作者、时间、成功/跳过/失败数；每条错误能回到原始数据行。真实文件与教学样例明确区分。
3. 第三批补主系统退货退款。分别处理申请、审批、退款结果与退货验收，拒绝超数量/超金额及重复执行；暂不连接真实付款接口。
4. 第四批做全量且分币种的汇总，再做一种能落到单据的异常预警。未知费用应显示缺失，不能按零计入净利润。
5. 第五批完善运行轨迹和一个主力 AI 工作流。优先采购补货，因为已有证据、计算和审批基础；其他 Agent 不同时扩张。

暂缓：多平台同时对接、自动广告竞价、全自动退款、复刻完整选品数据库、跨主系统/独立 OMS 双向同步。它们依赖当前缺少的数据授权或显著增加维护成本。

## 后续产品验证要回答的问题

- 实际使用者最常从哪张表导入订单/库存，字段与时间口径是什么？
- 采购建议出来后，由谁确认，进入哪张业务单据？
- 使用者最需要的是更快生成文案、批量维护，还是发现库存/费用异常？

这些答案不能从官网营销文案直接推导。先做可操作的本地样例，再以经授权的数据和实际使用反馈调整。
