# 消费者商城端 PRD 逐项验收清单

依据：`03_消费者商城端_PRD.docx`，版本 v1.0，2026-10-21。本文区分代码已实现、仅在本地演示环境可验收和正式上线前置条件；本地演示通过不等于生产验收通过。

## 本轮 MVP 聚焦：商城到企业端订单状态

范围限定为“浏览商品 → 选择规格并加购 → 提交一笔演示订单 → 企业端处理后回读状态”。企业端订单 API 契约已冻结；商城按该契约在一次性 SQLite 环境完成浏览器闭环验收，共享后端合同未修改。

| 环节 | 商城侧现状 | 本轮发现 / 联调验收点 |
| --- | --- | --- |
| 浏览商品 | 列表页会并行读取 `/site` 与 `/products`；直达 `/products/:slug` 时复用已载入商品或按 slug 请求详情，并显示规格对话框。 | 深链接/刷新逻辑已修复并加路由解析回归用例；本地 API 桩浏览器验证了首次直达和刷新后均展示正确商品与规格。未知商品的 404/空态由路由失败分支处理。 |
| 选择规格、加购 | 提交 `variant_id`、数量及 `product_version`；按页面快照限制数量，重复 SKU 合并。 | 选规格与加购目前使用列表中的商品快照。联调时确认列表/详情 DTO 的 variant ID、`available_qty`、价格格式和版本字段一致，并覆盖库存/价格变化后的购物袋复核。 |
| 提交演示订单 | `POST /api/storefront/v1/checkout`；请求头含 `Idempotency-Key` 与 `X-Checkout-Recovery`；响应为 `{ order, access_token }`。原 payload 和凭据先写入当前标签页 `sessionStorage`；单飞保护重复点击；超时/网络错误提示重试原提交。 | 一次性 SQLite 浏览器验收中提交成功，返回公开订单号与访问凭据，页面显示待确认库存与不扣款说明。 |
| 回读处理状态 | `GET /api/storefront/v1/orders/{public_id}`，使用 `Authorization: Bearer <access_token>`；刷新按钮重新读取；订单响应呈现 `status_label`、`fulfilment_events`、商品快照与演示出库号。 | 浏览器中完成 ERP 审核、申请发货、确认出库后，商城刷新回读 `draft → approved → shipping_requested → fulfilled` 和相同演示运单号。订单 ID 不承担授权；首次读取失败时仍用原幂等键与恢复凭据恢复。 |

**本轮验收结果**：商城直达/刷新回归 3 项、商城全量测试 15 项、商城构建均通过；`backend/tests/test_mvp_order_flow.py` 隔离测试 1 项通过。浏览器实测的商城下单、ERP 审核/出库、商城状态回读已完成。详细测试订单和 Run→Trace 记录见[三端 MVP 闭环验收记录](三端MVP订单闭环验收-2026-10-21.md)。全程使用一次性 SQLite 与虚构资料，没有写共享或生产数据库。

## 实际 API 与权限边界

| 接口 | 授权/权限 | 说明 |
| --- | --- | --- |
| `GET /api/storefront/v1/site`、`/products`、`/products/{slug}`、`/media/{key}` | 商城启用时公开读取 | 只返回已发布商品和公开媒体。默认 app 不启用商城 router。 |
| `POST /api/storefront/v1/checkout` | 无顾客账号；需 `Idempotency-Key`、`X-Checkout-Recovery` | 服务端校验商品版本、活动 SKU 和库存后写 ERP 草稿；仅演示金额/币种。 |
| `GET /api/storefront/v1/orders/{public_id}` | 随机 Bearer 订单凭证 | 凭证只保存 hash；订单号本身不可授权。错误订单/凭证不返回订单内容。 |
| `POST/GET /api/storefront/v1/support-requests` 与附件读取 | 对应订单 Bearer 凭证 | 顾客只能读该订单的请求/附件；附件从私有目录授权下载。 |
| `/api/v1/storefront/site`、`products`、`media`、`support-requests` | ERP `storefront:read` / `storefront:write` 与站点范围检查 | 运营端维护站点/商品/媒体/请求状态；媒体上传和状态修改要求 write。 |

ERP 管理员的用户名密码及角色体系只供内部人员使用；这不是消费者登录实现。商城 API 在演示 app 未显式启用时返回 404。

## 需要用户提供的最小决策/资料

1. **账户优先级与身份方式：**PRD 的复购顾客说明标成 P1，但 C-P10/SHOP-FR-016 标成 P2；请定优先级，并确认游客结账是否保留、消费者登录采用邮箱一次性链接/验证码还是密码、地址是否允许保存、保存/删除期限。若启用邮件，还需邮件服务商与验证发件域名。
2. **经营主体与市场：**真实公司法定名称/注册地址/联系方式、首发国家和适用语言；这些决定政策页面和站点范围。
3. **支付与税务：**PSP、支持币种/支付方式、退款/争议回执契约；VAT 注册/适用税区、标价含税规则和结账税额口径。
4. **配送与退货：**承运商、覆盖地区、费率/服务时效、电话必填规则、退换/取消/退款政策及可公开承诺的状态来源。
5. **商品事实：**每个可售 SKU 的授权商品实拍、准确材质/护理/尺寸、库存发布责任人和公开价格确认。
6. **生产环境：**正式域名/TLS 终止和 CSP 来源白名单；对象存储与附件访问控制；备份加密密钥管理、异地目标、保留期/RPO/RTO、恢复责任人和审计要求。

在这些资料确认前，正式支付、税务/运费、真实物流通知、有效法律政策、消费者账户和生产媒体服务均保持关闭或演示态；本清单中的本地测试不能替代法律、税务、渗透或生产恢复验收。
