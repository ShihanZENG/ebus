# CommerceOS｜五系统三端 PRD 文档集 v1.0

> 日期：2026-10-21  
> 状态：目标产品需求基线（与现有功能清单对齐，**不等于全部已交付**）

## 一、五个系统与三个前端的关系

| 系统编号 | 五大系统 | 归属前端 | 用户界面与部署边界 | 当前基础 |
|---|---|---|---|---|
| S1 | ERP 业务系统 | ① 企业经营管理端 | `/erp/*` ERP 管理工作区 | B01–B31 已有业务实现，待验收 |
| S2 | LIM 智能中间层 | ② AI 平台管理端 | `/lim/*` 工程控制台；不持有 ERP 业务真值 | 已有分散 AI 运行资产，统一 LIM 为建设目标 |
| S3 | AI 智能经营应用 | ① 企业经营管理端 | `/ai/*` AI Operations 独立工作区 | A01–A12 已有部分 Agent/助手，跨 Agent 协同为目标 |
| E1 | 独立 OMS | ① 企业经营管理端（**独立应用入口**） | `/oms/*` 或独立域名，不必与 ERP 合并前端/数据库 | O01–O07 单独开发，跨系统同步待契约定义 |
| E2 | Storefront 独立站 | ③ 消费者商城端 | 独立公开商城域名，独立于企业应用 | S01–S06 本地首单闭环演示，非正式支付商城 |

**关键解释：** “三个端”是按用户角色和前端产品划分，不是把五套后端缩减成三套服务；企业端包含 ERP、AI、OMS 三个工作区，OMS 维持系统独立性；AI 经营与 LIM 工程控制台不能混为一个页面。

## 二、三个 PRD 的阅读顺序

1. `01_企业经营管理端_PRD`：员工日常业务操作、订单/库存/采购/财务、AI 经营诊断、审批与独立 OMS。
2. `02_AI平台管理端_PRD`：LIM Runtime、Agent、Tool、GraphRAG、Memory、Harness、Trace、评测与发布。
3. `03_消费者商城端_PRD`：面向消费者的品牌商城、SKU、购物袋、演示/真实结账边界、订单查询和售后。

建议先建立“现有功能台账 + 接口盘点 + 数据主权矩阵”，再按 G0–G4 阶段推进；跨端能力应以 API 合同测试为准。

## 三、统一导航方案

```text
企业应用入口 /workspace
├── ERP 业务工作区          /erp/...
├── AI 智能经营工作区       /ai/...
└── OMS 独立系统入口        /oms/...   或实际独立地址

AI 平台管理端               /lim/...   只对技术与管理员开放
消费者独立站               storefront 独立 URL，不使用企业入口
```

## 四、跨端能力责任矩阵

| 能力 | 企业端 ERP/OMS | AI 管理端 LIM | 消费者端 Storefront | 系统主责原则 |
|---|---|---|---|---|
| SKU 主数据、价格、库存 | 维护、审核、计算 | 受权检索快照 | 仅展示可售投影 | ERP / 指定确定性服务 |
| Agent 业务问题 | 提交、阅读、反馈 | 配置 Runtime、Trace 和工具 | 默认不暴露后台 Agent | S3 业务语义 / S2 技术治理 |
| GraphRAG 证据 | 只读解释结果 | 导入、检索、索引、版本管理 | 无直接访问 | LIM 索引为投影，不覆盖 ERP 真值 |
| 订单创建 | ERP 规则确认；OMS 视契约参与 | 仅审计工具轨迹 | 提交幂等意图 | 当前首单演示由 ERP 受理 |
| 库存/采购/广告写入 | 业务规则、权限、审批和状态机 | 拦截风险、追踪调用、验证 scope | 无权限 | ERP 确定性业务服务 |
| 付款/退款 | ERP/支付适配或 OMS 按唯一主责 | 不得自行生成真实收款状态 | 仅显示已核验状态 | 支付/业务回执 |
| 客服/售后 | 创建处理工单、审核草稿 | 模型工具权限、审计 | 提交查询或售后意图 | 业务后台而非 LLM |
| 评测/模型发布 | 提供脱敏业务样例/验收 | Golden Dataset、发布门禁 | 不可操作 | LIM / AI 工程团队 |

## 五、功能成熟度四状态（强制记录）

- `implementation_status`：代码与页面是否存在。
- `integration_status`：接口、模型、存储、第三方服务是否可用。
- `acceptance_status`：业务用例与安全负向测试是否通过。
- `production_status`：在真实业务/真实资金/真实平台是否获准上线。

存量对应 B01–B31、A01–A12；P01–P07 为部分能力或演示基础；O01–O07 为独立 OMS；S01–S06 为独立站首单演示。不要将“页面已存在”自动判定为“生产已上线”。

## 六、建议统一设计系统

- **企业端**：深色导航 + 浅色业务内容区；Ant Design 风格的数据表、筛选器、审批抽屉、Evidence Drawer。
- **AI 管理端**：控制台型信息密度；Agent/Tool 注册表、Workflow 画布、Trace 树/时间轴、Evaluation 版本对比。
- **消费者端**：品牌型导航、商品图片、规格选择、购物袋/结账，移动优先。
- 共用：色板、字号、错误语义、请求关联 ID、数据状态徽标；**不要共用企业后台左侧导航给消费者**。

## 七、跨端验收的最低闭环

- 流程 1：ERP 真实/已标示样例数据→AI 诊断→LIM Trace→证据链→受控提案→人工审核→ERP 状态回读。
- 流程 2：消费者 SKU 选择→演示提交→ERP 草稿订单→审核/预留/出库→商城订单状态刷新，重复提交幂等。
- 流程 3：OMS 独立订单→明确映射/唯一写入主责→受控状态查询/对账，不宣称不存在的自动双向同步。

## 八、需求来源与后续使用

核心依据：2026-10-20 的《LLM 原生跨境电商 ERP：企业级系统架构、Agent 协同与存量需求对齐 v0.3》、原始 v0.1 和《现有功能清单（需求对齐用）》；五系统交互式前端原型用于导航、界面布局和演示流程的可视化参考。需求条目与 API 路径是本次**进一步细化的建议设计**，具体实现以源码盘点、架构决策记录和接口评审为准。
