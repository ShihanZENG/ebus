# 销售：订单从哪来

## 页面用途

销售订单模块（OMS）管理从各渠道进来的订单，走完"建单 → 审核 → 预留库存 → 发货 → 完成"的全流程。路由为 `/orders`。前端实现见 [`Orders.tsx`](../../../frontend/src/pages/Orders.tsx)，后端路由见 [`orders.py`](../../../backend/app/orders.py)。

订单的来源有两种：**手工创建**和**批量导入**。当前系统不自动对接 Amazon、Shopify 等平台 API，订单需要手工录入或通过批量导入接口创建。

## 订单状态机

```
draft（待审核）
  │
  ├─ 审核通过 → approved（待发货）
  │                 │
  │                 └─ 申请发货 → shipping_requested（待出库）
  │                                     │
  │                                     └─ 确认出库 → fulfilled（已完成）
  │
  └─ 取消 → cancelled（已取消）

任意状态 → after_sale（售后中，仅完成后可发起）
```

## 页面内容与操作

### 订单列表（/orders）

| 列 | 说明 |
|---|---|
| 来源单号 | 渠道侧的订单号，同一店铺+渠道下来源单号唯一 |
| 客户 | 客户名称 |
| 金额 | 订单总金额（原币种） |
| 状态 | 待审核/待发货/待出库/已完成/已取消/售后中 |
| 下单时间 | 创建时间 |

操作：
- **新建订单**：选择店铺、填写客户信息、添加 SKU 明细行（SKU、数量、单价），系统自动计算行金额和订单总额。
- **批量导入**：上传 JSON 格式的订单数组，系统逐行校验，重复来源单号自动跳过并返回错误行。
- **审核**：将 draft 状态订单标记为 approved，需指定发货仓库。
- **申请发货**：在 approved 状态下调用库存预留，系统用行锁锁定库存，不足则整单回滚。
- **取消**：输入取消原因，取消已预留的订单会自动释放库存。
- **付款记录**：为订单登记付款金额、方式和来源。
- **售后**：完成状态的订单可发起退货/退款售后。

### 订单详情抽屉

点击列表行打开右侧抽屉，显示：
- 订单基本信息：来源单号、状态、客户、总金额、币种
- 商品明细：SKU 编码快照、名称快照、数量、单价、行金额
- 付款记录：金额、方式、来源

## 数据来源

| 操作 | 接口 | 说明 |
|---|---|---|
| 订单列表 | `GET /api/v1/orders?page=&page_size=&status=&q=` | 按店铺范围过滤 |
| 订单详情 | `GET /api/v1/orders/{id}` | 含明细行和付款记录 |
| 创建订单 | `POST /api/v1/orders` | 手工建单 |
| 批量导入 | `POST /api/v1/orders/import` | JSON 数组，来源单号去重 |
| 审核 | `POST /api/v1/orders/{id}/approve` | body 指定 warehouse_id |
| 申请发货 | `POST /api/v1/orders/{id}/shipment-request` | 预留库存 |
| 取消 | `POST /api/v1/orders/{id}/cancel` | body 指定 reason |
| 登记付款 | `POST /api/v1/orders/{id}/payments` | |
| 创建售后 | `POST /api/v1/orders/{id}/after-sales` | |

订单模型见 [`models.py`](../../../backend/app/models.py)：字段含 shop_id、source_channel、source_order_no（联合唯一）、status、currency_id、grand_total、customer_name。明细行在创建时快照 SKU 编码和名称，后续 SKU 修改不影响历史订单。

## 库存联动

申请发货时，后端在数据库中对 `inventory_balances` 行加锁（SELECT...FOR UPDATE），将可售库存转入预留库存。如果某行 SKU 库存不足，整个事务回滚，订单不会进入待出库状态。确认出库时同时扣减在库和预留。取消已预留订单自动释放预留库存回可售。这部分逻辑在 [`wms.py`](../../../backend/app/wms.py) 中实现。

## 操作示例

1. 进入"销售 → 销售订单"，点击"新建订单"。
2. 选择店铺，填写客户名称，添加一行 SKU，选择 SKU、数量 2、单价 39.99。
3. 保存，订单出现在列表中，状态为"待审核"。
4. 点击"审核"按钮，选择发货仓库，状态变为"待发货"。
5. 点击"申请发货"，系统检查库存，状态变为"待出库"。
6. 在库存模块确认出库后，订单状态变为"已完成"。

## 权限说明

- `orders:read`：查看订单列表和详情。
- `orders:write`：创建订单、批量导入。
- 审核、申请发货、取消、登记付款、创建售后均要求 `orders:write`。
- 订单接口按当前用户的店铺范围（shop_scope）过滤，无权限的店铺订单不可见。

## 当前实现边界

### 已实现

- 手工建单：多明细行、自动计算金额。
- 批量导入：JSON 数组、来源单号去重、错误行定位。
- 完整状态流转：draft → approved → shipping_requested → fulfilled/cancelled。
- 库存行锁预留与释放，不足整单回滚。
- 付款记录和售后记录。
- 订单详情抽屉展示明细和付款。

### 部分实现

- 批量导入接受 JSON 格式，前端尚未提供文件上传组件，需通过 API 文档或工具调用。
- 订单列表的筛选条件有限（状态、关键词），没有日期范围、店铺筛选 UI。
- 金额使用订单原币种，不做汇率换算。

### 尚未实现

- 自动对接 Amazon/Shopify/TikTok 平台 API 拉取订单。
- 订单拆分、合并、改地址、改价格。
- 物流跟踪号回传。
- 打印发货单、拣货单。
- 订单评论和评分管理。
- 批量审核、批量发货。

## 验收步骤

1. 登录后进入"销售 → 销售订单"，确认列表加载。
2. 新建一笔订单，选择店铺和 SKU，保存后状态为"待审核"。
3. 审核订单，选择仓库，状态变为"待发货"。
4. 申请发货，确认库存充足时状态变为"待出库"；库存不足时应提示错误且订单状态不变。
5. 在库存模块确认出库，返回订单列表确认状态为"已完成"。
6. 取消一笔订单（含已预留库存的），确认库存预留被释放。
7. 为订单登记一笔付款，在详情抽屉中确认付款记录出现。
