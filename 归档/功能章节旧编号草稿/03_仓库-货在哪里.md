# 仓库：货在哪里

## 页面用途

仓储模块（WMS）回答两个问题：**每个 SKU 在每个仓库有多少货**，以及**每笔库存变动是怎么来的**。路由包括 `/inventory`（库存余额）、`/inbound`（入库单）、`/shipments`（出库单）、`/inventory-txns`（库存流水）、`/warehouses`（仓库档案）。前端实现见 [`Inventory.tsx`](../../../frontend/src/pages/Inventory.tsx)、[`InboundOrdersPage.tsx`](../../../frontend/src/pages/InboundOrdersPage.tsx)、[`ShipmentsPage.tsx`](../../../frontend/src/pages/ShipmentsPage.tsx)、[`InventoryTxnsPage.tsx`](../../../frontend/src/pages/InventoryTxnsPage.tsx)，后端见 [`wms.py`](../../../backend/app/wms.py)。

## 核心概念

**库存余额**按"SKU × 仓库"记录三个数量：
- `on_hand`（在库数量）：物理存在仓库的总数
- `reserved`（预留数量）：已被订单锁定但尚未出库的数量
- `available`（可用数量）：`on_hand - reserved`，可售可分配数量

**库存流水**记录每笔变动：入库增加 on_hand，出库减少 on_hand 和 reserved，库存调整直接修改 on_hand。

## 页面内容与操作

### 库存余额（/inventory）

| 列 | 说明 |
|---|---|
| SKU | 物料编码 |
| 仓库 | 仓库名称 |
| 在库 | 物理库存总数 |
| 预留 | 被订单锁定数量 |
| 可用 | 在库 - 预留 |

操作：按 SKU 关键词搜索、按仓库筛选、分页浏览。支持库存调整（在后端通过 `/warehouses/{id}/inventory/adjust` 接口直接调整在库数量，记录原因）。

### 入库单（/inbound）

| 字段 | 说明 |
|---|---|
| 入库单号 | 系统自动生成 |
| 仓库 | 入库目标仓库 |
| 类型 | 采购入库 / 其他入库 |
| 状态 | draft → confirmed |
| 明细 | SKU、数量 |

操作：创建入库单（draft），确认后增加对应 SKU 在该仓库的 on_hand。

### 出库单（/shipments）

| 字段 | 说明 |
|---|---|
| 出库单号 | 系统生成 |
| 关联订单 | 来源销售订单 |
| 仓库 | 发货仓库 |
| 状态 | draft → confirmed |
| 明细 | SKU、数量 |

操作：确认出库时同时扣减 on_hand 和 reserved，订单状态自动流转为 fulfilled。

### 库存流水（/inventory-txns）

只读列表，展示每笔库存变动：时间、SKU、仓库、变动数量（正负）、变动类型（入库/出库/调整）、关联单据。

### 仓库档案（/warehouses）

CRUD 页面：仓库编码、名称、地址、是否默认、状态。

## 数据来源

| 操作 | 接口 |
|---|---|
| 库存余额列表 | `GET /api/v1/inventory?sku_id=&warehouse_id=&page=&page_size=` |
| 库存流水 | `GET /api/v1/inventory/transactions?sku_id=&warehouse_id=` |
| 库存调整 | `POST /api/v1/warehouses/{warehouse_id}/inventory/adjust` |
| 创建入库单 | `POST /api/v1/inbound-orders` |
| 入库单列表 | `GET /api/v1/inbound-orders` |
| 出库单列表 | `GET /api/v1/shipments` |
| 出库单详情 | `GET /api/v1/shipments/{id}` |
| 确认出库 | `POST /api/v1/shipments/{id}/confirm` |
| 仓库 CRUD | `GET/POST/PATCH /api/v1/warehouses` |

库存余额按当前用户的仓库范围（warehouse_scope）过滤。

## 操作示例

1. 进入"仓库物流 → 库存余额"，确认各 SKU 在各仓库的在库/预留/可用数量。
2. 进入"入库单"，新建一笔采购入库，选择仓库和 SKU，数量 100，保存。
3. 确认入库单后，回到库存余额，该 SKU 在该仓库的在库数量增加 100。
4. 销售模块申请发货后，进入"出库单"，找到对应出库单，点击确认出库。
5. 确认后库存余额中该 SKU 的在库和预留同时减少，订单状态变为"已完成"。
6. 在"库存流水"中可看到该 SKU 的入库和出库记录。

## 权限说明

- `inventory:read`：查看库存余额和流水。
- `inventory:write`：库存调整。
- `inbound_orders:read/write`：入库单查看和创建。
- `shipments:read`：出库单列表和详情。
- `shipments:write`：确认出库。
- `warehouses:read/write`：仓库档案管理。

## 当前实现边界

### 已实现

- 库存余额三量模型（在库/预留/可用），按 SKU×仓库维度。
- 入库单创建和确认，自动增加在库。
- 出库单确认，自动扣减在库和预留，联动订单状态。
- 库存流水完整记录每笔变动。
- 库存调整接口（带原因记录）。
- 仓库档案 CRUD。

### 部分实现

- 入库单确认后直接增加库存，没有质检、上架、批次管理流程。
- 出库单目前由销售订单自动生成，没有手工出库单创建入口。
- 库存调整接口已实现，前端页面尚未提供调整按钮。

### 尚未实现

- 库位管理（货架、货位）。
- 批次号、效期管理。
- 盘点单（全盘/抽盘）和盘盈盘亏。
- 库存预警和补货建议（补货建议在 SCM 模块单独实现）。
- 移库、调拨单。
- 多仓库存汇总视图。

## 验收步骤

1. 进入库存余额页，确认有数据，在库 = 预留 + 可用。
2. 创建并确认一笔入库单，回库存确认数量增加。
3. 从销售订单申请发货后，在出库单页确认出库，回库存确认数量减少。
4. 在库存流水中确认能看到对应的入库和出库记录。
5. 在仓库档案页新增一个仓库，确认列表更新。
